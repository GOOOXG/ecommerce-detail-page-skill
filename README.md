# 商品图深度推演与图生图分镜技能

这是一个通过流程化推演控制 AI 深化思考与主动延展、最终只交付中文图生图分镜提示词的 Codex 技能。它接受实体商品实拍，也接受数字权益或服务商品的真实界面、权益页、流程截图、授权页和已授权场景；完全没有可访问参考视觉时不会伪装成图生图任务。唯一主线是“识别参考视觉中的商品主体 → AI预构建 → 用户编号选择或手动纠正 → 商品卡（待确认） → 用户确认 → 已确认商品卡 → 需求预判/输出范围 → 图组结构 → 5个综合方向 → 逐张确认 → 中文图生图分镜提示词 → 可选生图”。

它先实际识别图片中的商品主体，再由 AI 预构建卖点、事实需求、素材缺口和建议图片；你可以用数字选择，也可以直接纠正。选择后先生成商品卡（待确认），你明确确认后才进入需求预判、输出范围、结构、方向、图组规划和正式提示词编写。提示词完整交付后，是否生图、生成哪些分镜和每张生成几张，都由你决定。

商业、运营、产品、营销、消费者心理和美学知识只在后台帮助判断“做什么图、为什么做、怎样画”，不会另外生成运营报告、营销方案或产品分析报告。

## 核心能力

- 实际查看全部参考视觉，先判断实体商品、数字权益或服务，再识别核心对象、品类、品牌、SKU/版本、状态、包装/权益与交付内容。
- 内部可建立稳定图片编号用于纠错和证据追踪，但正式分镜不输出参考图索引或固定参考图编号。
- AI预构建候选卖点、需要用户补充的事实与内容、可用素材、缺失素材、建议图片和生产条件。
- 用编号选择或自然语言手动纠正，先生成一张商品卡（待确认）；你明确确认后才形成已确认商品卡。
- 商品卡确认后按信息缺口确认范围：原意向完整且无冲突时，原意向本身即完成范围确认，一行摘要与结构首推在同一轮给出且不等待再次回复；意向不清时才展示完整设计需求预判卡。
- 多图支持递进式主次、等量并列、混合结构；结构确定后固定推演5个产品专属综合方向。
- 从买家识别、理解、选型、证明、使用和防错任务中判断真正需要的图片数量，拒绝重复凑图。
- 从注意力抓取、三秒信息效率、信任、情绪认同、转化意愿、平台与无障碍适配六个维度模拟用户决策，并把结论直接编译进分镜提示词。
- 用八项商品决策特征动态适配服饰、美妆、食品、3C、家电、家居、工具、汽配、母婴、宠物、户外、工业品、礼赠、耗材和虚拟商品，不靠固定行业模板硬套。
- 开放式调用商品标准呈现、结构拆解、细节质感、功能验证、参照认知、选择防错、教学维护、场景呈现、创意视觉、组合到手、信任来源、利益行动、数字权益与服务交付等十三类图型；用户示例是思维起点，不是能力上限，同一买家问题可组合多个相容表现手法。
- 输出主图、SKU图、详情页、海报、白底图、透明图和无字场景图的逐张中文图生图分镜提示词。
- 实体商品中真实存在且与任务有关的背面、底部、内部或拆解才启用隐藏视图规则：同SKU真实目标图作为直接证据；缺少资料时分别计算还原置信度，超过80分的目标先推送写实视图确认清单，用户用序列号确认后才写入写实分镜。数字权益、服务和不具备该物理面的对象不评分。
- 复杂任务可由商品识别、预构建、图组、视觉、提示词和独立审查子智能体分工，主控统一合并。
- 通过“证据观察、问题建模、发散、组合、反证、收敛、阶段落位、查漏”的推演循环和经授权的偏好学习，提高分镜与用户思维的匹配度。
- 事实、SKU、安全和平台使用必要硬边界；创意部分优先用正向目标、可变空间与成功标准引导AI，不用通用禁令压缩合理想象。
- 推理先分析全部参考视觉；每张生成只输入当前目标SKU/版本真正需要的一张、多张或全部同款资料。其他SKU默认不传入单SKU生成，冲突在提示词内写成具体采用与舍弃结果，不依赖隐藏商品卡。
- 交互模式逐张展示完整确认卡；简单任务默认只显示“AI首推 / 确认 / 修改”，返修时再展开完整数字菜单，也可授权剩余图片自动复核。
- 提示词交付后可选生图，可指定分镜、图组和每张候选数量；工具不支持独立负面提示词、批量、多参考或透明时按等价适配或明确降级处理，不静默改变方案。

## 唯一流程

```text
识别商品主体
  ↓
AI预构建（卖点、事实、素材、图片建议、视图置信度与写实视图候选）
  ↓
用户数字选择或手动纠正
  ↓
商品卡（待确认）
  ↓
用户确认
  ↓
已确认商品卡
  ↓
设计需求预判与输出范围确认
  ↓
多图结构选择
  ↓
固定5个综合方向
  ↓
图组编排与逐张确认
  ↓
逐张中文图生图分镜提示词
  ↓
可选生图与候选数量
```

商品卡是中间确认依据，不是最终报告。最终核心交付始终是逐张图生图分镜提示词。

运行规则详见：[预构建与已确认商品卡](ecommerce-detail-page/references/prebuild-and-product-card.md)。

## 安装

### 1. 克隆仓库

```powershell
git clone https://github.com/GOOOXG/ecommerce-detail-page-skill.git
Set-Location .\ecommerce-detail-page-skill
```

### 2. 安装到 Codex

下面命令会先把同名旧版本备份，再复制当前技能：

```powershell
$codexHome = if ($env:CODEX_HOME) { $env:CODEX_HOME } else { Join-Path $env:USERPROFILE '.codex' }
$skillsDir = Join-Path $codexHome 'skills'
$source = Join-Path (Get-Location).Path 'ecommerce-detail-page'
$target = Join-Path $skillsDir 'ecommerce-detail-page'

if (-not (Test-Path -LiteralPath $source -PathType Container)) {
    throw "未找到技能目录：$source"
}

New-Item -ItemType Directory -Force -Path $skillsDir | Out-Null

if (Test-Path -LiteralPath $target) {
    $backupRoot = Join-Path $codexHome 'skill-backups'
    $backupName = 'ecommerce-detail-page-' + (Get-Date -Format 'yyyyMMdd-HHmmss-fff')
    $backup = Join-Path $backupRoot $backupName
    New-Item -ItemType Directory -Force -Path $backupRoot | Out-Null
    Move-Item -LiteralPath $target -Destination $backup
    Write-Host "旧版本已备份到：$backup"
}

Copy-Item -Recurse -Force -LiteralPath $source -Destination $target
```

安装后重新打开 Codex 或新建任务，让技能重新扫描。仓库更新后再次运行复制命令即可。

## 快速开始

上传一张或多张商品参考视觉后直接输入。实体商品可以上传实拍或包装图；数字权益或服务可以上传真实界面、权益页、流程或授权页：

```text
使用 $ecommerce-detail-page。先识别这些参考图中的商品主体，给出AI预构建建议和编号选项；我确认商品卡后，再输出逐张中文图生图分镜提示词。暂不生图。
```

如果你已经知道输出对象，也可以写清楚：

```text
使用 $ecommerce-detail-page。为这个商品制作天猫主图和详情页分镜。先识别主体并让我确认商品卡，每张解决不同购买问题；提示词完成后暂不生图。
```

## 推进方式

| 说法 | 技能如何处理 |
|---|---|
| “先推荐让我选” | 展示主体、卖点、资料、素材、图片，以及仅对适用且缺直接证据目标启用的写实视图候选 |
| “逐张确认” | 商品卡确认后，每张分镜先给完整确认内容，确认或返修后再继续 |
| “全部采用AI推荐并确认” | 压缩可见选择，但仍完成识别、冲突检查和商品卡；不代表授权生图 |
| “直接完成，只要提示词” | 仍先在内部生成并记录商品卡（待确认），把用户明示直出视为确认后完成其余判断，外部只保留最终逐张中文分镜 |
| “继续” | 商品卡待确认时先回问确认或纠正；在预判/范围阶段确认当前意向，在结构/方向阶段采用首推，在单图阶段只确认当前图 |
| “确认本张，剩余自动完成” | 确认当前图后，剩余图片进入内部自动复核并在最后统一交付 |
| “暂不生图” | 提示词交付后结束，不调用生图工具 |

## 第一步：图片识别

技能会实际查看每份可访问参考视觉；可按上传顺序建立仅供对话纠错的内部编号，再综合全部有效内容。实体商品可使用实拍、包装、结构图和可靠三维资料；数字权益或服务可使用真实界面、权益页、流程截图、授权页、已授权场景和品牌视觉。完全没有可访问参考视觉时会停止并请求最小必要素材，不进入纯文本概念稿旁路。识别会整理：

- 商品形态、核心对象、品类和主要用途。
- 品牌、型号/SKU或权益/服务版本、档位、时长、地区、账号范围、状态和组合关系。
- 实体的轮廓、结构、颜色、包装和配件，或非实体的真实界面、权益层级、流程、交付状态和授权边界。
- 每张图对身份、视角、细节、文字、包装、配件、尺度或场景提供什么内容，以及多图如何互补或冲突。
- 哪些是图片直接可见事实，哪些是用户提供事实，哪些只是策略推断或待验证内容。

如果图片无法支持主体或 SKU 判断，技能会指出最小冲突并请你补充；不会先猜一个商品再继续写提示词。

## 第二步：AI预构建

主体候选建立后，技能在一次对话中集中展示需要你确认的内容：

1. 候选卖点，以及每个卖点的依据或缺失证据。
2. 需要你提供的准确事实，例如尺寸、容量、材质、适配、数量、安装方式或包装清单。
3. 已有素材能证明什么，以及缺少哪些角度、细节、参数、实拍或三维资料。
4. 建议制作的图片，包括推荐图型、唯一买家问题、目标SKU/版本、所需证据、实际生成参考输入、生产方式、视觉记忆点、主要风险和降级方式。
5. 可用的视角、场景、人物、画布、后期和图生图生产条件。
6. 仅对实体商品中真实存在且与任务有关的背面、底部、内部、拆解记录直接证据；缺少同SKU直接资料时再分别计算还原置信度。
7. 缺少直接资料且超过80分的适用写实视图候选及其序列号；低于或等于80分、不适用或与任务无关的目标不进入操作卡。

AI只建议你提供哪些资料，不会把猜测的数值当成事实。此时使用轻量候选图型导航做预构建初筛，不提前加载完整图组排序；商品卡确认后才正式决定输出对象、图型和顺序。它会主动检查空间适配、收纳携带、到手内容、清洁维护、选型兼容、使用边界、交付激活、信任证据、利益行动和视觉记忆是否有遗漏。简单且资料充分时只显示首推和真正会改变分镜的备选，复杂任务通常显示3到5项。

## 第三步：数字选择与手动纠正

建议卡的编号只用于当前卡；看到新的建议卡后按新卡重新选择，不沿用旧卡编号。推荐回复格式：

```text
主体：1
卖点：1,3
补充：容量=750ml
采用素材：1,2
建议图片：1,2,4
```

这张紧凑回复只选择当前“AI预构建建议”卡。写实视图的序列号要等独立“写实视图确认”卡显示后再回复，不能提前猜测。也可以直接回复“全部采用AI推荐并确认”，或指出错误；直接确认不会自动选择任何尚未编号的写实视图，默认把它们排除在写实分镜外。要纳入某个视图时，先让技能显示独立确认卡，再回复卡内序列号：

```text
参考图1和参考图2是同一款，容量不是500ml而是750ml；卖点3没有检测报告，不采用；只做主图4张。
```

用户手动纠正优先级最高。纠正后技能会重发受影响的建议，不会继续使用旧的 SKU、容量或卖点。

字段内选择要写字段名，例如`卖点：1,3；建议图片：1,2`；裸单个数字只执行当前卡的操作项。若只回复`1,2`而当前卡里有多个编号列表，技能只会问一句这些数字对应哪个字段，不会猜。每张数字卡都会提示“本卡数字只对当前卡有效，下一卡自动失效”。

### 建议卡示例

```text
【AI预构建建议】
商品形态：实体商品
主体候选：1. 不锈钢保温杯（高）  2. 旅行水壶（中）
候选卖点：1. 杯盖可见开合结构（图片可见）  2. 保温性能（待补证）
需要补充：1. 准确容量  2. 材质证明  3. 包装清单
采用素材：1. 参考图1正面  2. 参考图2杯盖细节
建议图片：1. 商品英雄识别图｜首屏认出商品  2. 结构细节图｜看清杯盖结构  3. 真人比例图｜建立使用尺度
写实视图：发现1项待独立编号确认；完成本卡后显示确认卡

1. 采用AI首推并生成商品卡（待确认）
2. 修改主体或SKU
3. 修改卖点
4. 补充事实或素材
5. 修改建议图片和数量
6. 逐项重新选择
7. 直接输入纠正

本卡数字只对当前【AI预构建建议】有效，下一卡自动失效；选择上方字段时请带字段名。
```

主建议完成选择或纠正后，如果实体商品中真实存在、与任务有关且缺少同SKU直接证据的适用隐藏视图存在超过80分的目标，再单独显示一张不会与其他数字菜单共存的确认卡：

```text
【写实视图确认】
1. 背面｜92分｜依据摘要：可见侧边连续、同SKU结构一致｜主要限制：不得新增未出现的接口或配件

请只回复要纳入本次写实分镜的序列号，例如“1”；不采用可回复“无”。
```

## 第四步：生成并确认商品卡

选择或纠正后会先生成一张标明“待确认”的紧凑商品卡：

- 商品形态、核心对象与识别置信度。
- 品类、品牌、型号/SKU或权益/服务版本，以及每个对象的综合有效参考内容和状态。
- 图片可见事实与用户确认事实。
- 已采用卖点、待补证卖点和已跳过内容。
- 已有素材、缺失素材及其职责。
- 用户原始输出意向（只作为待范围确认线索，不当作已确认对象或数量）。
- 必须保持、允许变化与自由探索、必要边界、真实证据像素职责，以及用户明确禁止的内容。
- 实体商品记录适用隐藏视图的直接证据、独立置信度和序列号；数字权益或服务改为记录交付内容、发放/预约、有效期、权限范围、退款/取消/续费、授权与异常处理，物理隐藏视图标为不适用。

商品卡汇总此前已确认和未选择的写实视图；只有尚未完成显式视图选择时，才补发一次独立的“写实视图确认”序列号清单。回复序列号（例如“1、3”）只确认对应视图，不等同于商品卡确认。请再回复“确认商品卡”或直接指出需要修改的字段。当前唯一可见确认对象就是商品卡且没有歧义时，回复“确认”“没问题”“按这个”或“就这样”也算明确确认；“继续”和裸数字仍不确认。待确认卡阶段不提供商品卡裸数字确认。只有明确确认后，商品卡才标记为“已确认商品卡”，技能才会进入设计需求预判和输出范围确认；非关键资料可以选择跳过，相关主张会从后续设计中删除；主体、SKU、安全或合法性仍不成立时只问一个关键问题。用户明确要求“全部采用AI推荐并直接确认”时，仍先生成并记录商品卡（待确认）；这句话只确认商品卡，不自动确认写实视图，未同时提供序列号的视图全部排除。完成视图选择和内部冲突检查后才直接标记商品卡确认，不再额外停顿。

## 隐藏视图置信度规则

先判断适用性：只有实体商品中真实存在且可能进入本次图片任务的背面、底部、内部或拆解才评分；数字权益、服务及没有相应物理面的对象不评分。已有可确认的同SKU真实目标图时直接作为证据使用，不进入序列号确认。其余适用目标分别按可见几何30%、对称与连续20%、同SKU线索20%、品类稳定度15%、无冲突与低隐藏复杂度15%计算并向下取整。

每项使用统一锚点：`0=没有依据或冲突，1=极弱，2=局部线索，3=仍有关键未知，4=关键结构可闭合，5=近乎直接证据`。分数表示“能否精确还原当前同款而不发明结构”，不是“能否生成看起来合理的同类商品”；任一接口、开孔、连接、零件数量或安全关键特征低于4分时，总分上限为80分。

- `81–100分`（严格超过80分）：列入写实视图确认清单，分配序列号，向用户展示分数、依据摘要和主要限制；不自动写入写实分镜。
- `0–80分`：不列入写实视图确认清单，不写入写实分镜，改用已证实角度、补拍、真实商品层合成、三维资料或明确概念稿。
- `80分`不放行，因为门槛是“超过80分”。

用户回复写实视图清单中的序列号（例如“1、3”）后，只将对应推理目标写入本次写实分镜范围；没有被选中的目标继续排除。序列号只绑定当前清单，不跨卡复用，也不替代“确认商品卡”。商品卡整体确认后才编译正式分镜；正式分镜不显示分数、置信度或任何视图推断性质的标签。用户确认只授权该视图作为本次画面目标，不自动补充未提供的结构、参数、功效或配件事实。后续补充同SKU真实目标视图时，改为直接证据并重新核对冲突。

## 第五步：设计需求预判与输出范围

商品卡确认后按信息缺口走最短路径：对象、数量、平台/位置、用途和目标SKU/版本已经完整且无冲突时，原意向直接完成范围确认，一行摘要与结构首推在同一轮给出，不再为范围单独停一次，也不展示全菜单；只缺一两项时只补这些缺口；意向不清或你要求完整探索时，才展示下面的设计需求预判卡。预判卡不是运营报告，而是把商品事实转成图片选择：

```text
【设计需求预判卡】
- 已确认商品：品类、商品关系和核心视觉锚点
- 已捕捉意向：原话中已经点名的对象、数量、平台或用途
- 主图：适合解决什么问题、现有依据和主要风险
- SKU图：可用的型号/颜色/容量/套装依据；没有真实关系时不启用
- 详情页：需要解释的决策链、证据和主要风险
- 海报：可成立的主题和场景；没有活动事实时不编造促销
- 产品素材图：白底、透明、无字场景的复用价值与可行性

请选择：
1. 主图  2. SKU图  3. 详情页  4. 海报
5. 产品素材图  6. 全部设计  7. 自定义组合
```

确认时同时写清：对象、分镜数量、平台/位置、用途和目标 SKU 映射。例如：

```text
对象：主图4张 + SKU图2张
目标SKU：红色500ml、蓝色750ml；每张标明对应SKU或“总览”
平台/用途：天猫商品页，解决识别和选型防错
```

这里的“4张、2张”是要交付的分镜数量；提示词完成后说“每张3张”才是每个分镜生成的候选图片数量。用户没有指定对象时，“继续”不会自动等于“全部设计”；用户已经把范围说完整且无冲突时直接记录并推进，只有仍有缺口或多种解释时才请用户确认或调整。

### 用户决策六维

技能不会只从设计者角度判断好不好看，还会在后台模拟用户从“划到图片”到“愿意继续点击”的完整过程：

| 维度 | 核心判断 | 写入分镜时的约束 |
|---|---|---|
| 注意力抓取 | 列表页第一眼是否愿意停驻 | 用主体比例、反差、构图张力和商品专属记忆点抓眼，不靠无关装饰 |
| 三秒信息效率 | 是否马上知道卖什么、好在哪 | 保持“商品主体＞核心卖点＞辅助利益”，核心卖点只保留一到两个，优先保证品类识别 |
| 信任建立 | 是否相信品质、依据和真实度 | 用真实材质、做工、细节和已确认客观证据；销量、认证、专利、功效必须有资料 |
| 情绪与身份 | 是否能想象自己使用、感到适合自己 | 按真实目标人群选择场景、身份气质和氛围，不让情绪表达遮住商品 |
| 转化驱动 | 是否愿意点击、加购或继续浏览 | 价格、优惠、赠品、权益和行动文案只能使用用户确认内容，视觉动线服务下一步行动 |
| 平台与无障碍 | 在实际入口中是否完整、清楚、合规 | 依据任务当时可核验的当前官方规则检查尺寸、裁切、内容限制、对比度和安全区，不把旧记忆当最新规范，也不只依赖颜色传递关键信息 |

不同图片不会强行塞满六个维度：主图优先注意力、三秒信息和品类识别，详情页优先信任、理解和防错，场景图优先情绪与尺度，白底/透明素材优先真实与复用。所有判断只会改变成图任务、构图、信息层级、光影、文案安全区、生产方式和正负提示词，不会生成额外营销报告。

### 全行业商品决策特征

技能不靠固定类目模板限制AI，而是先判断当前商品的八项决策特征：

| 特征 | 主要发现什么 | 会优先调用什么图 |
|---|---|---|
| 身份与SKU复杂度 | 是否容易认错款、颜色、规格、套装或状态 | 标准呈现、SKU差异、到手全家福 |
| 尺寸、适配与空间风险 | 是否可能穿不合、放不下、装不上或接不上 | 尺寸容量、真人比例、空间落位、接口适配 |
| 结构与功能解释难度 | 价值是否藏在内部、连接、层级或工作状态 | 爆炸、剖面、局部开窗、机制与状态验证 |
| 效果与主张证据敏感度 | 是否涉及功效、成分、前后变化、参数或对比 | 同条件对比、真实测试、数据图解、原料来源 |
| 使用、安装与维护成本 | 是否担心不会装、不会用、难清洁或难收纳 | 步骤、正确/错误、清洁维护、耗材更换 |
| 安全、合规与人群风险 | 是否容易误用或触发健康、安全和广告风险 | 使用边界、防错、警示、真实资质 |
| 感官、审美与情绪依赖 | 是否依赖上身、质地、食欲、空间气质或礼赠情绪 | 材质特写、真人场景、感官转译、礼赠场景 |
| 包装、交付与服务复杂度 | 是否关心收到什么、包装版本、赠品或服务 | 开箱清单、包装层级、权益与保障范围 |

同一商品可以同时命中多个特征，但主图、SKU图、海报和详情页会分别承担不同职责：主图负责停驻与识别，SKU图负责选择防错，海报负责单一主题与记忆，详情页负责连续解释、证明、使用和顾虑解除。白底、透明和无字场景只在有真实复用价值时生成。

### 开放式候选图型库

技能内置十三类起点：商品标准呈现、结构拆解、细节质感、功能验证、参照认知、选择适配与防错、使用教学与维护、场景呈现、创意视觉、组合包装与到手、信任背书与来源、利益与行动、数字权益与服务交付。新增的非实体路径覆盖权益总览、真实界面、交付激活、版本差异、有效期与服务边界。每类还包含更细的爆炸图、剖面图、微距、性能测试、空间落位、兼容匹配、清洁维护、人物关系、视觉隐喻、开箱、溯源和利益引导等画法。

这不是封闭菜单。用户给出的图型、案例或参考项目只是思维起点；AI会先检查已有类型，再寻找当前商品尚未覆盖的关键买家问题。每张只保留一个主任务和一个视觉中心，优先用一个主图型组织画面；尺寸线、局部放大、引线、分屏、场景或时间切片等相容手法可以按同一问题组合，并由移动端可读性、证据和生产可行性决定数量。明显占优的简单候选直接按决定性理由选择；只有复杂或难分高下时才使用带统一锚点的一百分排序，避免伪精确。每选一张后再检查其余候选是否真正增加任务、证据、风险降低、场景理解或必要资产，不靠换背景凑数。

### 深化推演循环（loop）与正向引导

每个会改变需求或画面的关键节点都会执行：

```text
证据观察 → 问题建模 → 发散候选 → 跨域组合
→ 反证淘汰 → 收敛排序 → 阶段落位 → 缺口回看
```

“阶段落位”只生成当前步骤允许的结果：预构建是编号建议，商品确认是商品卡，范围阶段是对象、数量、结构和方向，图组阶段是逐张任务；只有正式分镜阶段才编译提示词，不会提前越过商品卡。发现关键缺口时回到问题建模；没有新增决策价值或没有证据可支持时停止。多SKU、高风险、跨行业或陌生商品可增加专业子智能体和独立反证，主控只合并结论。事实、SKU、安全和平台使用必要硬边界；构图、场景、人物、光影、视觉隐喻和表达方式优先用正向目标、可变空间和成功标准引导，让AI主动探索而不是被通用禁令锁死。完整思考链、未采用候选和角色讨论不会进入最终交付。

## 第六步：图组结构与五个综合方向

多张主图、SKU图、海报或详情页都要确定图组结构，但只有多个结构会实质改变任务或顺序时才展示完整菜单；用户已经说明“逐步讲清”“每张独立投放”等关系，或一个结构明显占优时，一句摘要即可确认。可选结构包括：

1. **递进式主次**：从识别到理解、证明、场景或防错逐步增加信息。
2. **等量并列**：每张都能独立使用，各自解决不同购买问题。
3. **混合结构**：前段递进，后段作为独立 SKU、场景或人群变体。
4. **采用系统首推**。
5. **自定义结构**：说明主链张数、独立变体和顺序。

单张采用单张闭环，白底/透明/无字素材默认按资产角色并列；单张也会在内部比较5个方向，只在方向会改变任务或你要求选择时展示选择卡。多图结构确定后固定推演5个产品专属综合方向：

- 方向1–3：偏转化稳妥、平台适配、价值/品牌。
- 方向4–5：偏视觉差异、情绪场景。

每个方向都写当前商品的主任务、依据、主要画法和风险；方向不是五份报告，也不会自动增加图片数量。五个方向始终内部比较，但只有两个以上方向会实质改变任务、场景或生产方式，或你要求查看时，才显示选择卡；用户原话已充分指定、一个方向明显占优、采用推荐或直出时，只记录采用结论并用一句摘要推进。信息型与非实体商品不会为凑方向硬造材质或情绪画面。

没有结构和方向采用结论前，不开始第1张正式分镜。方向确定后先列出每张的唯一任务、目标SKU/版本、实际生成参考输入、信息增量和前后承接，再进入逐张确认。

## 第七步：逐张分镜提示词

交互模式下，每次只展示当前一张完整确认卡，确认或返修后才进入下一张。确认卡至少说明：当前任务、对象和 SKU、参考图使用方式、商品锁定、允许变化、事实边界、画面、镜头、场景/人物、光影材质、文案安全区、生产后期、正向提示词、动态负面提示词和前后承接。

简单、低风险且没有返修历史时，当前图默认只显示：

```text
0 AI首推并自检   1 确认本张并继续   2 定向返修本张
```

需要更多控制、出现复杂风险或选择`2`时，再展开完整 `0–9`：

```text
0 AI首推       1 确认本张并继续   2 定向返修本张
3 返回上一环节 4 补充商品资料     5 调整输出控制
6 调整卖点文案 7 调整视觉与生产   8 调整后续与模式
9 自定义
```

选择 `2` 后可用 `2-1` 到 `2-10` 定位当前任务、卖点证据、文案、美学、场景、镜头构图、商品事实、提示词、画布后期或整张重推。`1` 只确认当前图；当前唯一对象就是这张分镜时，“这张可以”“通过”“下一张”或“按这个继续”也等价于确认本张。只有说“确认本张，剩余自动完成”“1-全部”或“后面直接完成”才切换剩余图片为内部自动复核。直出/全自动只隐藏停顿，不跳过检查。

整张分镜先执行上面的深化推演循环；收敛到当前画面后，提示词再按以下顺序定稿：

```text
观察当前字段 → 草拟 → 结构检查 → 反证 → 最小修复 → 定稿
```

每张分镜只解决一个主要任务，并完整写明参考图使用方式、商品锁定、允许变化与自由探索、视角与事实边界、最终画面、镜头构图、场景人物、光影材质、文字安全区、生产与后期、正向提示词和动态负面提示词。推理阶段先分析全部参考视觉，但单张提示词只声明真正送入模型的一张、多张或全部同款资料；其他SKU默认不传入单SKU生成。正向提示词必须脱离商品卡和上一张独立执行，直接写明采用特征与舍弃项，不能说“以商品卡为准”。动态负面提示词只处理本张最可能发生的具体错误。商品事实、SKU或参考内容改变时，回到商品卡并只重做受影响图；未确认图不能被假装已经完成。

默认使用当前可用的最高推理强度；简单任务只压缩展示，不降低事实、结构和可执行性检查。

只有全部图确认或内部自动复核通过后，才无损聚合最终中文分镜。正式分镜不包含内部评分、置信度数字、子智能体讨论、隐藏思考链、未采用方案、状态或测试文字。

## 第八步：可选生图

正式提示词全部交付且没有待确认分镜后，你可以回复：

- `暂不生图`
- `生成主图-01和主图-03，每张3张`
- `生成当前主图组，每张2张`
- `生成全部图组，每张1张`
- `主图-01生成4张，详情页-03生成2张`

这里的数量是候选图片数量，不是分镜数量；没有明确数量时，每个指定分镜默认生成1张。用户已经说“暂不生图”时直接结束，不重复显示菜单。只有当前环境提供可用生图能力时才执行：没有独立负面提示词入口时可把动态负面约束等价并入同一次指令；候选超上限时拆批；只支持单参考图时，只有能用同一目标SKU的真实商品层或无损参考画布保留证据才继续；多SKU比较优先分别生成/使用真实商品层后期合成；真实透明通道无法可靠实现时不以白底或棋盘格冒充。任何需要减少证据或改变交付语义的降级都会先征求确认。

生图结果出现问题时，只返修最早失败层：商品识别、参考图筛选与综合方式、图片任务、场景物理、提示词冲突或工具能力。未经要求不会自动重生整组。

## 最终分镜提示词示例

下面示例展示正式交付格式。AI会先分析全部有效参考视觉，再为当前分镜选择真正输入模型的一张、多张或全部同款资料；正式分镜不添加参考图索引或固定图片编号，不依赖隐藏商品卡，也不包含内部评分、菜单、确认过程或未采用方案。

## 返修

用稳定编号点名，例如：

```text
返修详情页-03。
保留：商品、SKU、动态参考图使用方式、任务和机位。
修改：手部接触、接触阴影和主体占比。
禁止：不要改容量、品牌原文或其他分镜。
交付：完整重发这一张分镜，暂不生图。
```

局部返修保留原页码和编号，只重算受影响字段；共享商品事实改变时才检查相邻分镜。

## 自我学习

当前任务中明确的选择、否定、纠正和有效返修会帮助后续分镜更贴近你的思路。跨任务长期保存必须由你明确授权；没有可用的私有记忆能力时只在本轮生效，不写入仓库。

学习不会改变商品事实、合规边界、隐藏视图的“直接证据优先；缺少直接资料时超过80分且序列号确认”规则或本轮明确要求。候选数量、工具故障和未评价结果不会被当成偏好。

## 常见问题

### 只有正面图，可以做背面吗？

实体商品的背面真实存在且与任务有关时，可以先单独评分。超过80分会进入写实视图确认清单，并带有序列号；你回复序列号确认后，才会写入写实分镜。80分及以下不进入该清单，改用补拍、合成、三维资料或概念稿。确认后的正式分镜不显示分数或视图推断性质标签。

如果已经提供同SKU真实背面图，则直接作为证据使用，不需要评分或序列号确认；仍会检查它是否与目标SKU、状态和其他图片冲突。

### 图型库会不会限制AI只能做固定画法？

不会。图型库是帮助AI发散的能力下限，不是上限。AI会先匹配已有类型，再从买家问题、行业风险、输出对象和生产方式主动寻找遗漏；只要新画法能够解决真实问题、有证据、可生产且不重复，就可以建立商品专属候选。

### 为什么有很多规则，又说以正向引导为主？

硬规则只保护商品事实、SKU、安全、合规和平台边界。构图、场景、人物、光影、创意隐喻与视觉语言会优先通过“要达到什么效果、哪里可以变化、什么算成功”来引导；负面提示词只针对当前分镜的具体高风险错误，不使用通用黑名单。

### 怎样适配完全陌生的行业商品？

技能先判断八项商品决策特征，再选择主图、SKU图、海报或详情页各自真正需要承担的任务；已有图型不够时会建立新候选。行业常识只帮助发现问题，不能替代当前SKU的参数、功效、适配、认证或安全证据。

### 数字权益或服务商品怎样使用？

至少提供一种可访问参考视觉，例如真实界面、权益说明页、交付/预约流程、授权页或已授权服务场景。商品卡会把SKU解释为档位、版本、时长、地区或账号类型，并确认交付、有效期、退款/取消/续费和异常处理边界；不会评分物理背面、底部、内部或拆解。真实UI、订单状态、授权文件、二维码和编号使用原始证据像素或后期排版，模型只生成其外部的背景、设备框、场景与光影，也不会把权益画成会收到的实体卡或快递。

### 多张参考图会全部传给生图模型吗？

不会机械全传。AI先分析全部有效参考视觉，再按当前分镜只输入能证明目标SKU/版本的一张、多张或全部同款资料。其他SKU默认不进入单SKU生成，只用于内部识别差异；SKU总览或比较图会分别锁定各SKU并采用独立商品层、分区生成或后期合成。若参考内容冲突，最终提示词直接写明采用和舍弃的具体特征，不让生图模型猜“商品卡里是什么”。

### 没有卖点和参数怎么办？

AI会先列候选卖点和需要补充的准确字段，让你数字选择或手动输入。未确认的内容不会进入商品卡事实区、文案或提示词。

### 商品卡什么时候算确认？

数字选择或纠正后先得到“商品卡（待确认）”。当前唯一确认对象就是商品卡时，“确认”“没问题”“按这个”“就这样”都可以；“继续”和裸数字不算确认。明确确认后（或明确授权“全部采用AI推荐并直接确认”，且系统先形成待确认卡并通过冲突检查），才进入设计需求预判和输出范围；在此之前不会编写正式分镜。

### 可以直接出稿吗？

可以说“全部采用AI推荐并直接确认”。技能仍会先生成并记录商品卡（待确认），完成冲突检查后把这句话视为确认，再完成后续范围、结构、方向和逐图复核；外部只展示必要确认和最终分镜。

### 能不能只要提示词，不要报告？

可以。商品卡和建议只用于确认；最终交付只保留逐张中文图生图分镜提示词。

### 能不能生图？

可以在提示词完整交付后选择是否生图、生成哪些分镜和每张数量。默认不自动生图。

### 多张图为什么还要选结构和方向？

结构决定图片之间是递进、并列还是混合；方向决定这组图优先解决转化、选型、证据、视觉差异还是情绪场景。技能始终内部比较5个产品专属方向，但用户意向清楚或一个方案明显占优时只给一句采用摘要；只有真实歧义或你要求查看时才展开菜单，避免多张图只换背景，也避免无价值停顿。

### 我只确认当前图，什么时候会到下一张？

交互模式下，当前图确认或返修完成后才进入下一张。回复“确认本张，剩余自动完成”后，后续图仍会经过内部复核，但不再逐张停下来询问。

### 分镜数量和生图数量有什么区别？

范围确认里的“主图4张”表示交付4个不同任务的分镜；提示词交付后的“每张3张”表示每个分镜生成3个候选图片，两者不会混用。
