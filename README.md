# 商品图深度推演与图生图分镜技能

这是一个专门把“商品参考图”转化为“逐张中文图生图分镜提示词”的 Codex 技能。

它先判断商品是什么、参考图能证明什么、真正需要制作哪些图片，再为每张图片写出可直接用于图生图模型和后期制作的提示词。商业、运营、产品、营销、消费者心理和美学知识只在后台帮助判断，不会扩展成报告或方案。

正式分镜提示词始终先完整交付。之后可以选择不生图、生成指定分镜、生成当前图组或全部图组，并为每张设置候选数量；默认不会自动生成图片。

## 能做什么

- 识别商品、SKU、颜色、型号、包装、配件、状态和可见结构。
- 给上传图片建立稳定的`参考图1、参考图2……`编号，避免引用错图。
- 判断哪些视角、材质、文字和场景能够真实制作，哪些未知内容不能补画。
- 从买家任务、证据、选型、防退货、平台位置和素材能力反推不重复且足够的必要图片清单。
- 生成主图、SKU图、详情页、海报、白底图、透明背景图和无字场景图的逐张分镜。
- 根据任务选择1、3或5个真正不同的方向，不用换色和风格名称凑方案。
- 用内部定量评分比较图片价值、证据、生产可行性和信息增量。
- 在复杂任务中调用不同子智能体分别处理商品、图组、视觉提示词和独立审查。
- 根据明确选择、否定和有效返修学习本轮偏好；获得授权后才保存长期偏好。
- 根据外部生成结果定位商品、构图、人物物理、提示词或工具问题，只返修受影响内容。

## 核心工作方式

整个技能只围绕一条自然中文主线工作：

`看懂商品与参考图 → 判断真正需要哪些图 → 编排每张唯一任务 → 写中文图生图提示词 → 可选生图或定向返修`

循环、多智能体、定量评分和偏好学习只在后台增强结果，不增加用户需要操作的技术流程。

### 商品保真

- 商品身份、SKU、结构、比例、颜色、可见材质、包装、配件、标志和可见原文不得无依据改变。
- 只有正面图时，不生成真实背面、底部、内部或拆解。
- 多角度照片不等于精确三维模型，不证明隐藏结构。
- 复杂标志、型号、包装原文、参数表和长文案优先由真实商品层或后期排版。

### 图组选择

候选图片先通过事实、合规和可实现性检查，再按买家决策价值、证据强度、生产可行性、信息增量、理解效率和输出位置适配进行内部排序。

每加入一张图片都会重新检查新增价值。不能新增事实、证据、选择帮助、场景理解、顾虑解法或必要素材形态的页面会被合并或删除；只有用户明确接受时，才可另做清楚标注的视觉变体。

### 提示词循环

每张提示词在后台执行：

`观察 → 草拟 → 结构化检查 → 反证 → 最小修复 → 定稿`

事实、SKU、未知面和生产可行性是不可妥协条件，不能被平均分或审美偏好覆盖。最终只交付正式中文分镜，不显示内部评分、角色讨论或思考链。

## 安装

### 1. 克隆仓库

```powershell
git clone https://github.com/GOOOXG/ecommerce-detail-page-skill.git
Set-Location .\ecommerce-detail-page-skill
```

### 2. 安装到 Codex

把仓库中的 `ecommerce-detail-page` 文件夹复制到 Codex 技能目录。下面命令会先备份同名旧版本：

```powershell
$codexHome = if ($env:CODEX_HOME) { $env:CODEX_HOME } else { Join-Path $env:USERPROFILE '.codex' }
$skillsDir = Join-Path $codexHome 'skills'
$source = Join-Path (Get-Location).Path 'ecommerce-detail-page'
$target = Join-Path $skillsDir 'ecommerce-detail-page'

if (-not (Test-Path -LiteralPath $source -PathType Container)) {
    throw "未找到技能目录：$source"
}

New-Item -ItemType Directory -Force -Path $skillsDir | Out-Null

if (Test-Path -LiteralPath $target) {
    $backupRoot = Join-Path $codexHome 'skill-backups'
    $backupName = 'ecommerce-detail-page-' + (Get-Date -Format 'yyyyMMdd-HHmmss-fff')
    $backup = Join-Path $backupRoot $backupName
    New-Item -ItemType Directory -Force -Path $backupRoot | Out-Null
    Move-Item -LiteralPath $target -Destination $backup
    Write-Host "旧版本已备份到：$backup"
}

Copy-Item -Recurse -Force -LiteralPath $source -Destination $target
```

安装后重新打开 Codex 或新建任务，让技能重新扫描。更新仓库后，重新运行复制命令即可。

## 快速开始

上传商品图后，直接输入：

```text
使用 $ecommerce-detail-page，根据这些商品参考图，判断真正需要制作哪些图片，并输出逐张中文图生图分镜提示词。暂不生图。
```

如果目标已经明确，可以更直接：

```text
使用 $ecommerce-detail-page，为这个商品制作6张天猫主图。商品结构、颜色、标志和包装原文不得改变；每张解决不同购买问题。最终只输出中文分镜提示词，暂不生图。
```

## 完整任务模板

需要精确控制时使用下面模板；不知道或不需要的行直接删除：

```text
使用 $ecommerce-detail-page。

商品名称：【名称】
商品与SKU：【单品 / 多SKU关系 / 套装关系】
参考图说明：【每张图对应的SKU、角度、状态或用途】
输出对象：【主图 / SKU图 / 详情页 / 海报 / 白底图 / 透明图 / 无字场景图】
数量：【按对象填写；不确定可写“请判断真正需要几张”】
平台与位置：【淘宝 / 天猫 / 京东 / 拼多多 / 抖音 / 小红书 / 亚马逊 / 独立站等】
画布要求：【比例、像素、横竖版；未知则删除】
已确认事实：【材质、尺寸、功能、适配、认证等】
核心卖点：【只写有可靠依据的内容】
必须保持：【结构、比例、颜色、材质表面、标志、包装原文、配件等】
允许变化：【背景、人物、道具、光影、摆放、留白等】
禁止内容：【未知背面、虚构内部、错误文字、夸张效果等】
推进要求：【默认推荐 / 逐张确认 / 直接完成 / 深度推演 / 脑暴后收敛】
提示词完成后：【暂不生图 / 指定分镜生图 / 当前图组生图 / 全部生图，每张N个候选】
```

## 控制推进方式

| 方式 | 可以这样说 | 实际行为 |
|---|---|---|
| 默认推荐 | “先推荐让我选” | 只展示会实质改变结果的选择 |
| 逐张确认 | “一张一张确认” | 完整展示当前一张，确认或返修后继续 |
| 直接完成 | “直接完成，只要最终提示词” | 内部完成必要检查，只在无法安全继续时询问 |
| 深度推演 | “完整深度推演” | 提高商品核对、图组、视觉、生产和反证强度 |
| 脑暴后收敛 | “先多想一些方向再收敛” | 扩大搜索后只让采用方向进入正式分镜 |
| 返修 | “只改第3张” | 保留其他内容，只重算受影响分镜 |

用户没有指定时采用默认推荐。自然语言始终优先，不需要记忆专用命令或数字菜单。

## 一次完整任务会发生什么

1. **参考图建档**：按上传顺序建立稳定编号，区分商品、SKU、视角、细节、包装和场景职责。
2. **商品判断**：提取轮廓、结构、比例、颜色、可见材质、文字、配件和未知面。
3. **图片需求推演**：判断买家需要识别、理解、选择、相信、代入、学会或消除什么顾虑。
4. **必要图片选择**：先排除伪事实和不可实现画面，再用内部评分及新增价值去重。
5. **方向收敛**：方向明确时深审1个，存在真实歧义时比较3个，用户明确要求深度全案、比较或脑暴时搜索5个。
6. **逐张设计**：为每张确定唯一任务、参考图、商品锁定、构图、场景、人物、光影、文案区和生产方式。
7. **提示词检查**：通过商品保真、事实、物理关系、单义性和可执行性检查后定稿。
8. **正式交付**：输出逐张中文分镜提示词。
9. **可选生图**：按用户选择生成指定范围和数量，或直接结束。

用户已经明确对象、数量和方向时，技能会直接采用，不强迫重复走完整确认流程。只有商品无法识别、可能误导购买、要求无依据高风险内容、素材无法维持真实性或合法授权不成立时，才会询问一个关键问题。

## 常用示例

### 多SKU详情页

```text
使用 $ecommerce-detail-page，为这组多SKU商品制作详情页。先区分每张参考图对应的型号、颜色和包装，再判断真正需要哪些页面；不要编造尺寸、适配和效果。采用逐张确认，最终输出完整中文分镜提示词。
```

### 白底、透明和无字场景素材

```text
使用 $ecommerce-detail-page，基于商品参考图制作白底图2张、透明背景图1张、无字场景图3张的分镜提示词。保留商品原有文字，不新增广告文案；直接完成，提示词完成后暂不生图。
```

### 方向已经锁定

```text
使用 $ecommerce-detail-page。为这个商品制作6张主图，方向已经锁定为“真实厨房使用场景、商品大比例识别、道具克制”。只深审这个方向，不生成陪跑方案；外部只输出最终中文分镜提示词。
```

### 定向返修

```text
返修【详情页-04】。
保留：商品、参考图、页面任务、背景色和上下页关系。
修改：提高主体占比，缩短标题，修正手部接触和阴影。
禁止：不要改变SKU、机位和原有标志。
交付：完整重发第4张分镜，暂不重新生图。
```

## 最终分镜包含什么

每组先列参考图索引。每张使用稳定标题，例如：

```text
## 第1张（主图-01）：首屏商品识别
```

正式必需字段是`输出对象`、`成图任务`、`画布与布局`、`商品身份参考图`、`画面主参考图`、`商品锁定`、`允许变化`、`视角与事实边界`、`最终画面`、`镜头与构图`、`光影、材质与色彩`、`生产与后期`、`图生图提示词`和`动态负面提示词`。`辅助参考图`、`场景与人物`和`最终文案`只在确实需要时出现。

如果指定数量无法真实成立且你已经允许缩减，参考图索引前只会增加一行`> 数量说明：实际交付数量与原因`，不会附加评分或审查报告。

最终结果不会包含内部评分、多智能体讨论、隐藏思考链或模型名。

## 提示词完成后选择是否生图

可以直接回复：

- `暂不生图`
- `生成主图-01和主图-03，每张3个候选`
- `生成当前主图组，每张2个候选`
- `生成全部图组，每张1个候选`
- `主图-01生成4个，详情页-03生成2个`

已经明确要求生图但没有写数量时，每个指定分镜默认生成1张。

生图前会检查当前工具是否支持所需参考图、负面提示词、遮罩、尺寸、透明背景和候选数量。必需能力不足时不会调用，也不会把白底图冒充透明成品或静默减少数量。

生成结果出现问题时，技能会先区分随机候选差异、工具故障和提示词的可重复错误，再决定是否返修。未经明确要求，不会自动重生整组。

## 偏好学习

当前任务中的明确选择、否定和有效返修会用于本轮后续分镜。例如：

```text
本次后续主图都优先真实使用场景，商品占比更大，不使用悬浮圆台。
```

需要跨任务记住时必须明确授权：

```text
记住：以后为本品牌制作主图时，优先真实场景和大比例商品，不使用悬浮圆台。适用范围是本品牌主图，请长期保存。
```

跨任务保存只在用户明确授权且当前环境提供私有记忆能力时执行，不写入技能仓库；没有可用记忆能力时只在本轮生效。可以随时查看、声明本次例外、缩小范围、撤销或彻底删除。偏好不能覆盖商品事实、合规边界和当前明确要求。

## 常见问题

### 只有一张商品图能用吗？

可以，但只制作该图能够证明的角度和状态。未知背面、内部、配件和开合结构不会被补成事实。

### 不知道应该做几张怎么办？

直接写“请判断真正需要几张”。技能会根据买家任务、信息增量、证据和生产能力选择，新增价值不足的页面不会加入。

### 我指定的数量很多怎么办？

技能会尽量给每张分配不同任务。如果真实任务或可用素材不足，会说明当前能真实制作几张，并让你选择减少数量、补充素材或把剩余图片明确作为视觉变体；不会把重复图片或缺素材任务伪装成可立即生图的新需求。

### 精确文字为什么常被安排到后期？

图像模型容易改错标志、型号、包装原文和长文案。保留真实商品像素并由后期排版通常更可靠。

### 能只返修一张吗？

可以。点名稳定编号并说明保留项、修改项和禁止联动项。局部返修保留原页码，不会把第4张改成第1张。

### 没有生图工具怎么办？

选择“暂不生图”，把正式提示词交给支持参考图的外部图生图模型。核心交付不依赖当前环境必须能够生成图片。
