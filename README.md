# 商品图深度推演与图生图分镜技能

这是一个面向 Codex 的中文技能：把一张或多张商品/交付参考视觉，经过识别、证据整理、需求挖掘、图组推演和逐张确认，编译成可以独立执行的中文图生图分镜提示词。它也支持在提示词交付后按用户选择调用生图，并根据已评价的结果做定向返修。

仓库地址：[GOOOXG/ecommerce-detail-page-skill](https://github.com/GOOOXG/ecommerce-detail-page-skill)

技能的唯一正式交付是逐张分镜提示词。商品卡、需求预判卡、范围卡和确认卡只用于对话中的事实、目标、授权与生产路径确认，不另行变成运营报告、营销方案、产品报告或审美报告。

## 先看懂它解决什么问题

普通的“给商品写提示词”容易出现四类根本错误：没有真正看图就猜商品；把卖点、参数或隐藏结构当成事实；多张图只是换背景而没有新增决策价值；提示词依赖上文，交给生图模型后无法独立执行。

本技能把任务还原为一个买家决策问题：

1. 买家第一眼能不能认出卖的是什么？
2. 三秒内能不能理解核心价值和差异？
3. 画面有没有真实证据来支撑品质、功能、尺寸或交付？
4. 用户能不能代入使用场景、身份和情绪？
5. 画面是否降低选错、误用、预期不符和售后风险？
6. 结果是否符合平台位置、可读性、无障碍和实际生产条件？

AI可以在这些问题上自由发散，但商品身份、SKU、可观察事实、安全、授权、隐私和生产能力是硬边界。创意部分使用正向目标、允许变化和成功标准引导，不用一长串通用禁令压缩合理想象。

## 核心流程

```text
查看全部有效参考视觉
  ↓
识别商品主体、SKU/版本、状态与证据边界
  ↓
AI预构建：卖点、待补事实、素材缺口、图片假设
  ↓
用户数字选择或自然语言纠正
  ↓
商品卡（待确认）
  ↓
用户确认，或单一清晰目标的明确直出授权
  ↓
已确认商品卡
  ↓
首要买家目标、风险等级、工具能力画像
  ↓
需求预判与输出范围
  ↓
必要时确认隐藏视图，再确定图组结构
  ↓
自适应综合方向（简单任务 1 个；复杂任务最多比较 5 个）
  ↓
图组编排、逐张确认或内部自动复核
  ↓
最终中文图生图分镜提示词
  ↓
可选生图、结果评价与受控返修
```

主线不能倒置。没有商品卡确认，不能把猜测写进正式提示词；没有范围、结构和逐张任务，不能直接编写第 1 张；没有完整提示词和用户授权，不自动生图。

## 适用范围与明确边界

### 可以处理

- 实体商品：服饰鞋包、珠宝、美妆、食品、3C、家电、家居、工具、汽配、工业品、母婴、宠物、户外、礼赠、耗材等。
- 数字权益与服务：软件/会员、课程、订阅、预约、租赁、门票、权益包、服务流程等。
- 输出对象：主图、SKU 图、详情页模块或连续长画布、海报、白底图、透明图、无字场景图。
- 单参考图、多参考图、同一商品的正面/侧面/细节/包装/结构资料，以及用于视觉灵感的风格或竞品图。

### 不会做

- 没有可访问的真实参考视觉时，假装已经完成图片识别或生成“保真商品分镜”。
- 把行业常识、相似款、风格图或竞品图当成当前 SKU 的参数、功效、认证、结构或权益证据。
- 把用户确认一个画面视图解释成安全、性能、功效、适配、认证或价格事实。
- 在正式分镜中输出内部分数、置信度、角色讨论、隐藏思考链、候选菜单、固定参考图编号或调试字段。
- 自动生成价格、优惠、销量、评价、赠品、认证、健康功效或服务承诺；这些内容必须有当前可核验资料。
- 用“产品素材图”这种模糊名称跳过白底、透明、无字场景等实际资产类型的确定。

## 安装

### 方式一：克隆仓库

```powershell
git clone https://github.com/GOOOXG/ecommerce-detail-page-skill.git
Set-Location .\ecommerce-detail-page-skill
```

### 方式二：复制到 Codex 技能目录

下面脚本会把同名旧版本移到备份目录，再安装当前版本。`CODEX_HOME` 未设置时使用用户目录下的 `.codex`。

```powershell
$codexHome = if ($env:CODEX_HOME) { $env:CODEX_HOME } else { Join-Path $env:USERPROFILE '.codex' }
$skillsDir = Join-Path $codexHome 'skills'
$source = Join-Path (Get-Location).Path 'ecommerce-detail-page'
$target = Join-Path $skillsDir 'ecommerce-detail-page'

if (-not (Test-Path -LiteralPath $source -PathType Container)) {
    throw "未找到技能目录：$source"
}

New-Item -ItemType Directory -Force -Path $skillsDir | Out-Null

if (Test-Path -LiteralPath $target) {
    $backupRoot = Join-Path $codexHome 'skill-backups'
    $backupName = 'ecommerce-detail-page-' + (Get-Date -Format 'yyyyMMdd-HHmmss-fff')
    $backup = Join-Path $backupRoot $backupName
    New-Item -ItemType Directory -Force -Path $backupRoot | Out-Null
    Move-Item -LiteralPath $target -Destination $backup
    Write-Host "旧版本已备份到：$backup"
}

Copy-Item -Recurse -Force -LiteralPath $source -Destination $target
```

安装后重新打开 Codex 或新建任务，让技能重新扫描。仓库更新后再次执行复制命令即可。

## 快速开始

上传一张或多张可访问的商品参考视觉后，输入：

```text
使用 $ecommerce-detail-page。
先识别全部参考图中的商品主体，进行 AI 预构建并让我确认商品卡；确认后根据买家任务输出逐张中文图生图分镜提示词，暂不生图。
```

如果已经知道输出对象，可以写清楚：

```text
使用 $ecommerce-detail-page。
为这个商品制作主图 4 张、SKU 图 2 张和详情页模块。先识别主体并让我确认商品卡；每张解决不同购买问题，提示词完成后暂不生图。
```

如果只想减少停顿，可以说：

```text
使用 $ecommerce-detail-page，全部采用 AI 首推并直接完成，只交付中文分镜提示词，不生图。
```

“直接完成”只压缩菜单，不会让模型跳过主体、SKU、事实、素材、安全和授权冲突检查。多 SKU、相似款或主体不清时，仍需要看到商品卡并确认。

## 完整使用教程

### 第一步：图片识别

技能会先实际查看每份可访问参考视觉的像素或真实画面内容，再判断商品形态：实体商品、数字权益或服务。文件名、附件数量、替代文字、聊天摘要和“已经提供图片”的口述，只能帮助定位，不能替代看图。

识别阶段会综合全部有效资料，整理：

- 核心对象、品类、用途、品牌、型号、SKU/版本和状态。
- 实体商品的轮廓、比例、部件、可见结构、颜色、表面、包装、配件和使用状态。
- 数字权益/服务的真实界面、权益层级、流程、交付/激活状态、地区、账号范围、有效期和授权边界。
- 每份视觉对身份、结构细节、文字/权益、尺度/使用、场景灵感或反例承担的职责。
- 图片直接可见事实、用户明确事实、策略推断、待补证内容和不能使用的内容。

多张图先全部分析，后面才决定某一张分镜实际向生成模型提供一张、多张或全部同款资料。分析全部资料不等于把全部资料机械传给模型。

如果主体、SKU 或状态无法合理区分，技能会先指出最小冲突并请求补充，不会先猜一个商品继续写提示词。

### 第二步：AI 预构建

识别后，AI 一次性给出可供你选择或纠正的预构建内容：

1. 候选卖点及其依据；没有证据的卖点标为待补证。
2. 会改变画面或文案的事实字段，例如尺寸、容量、材质、适配、数量、安装方式和包装清单。
3. 已有素材能证明什么、缺少什么，以及每份素材是商品证据还是视觉灵感。
4. 建议图片：每项只写唯一买家问题、需要的证据、画法、生产方式、信息增量和主要风险。
5. 可用视角、场景、人物、画布、后期和图生图条件。
6. 实体商品适用的隐藏视图候选（背面、底部、内部、拆解）。

建议图片只是需求假设，不锁定正式对象、分镜数量、最终图型或顺序。简单任务只给首推和会改变分镜的少量备选；复杂任务才展开更多候选。

## 营销模型如何帮助 AI 更快构建分镜

营销模型与消费决策心理学是技能内部的“推理加速层”，不是新的交付物，也不是用户必须学习或逐项选择的菜单。AI 会先识别买家当前最重要的阻力，再按需选一个主模型、最多两个辅助检查，把结论编译成图片任务；它不会改变“识别 → 预构建 → 商品卡 → 范围 → 图组 → 逐张分镜”的主流程，也不会用模型名替代商品证据。

统一编译格式如下：

```text
商品事实 → 买家任务 → 阻力/动机 → 卖点/利益 → 证据需求
→ 图片任务 → 文案命题 → 生产边界 → 成功标准
```

### FABE：把卖点变成可证明的画面

以“可拆卸杯盖”为例，只有当参考图或说明资料确实支持时，AI 才这样推演：

| 步骤 | 后台问题 | 分镜落点 |
|---|---|---|
| F 特征 | 看得见什么？ | 杯盖与杯身的连接关系 |
| A 优势 | 对当前任务有什么改善？ | 能按真实步骤分离 |
| B 利益 | 买家得到什么？ | 更容易理解清洁动作，减少死角顾虑 |
| E 证据 | 凭什么相信？ | 同 SKU 结构实拍或说明书步骤 |

最后只编译成一张“看清连接关系和拆卸顺序”的结构细节图，主体、部件和证据层由真实商品资料承担，模型可以自由探索背景、光线和留白。没有 E 证据时，利益降级为“展示可见连接”，待补证，不写“防漏、抗菌、保温”等未经证明的承诺。

### 不同模型怎样转成图片任务

| 关注点 | AI 可调用的模型 | 转成分镜时要做什么 |
|---|---|---|
| 先让用户停下并看懂 | AIDA、AIDMA、认知流畅 | 首图先锁定品类和主体，再用一个已确认利益建立视觉记忆点 |
| 从认知走到购买和忠诚 | AIPL、5A、RACE | 入口图负责认知，详情图负责解释和证据，复购/服务图只在有真实资料时承接 |
| 判断增长来自哪里 | GROW（渗透力、复购力、价格力、延展力） | 分别检查新品类教育、复购/补货、价格升级价值证明和关联品类延展；没有经营数据时只作为素材假设 |
| 人与商品在什么场景相遇 | 人货场、STP、同理心地图 | 明确谁在何时何地完成什么任务，再决定人物、道具、尺度和画面语言，不凭空编用户画像 |
| 快速抓卖点并证明 | FAB/FABE、USP、RTB、4U | 把特征、利益、差异和相信理由分别落到主体、短文案、细节或证据图 |
| 情绪入口与承诺 | EPP、ESP/RSP、叙事传输 | 先建立真实情绪和痛点，再给可验证承诺；无证据时只保留场景与可观察特征 |
| 复盘哪里掉人 | AARRR、指标树、OODA、CRO | 只返修最早失败的识别、理解、信任、选择或行动图片，不为指标盲目加图 |

参考文件还收纳了与分镜直接相关的历史扩展模型，例如相似人群、KOC/UGC、增长/内容/付费循环、A/B 与因果复盘、WTP 与价格带、CAGE 本地化、5W2H 根因分析、品牌资产、知识产权矩阵和危机沟通。它们只在能改变图片任务、证据、场景、SKU选择或返修动作时按需调用，不会全量加载，也不会变成独立运营报告。

之前版本中容易被遗漏、但仍能直接帮助构图的内容也已合并到同一个加速层：人口/地理/心理/行为/场景/价值/圈层细分、Persona/用户故事、场景立方体、非目标人群、生命周期与补货/订阅、主图CTR、详情页信息顺序、货盘金字塔、价格带卡位、SKU精简、素材工厂，以及 GPM、FACT、KFS、STEPS 等成交场路由。它们只改变“谁看、先看什么、需要什么证据、如何选择或如何复用”，不改变商品事实，也不要求恢复旧版的独立合同、状态机或运营报表。

同样补回了广告与平台责任、产品认证路径、知识产权矩阵、内容本地化、ESG/LCA、危机沟通、AI代理购物、个性化内容和归因边界等安全/生产视角；当这些模型不能落到当前分镜字段时，技能会跳过它们。具体图型仍由开放式图型库按商品和买家问题继续发散，不被历史清单封顶。

用户提到的平台、行业或模型只是思维入口。没有平台数据时，FAST 只用于提出“拉新、转化、高价值或活跃”哪一类素材假设；没有真实库存、截止时间、原价、销量或评价时，不使用 FOMO、锚定效应、社会证明等表达。FOMO 只能呈现可核验的真实时点，锚定只能使用真实规格、套装或可核验成本参照，不能伪造倒计时、划线价或“热销”标签。

当证据、生产能力或平台条件不足时，模型结论按以下顺序降级：保留可观察特征 → 标为待补证 → 改用真实商品层/后期/补拍/三维资料 → 删除主张。任何模型都不能放行健康、安全、性能、认证、价格、兼容或交付承诺，也不能把隐藏视图置信度当成这些主张的证据。

营销模型只在后台帮助排序和构设画面；最终分镜只写自然中文的图片任务、商品锁定、参考图使用、画面与生产指令，不显示模型名称、评分、角色讨论或营销报告。

### 第三步：数字选择与手动纠正

编号只对当前卡有效，下一张卡自动失效。推荐写字段名，避免多个列表的数字产生歧义：

```text
主体：1
卖点：1,3
补充：容量=750ml；材质=304不锈钢
采用素材：1,2
建议图片：1,2,4
```

也可以直接用自然语言：

```text
参考图中的正面和侧面是同一款；容量不是 500ml，而是 750ml；卖点“保温 24 小时”没有检测资料，不采用；只做主图和详情页。
```

用户纠正优先级最高。纠正会让 AI 重算受影响的主体、SKU、卖点、素材和图像建议，不继续沿用旧结论。

#### 隐藏视图确认规则

只有实体商品真实存在的背面、底部、内部和拆解才适用。数字权益、服务或没有对应物理面的对象标记为不适用，不评分。

- 已提供同 SKU 真实目标视图：直接作为证据使用，不需要评分或序列号确认，但仍检查冲突。
- 缺少同 SKU 目标视图：背面、底部、内部、拆解分别计算独立还原分数，不能用一个总分放开全部未知结构。
- 严格高于 80 分的目标：在任务相关性明确后推送独立序列号确认卡。
- 80 分及以下：不进入写实分镜，改用已证实角度、真实商品层合成、补拍、三维资料或明确概念稿。
- 用户回复序列号后，只授权对应视图进入本次写实分镜，不自动证明参数、功效、性能、安全、适配或认证。

示例确认卡：

```text
【写实视图确认】
1. 背面｜92 分｜依据：可见侧边连续、同 SKU 结构线索一致
2. 底部｜86 分｜依据：底部轮廓可闭合；接口细节仍需保守处理

请回复要纳入本次写实分镜的序列号，例如“1”；不采用可回复“无”。
```

最终正式分镜不会出现分数、置信度或视图推断性质标签。

### 第四步：生成并确认商品卡

选择或纠正后，技能先生成一张“商品卡（待确认）”。它是后续所有分镜的事实底座，至少包含：

- 商品形态、核心对象、SKU/版本/状态和识别把握。
- 全部有效参考视觉的综合结论，以及单目标与其他 SKU 的隔离关系。
- 图片可见事实、用户确认事实、已采用卖点和待补证卖点。
- 已有素材、缺失素材、素材职责和可靠生产方式。
- 必须保持、允许变化、自由探索和必要边界。
- 隐藏视图的直接证据、独立分数、已确认/未选择/待范围判断状态。
- 数字权益/服务的交付、激活、有效期、权限、退款/取消/续费、授权和异常边界。

重要主张会在内部轻量证据账本中记录来源、具体证据、可用范围和不可推导内容。用户声明可以作为本轮确认依据，但不能单凭声明升级成高风险事实。

确认方式：

- 当前唯一可见对象是商品卡时，“确认”“没问题”“按这个”“就这样”“确认商品卡”都可确认。
- “继续”和裸数字不确认商品卡，避免把浏览意图误当授权。
- 单一清晰目标且没有关键冲突时，“直接出/只要提示词/全部采用推荐”可作为明确直出授权。
- 多 SKU、相似款、主体/SKU/状态不确定或关键事实未证实时，必须展示卡并等待确认或纠正。

商品卡确认不是分镜确认，也不是生图授权；后续范围、逐图确认和生图数量分别处理。

### 第五步：首要目标、风险与范围

商品卡确认后，先确定本组的一个首要买家目标，最多保留两个次要目标，并写出不可牺牲的护栏。常见目标包括首屏识别、核心卖点理解、SKU 防错、功能证据、尺寸/容量认知、使用代入、信任建立和行动引导。

同时做三件事：

1. **风险分层**：低风险是背景、留白、普通构图变化；中风险涉及尺度、接触、文字、结构或平台可读性；高风险涉及健康、安全、性能、认证、价格、权益、隐私、授权或严重误购。
2. **工具能力画像**：确认可接收几张参考图、能否隔离 SKU、是否支持遮罩/分层/透明通道、文字由谁负责、画布与候选上限、失败能否回溯到分镜编号。
3. **输出范围**：明确对象、成品数量、分镜/模块数量、平台/位置、画布比例、目标 SKU 和生图候选数量。

完整意向已经明确且无冲突时，用一行摘要记录并直接进入结构首推；只有缺口会改变任务时才发完整范围卡。

数量必须分三层：

| 数量 | 含义 |
|---|---|
| 成品数量 | 最终交付多少个文件或连续长画布 |
| 分镜/模块数量 | 需要解决多少个不同买家问题、编写多少条提示词 |
| 每分镜候选数量 | 提示词交付后实际生成多少张候选图 |

例如：`详情页成品 1 张连续长画布 + 内部 5 个模块/分镜 + 每模块生成 2 个候选`。长画布的模块数由真实买家任务和证据决定，不默认 8、10 或 12 个。

### 第六步：图组结构与自适应方向

多张图先确定结构：

1. 递进式主次：识别 → 理解 → 证明 → 使用/防错。
2. 等量并列：每张可独立投放，各自解决不同问题。
3. 混合结构：前段递进，后段做独立 SKU、场景或人群变体。
4. 自定义结构：由用户指定主链、变体和顺序。

一个结构明显占优时只给一句采用摘要；只有结构会实质改变任务或顺序时才展示菜单。

方向推演采用自适应深度：

- 简单、低风险、资料充分：通常只保留一个首推。
- 中等复杂度或存在真实取舍：比较 1–3 个方向。
- 多 SKU、高风险、跨行业或生产路径分歧明显：最多比较 5 个。

下面五类只是发现入口和上限，不是固定方案：转化稳妥、平台适配、价值/信任、视觉差异、情绪场景。每个实际采用方向都必须针对当前商品写清主任务、依据、画法和风险；不为凑数硬造材质、情绪或场景。

整个推演 loop 统一使用：

```text
证据观察 → 问题建模 → 发散候选 → 跨域组合 → 反证淘汰
→ 收敛排序 → 阶段落位 → 缺口回看
```

当候选没有新增事实、证据、选择帮助、场景理解或风险解法时停止发散。提示词阶段不重新发散已经确认的商品、范围、结构和任务，只执行“编译 → 反证 → 最小修复”。

### 第七步：逐张分镜提示词

图组编排先列出每张的目标 SKU、唯一任务、参考资料使用、信息增量和前后承接。每张只解决一个主要买家问题；所有构图、人物、光影、文案和后期都服务该问题。

交互模式下，一次只展示当前一张完整确认卡。简单任务默认提供：

```text
0 采用 AI 首推并确认本张
1 确认本张并继续
2 定向返修本张
```

需要更多控制或出现复杂风险时，再展开 `0–9` 菜单和 `2-1` 至 `2-10` 的局部返修项。裸“继续/下一张”有歧义时，只询问是确认当前图还是预览下一张任务摘要，不静默改变状态。用户明确“确认本张，剩余自动完成”后，剩余图进入内部自动复核，但仍执行同样的事实、连续性和可执行性检查。

正式分镜每张使用稳定页码和对象编号，例如 `## 第1张（主图-01）：首屏商品识别`。模板字段为：

- 输出对象、成图任务、画布与布局。
- 参考图使用、商品锁定、允许变化、视角与事实边界。
- 最终画面、镜头与构图、场景与人物、光影材质与色彩。
- 最终文案（有真实文案时才写）、生产与后期。
- 中文正向图生图提示词、只针对本张风险的动态负面提示词。

`参考图使用`必须说明：AI 已分析全部有效参考视觉；本张实际向生成模型提供一张、多张或全部同款资料；各资料承担什么职责；冲突最终采用和舍弃什么。正式分镜不输出参考图索引，不把某一张图片永久绑定为商品身份，也不把其他 SKU 作为单 SKU 的生成身份输入。

正向提示词必须脱离商品卡和上一张独立执行，直接写出目标对象、实际参考输入、关键锁定特征、允许变化、视角边界和生产方式，不能写“以商品卡为准”“按前文”或“同上”。

### 第八步：可选生图

提示词全部交付且没有待确认分镜后，用户可以另行选择：

```text
暂不生图
生成主图-01和主图-03，每张 3 张
生成当前主图组，每张 2 张
生成全部图组，每张 1 张
```

这里的“每张”是候选图片数量，不改变分镜数量。默认不自动生图，也不在正式分镜同一份交付中追加菜单。

调用前先按工具能力画像适配：

- 不支持独立负面提示词时，等价并入同一次指令。
- 候选超上限时拆批，并保持分镜编号可追溯。
- 只支持单参考图时，优先使用同 SKU 真实商品层或无损参考画布；不能静默丢掉证据。
- 多 SKU 比较优先分层生成或真实商品层后期合成，防止融合串款。
- 不能可靠输出透明通道时，不用白底或棋盘格冒充透明成品。
- 需要改变交付语义、减少证据或降低保真时，先让用户确认。

生图结果按五个维度复核：事实保真、任务清晰、决策增益、生产完成度、平台可用性。只修最早失败层：商品事实回商品卡，任务回图组，工具问题回能力适配，表达问题回当前提示词。未经要求不会整组重生。

## 单参考图与多参考图

### 单参考图

先从一张图提取商品身份、可见几何、颜色、表面、文字、包装、配件和状态；未知面按隐藏视图规则单独处理。可以自由探索背景、场景和构图，但不能把品类常识补成未证实结构。

### 多参考图

先综合全部有效图，再为每张分镜选择真正需要的一张、多张或全部同款资料。清晰整体图约束比例，局部图补充细节，包装/参数图承担文字和到手内容，风格/竞品图只提供抽象视觉灵感。不同 SKU 默认只用于内部识别差异和形成禁区，不能传给单 SKU 生图模型。

最终分镜不出现参考图编号。内部可以临时编号用于纠错，但公开交付只描述“本张实际使用哪些类别的同款资料及其职责”。

## 图型能力库：从买家问题出发

图型库是发散入口，不是固定模板。当前能力覆盖：

| 类别 | 典型任务 |
|---|---|
| 商品标准呈现 | 一眼认出商品、包装和真实到手外观 |
| 结构拆解 | 看清内部层级、连接、装配和核心部件 |
| 细节质感 | 放大材质肌理、工艺、接口和做工 |
| 功能验证 | 把卖点转成工作状态、测试、前后效果或数据证据 |
| 参照认知 | 理解尺寸、容量、重量、空间和真人比例 |
| 选择适配与防错 | 区分 SKU、颜色、尺寸、接口、版本、套装和不适用边界 |
| 使用教学与维护 | 展示安装、操作、清洁、替换、收纳和安全步骤 |
| 场景呈现 | 在真实空间、人物动作和使用时刻中建立代入 |
| 创意视觉 | 用商品独有的形态、材质、原料或视觉隐喻形成记忆 |
| 组合、包装与到手 | 说明套装、配件、赠品条件、数量和包装层级 |
| 信任背书与来源 | 呈现真实资质、检测、授权、来源和服务边界 |
| 利益与行动 | 只在有当前资料时展示价格、优惠、权益和下一步入口 |
| 数字权益与服务交付 | 说明真实界面、发放/预约、激活、周期、权限和异常处理 |

每个候选都要回答：它解决哪个买家问题、需要什么证据、怎样画、怎样生产、增加了什么信息、有什么风险、缺资料时如何降级。已有类型不能覆盖关键问题时，AI可以建立商品专属图型，但仍必须通过证据、生产和新增价值检查。

## 各输出对象的职责

- **主图**：让用户停驻并在三秒内认出商品和一个核心利益；主体、品类和核心卖点优先。
- **SKU 图**：帮助选择和防错；每个 SKU 独立锁定，差异清楚，不把多个款融合成理想款。
- **详情页**：按最小充分决策链解释“为什么适合、依据是什么、怎么选/用、还有什么顾虑”。连续长画布仍按模块拆成不同任务。
- **海报**：一个明确主题、一个主要情绪、一个真实利益和一个行动方向；没有活动资料不编造促销。
- **白底图**：标准化、易审核、可复用的商品本体；不加入无依据道具和宣传文字。
- **透明图**：真实透明通道的可复用商品层；半透明、毛发、镂空、反射和独立阴影要明确生产职责。
- **无字场景图**：供后期排版的真实使用场景底图；不生成宣传标题、价格、参数和促销文字。
- **数字权益/服务**：优先使用真实界面、权益页、流程和授权资料，保护交付状态、有效期、权限、退款/取消/续费和隐私；不把非实体权益画成会收到的实体商品。

## 子智能体与自我学习

复杂、多 SKU、高风险或用户明确要求时，才按问题增配最少角色：商品识别与证据、预构建与需求、范围与结构、图组策略、视觉与提示词、结构与生产、类目合规、独立审查。每个角色只回答一个问题，返回结论、证据摘要、假设、风险和建议；主控按证据合并，不用多数票替代直接证据，也不向用户另交角色报告。

学习只在用户授权和可追溯范围内发生：记录选择、否定、纠正、有效返修、已评价生图结果和明确归因的业务反馈。一次沉默接受、候选数量、随机差异、工具失败或无归因的指标波动不会自动成为偏好。偏好只能影响后续排序和表达，不能覆盖商品事实、安全边界或本轮明确要求；可以降低可信度、缩小范围或撤销。

## 最终分镜提示词示例

下面是正式交付的形态。示例只展示分镜，不附内部菜单、分数或过程；实际任务中的商品特征必须来自已确认资料。

````markdown

- 输出对象：【主图】
- 成图任务：【让用户第一眼认出蓝色保温杯，并理解它是当前售卖主体】
- 画布与布局：【竖版 3:4；商品位于左侧偏中，主体约占画面高度三分之二；右侧保留低细节排版区，完整露出杯身与杯盖】
- 参考图使用：【已分析全部有效参考视觉；本张实际向生成模型提供当前目标 SKU 的全部同款资料，综合杯身轮廓、杯盖连接、蓝色外观、正面几何、真实反射和可见品牌原文；其他 SKU 不作为单 SKU 生成输入；同款资料一致】
- 商品锁定：【保持杯身轮廓、杯盖连接关系、蓝色外观、部件数量、真实表面反射和可见品牌原文】
- 允许变化：【自由探索简洁浅灰背景、自然台面、柔和接触阴影、轻微空间层次和右侧低细节留白；成功标准是缩略图下仍能立即识别商品】
- 视角与事实边界：【使用参考资料能够证明的正面范围；不新增未提供依据的背面、底部、内部、接口或配件】
- 最终画面：【单个蓝色保温杯完整放置在简洁台面上，商品是唯一视觉焦点，右侧留出后期排版区域】
- 镜头与构图：【平视略俯视中近景，自然透视，焦点落在杯身与杯盖连接处，背景浅景深但不损失轮廓】
- 光影、材质与色彩：【柔和左上方主光，保留真实蓝色色相、自然高光和接触阴影，背景低饱和浅灰】
- 生产与后期：【图像模型负责背景、光影和空间层次；真实商品层负责杯身、杯盖、品牌原文与边缘；短文案由后期排版】

- 🎨 图生图提示词：
```text

```
````

## 返修方法

用稳定对象编号点名，并说明保留项与修改项：

```text
返修详情页-03。
保留：商品、SKU、参考资料使用方式、唯一任务和机位。
修改：手部接触、接触阴影和主体占比。
不要修改：容量、品牌原文和其他分镜。
交付：完整重发这一张分镜，暂不生图。
```

如果修改涉及商品身份、SKU、参数、适配或品牌原文，先回商品卡纠正，再重新确认受影响的图；普通构图或表达问题只重算当前分镜字段。共享事实变化时，技能会标出受影响的相邻分镜，不会静默改写无关画面。

## 常见问题

### 只有正面图，可以做背面吗？

可以先对真实存在的背面单独计算还原分数。严格高于 80 分且任务相关时，技能会推送序列号确认卡；你确认序列号后才进入写实分镜。80 分及以下改用补拍、合成、三维资料或概念稿。确认后的正式分镜不显示分数或推断标签。确认只授权该画面目标，不证明隐藏结构之外的性能、功效或安全事实。

### 多张参考图会全部传给生图模型吗？

不会机械全传。AI 先分析全部有效视觉，再按当前分镜选择一张、多张或全部同款资料。风格图和竞品图只提取抽象视觉原则；其他 SKU 默认不作为单 SKU 生成输入。冲突会在分镜中写出具体采用和舍弃结果。

### 为什么正式分镜没有参考图编号？

内部可以临时编号帮助纠错，但固定编号会把提示词绑定到某次上传顺序，也容易让生图模型误解职责。正式分镜只写本张实际使用的资料类别、互补内容和裁决结果，保证单张可执行。

### 图型库会不会限制 AI？

不会。图型库是发现入口，不是上限。AI 先从买家问题和证据出发匹配已有类型，再主动补充商品专属画法；新画法必须有新增决策价值、可靠证据和生产路径。

### 为什么不固定输出五个方向？

固定数量会让简单任务产生无价值停顿和伪差异。简单任务通常只保留首推，中等任务比较 1–3 个，复杂任务最多比较 5 个；五类方向只是探索入口，不是每次必须展示的方案。

### 用户说“直接出”会跳过确认吗？

单一清晰目标且无关键冲突时，明确直出授权可以把待确认商品卡视为确认；多 SKU、相似款、主体/SKU/状态不确定或高风险事实未证实时，仍必须让用户确认商品卡。直出不会自动确认隐藏视图，也不会授权生图。

### 能不能只要提示词，不要报告？

可以。对话中的商品卡和确认卡只用于收敛事实与范围；最终正式交付只保留逐张中文分镜提示词，不附运营、营销、产品或审美报告。

### 成品、分镜和生图数量有什么区别？

`成品数量`是最终文件或长画布数量；`分镜/模块数量`是需要解决的不同任务和提示词条数；`每分镜候选数量`是提示词交付后实际生成的候选图数量。例如：`详情页成品 1 张 + 内部 5 个模块/分镜 + 每模块 3 个候选`。三种数量不会互相替代。

### “详情页 1 张”怎么处理？

先确认“1”指一张连续长画布、一个模块还是一组页面。若是长画布，写成“成品 1 张 + 内部若干模块/分镜”，每个模块解决一个问题并说明合成顺序；不按通用习惯默认 8、10 或 12 个模块。

### 数字权益或服务商品怎样处理？

需要真实界面、权益页、流程、授权页或已授权场景。SKU 解释为档位、版本、时长、地区、账号范围或服务包；重点保护交付、激活、有效期、权限、退款/取消/续费和异常边界。不启用物理背面/底部/内部评分，也不把权益画成会收到的实体卡或快递。

### 没有卖点和参数怎么办？

AI 会列出候选卖点和需要补充的字段，供你数字选择或手动纠正。未确认、无证据或高风险内容不会进入正式文案和提示词；缺资料的任务会删除主张或降级为可观察表达。

### 可以在提示词后生图吗？

可以。先完整交付提示词，再指定分镜、图组和每张候选数量。默认不自动生图；工具能力不足时会明确说明降级，不静默减少参考证据或改变交付含义。

### 个人信息或真实界面怎么保护？

姓名、头像、账号、联系方式、地址、订单号、设备号、车牌、可用二维码和其他敏感信息默认遮盖、裁切或替换；只有你明确确认有权公开且画面确实需要时才保留。真实 UI、订单、授权文件和长文字优先使用证据像素或后期排版，不让图像模型重绘。

### 没有任何可查看的参考图怎么办？

技能会停止图生图流程，只请求最小必要视觉资料，不会用纯文本猜测替代看图。收到可访问参考视觉后，再从第一步开始。

## 版本交付说明

本仓库的核心原则是“证据先于想象，目标先于图型，新增价值先于凑数，生产能力先于漂亮承诺”。后续修改应保持：

1. 正式交付仍然只有中文图生图分镜提示词。
2. 单参考图和多参考图都先完整分析，再按当前分镜选择实际输入。
3. 隐藏视图逐目标、严格高于 80 分、用户序列号确认；正式分镜不泄露内部标签。
4. 综合方向自适应，最多 5 个，不强制凑满。
5. 用户反馈只在授权、可追溯、可撤销的范围内影响后续首推，不改变事实和安全边界。
