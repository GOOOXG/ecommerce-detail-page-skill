# 商品图深度推演与图生图分镜技能

这是一个专门为“商品参考图 → 应该做哪些图 → 逐张图生图分镜提示词”构建的 Codex 技能。

它不会交付独立的商业咨询、运营报告、营销方案、产品经理分析或美学报告。商业、运营、消费者、产品、营销与视觉专业只在后台参与推演，最终服务于唯一核心产物：可直接交给图生图模型和后期团队的逐张中文 Markdown 分镜提示词。

正式分镜提示词始终是核心交付。全部提示词发布后，用户可选择不生图、生成指定分镜、当前图组或全部图组，并为每张设置候选图片数量；只有当前环境提供可用生图工具时才会实际生成，默认不自动生成，也不扩展到投放或其他交付。

## 核心能力

- 给原始商品附件建立永久稳定的参考图编号与附件索引。
- 识别商品身份、SKU/状态、视觉 DNA、可见面和事实边界。
- 用 P0–P4 做总体能力摘要，并按身份、几何、材质、颜色、文字、包装配件、交互尺度、证据、新外部视角、内部拆解、材质贴图和动态状态逐轴放行。
- 从买家任务、选型、防退货、场景、证据、平台与素材能力反推最小充分图组。
- 支持主图、SKU 图、海报、白底/透明/无字场景素材图和详情页。
- 支持递进式主次、等量并列、混合结构与单张闭环。
- 固定推演 5 个产品专属综合方向：3 个稳妥方向、2 个差异方向。
- 复杂或高风险任务可使用版本化工作包，分工完成商品图法证、需求与图组、转化产品思维、视觉导演、生产监制、提示词编译、独立上下文审查、事实红队、生图审计、失败诊断、偏好捕获与进化仲裁；简单任务由主控直接完成，不强制并发。
- 使用“循环 + 提示词编译器”反复执行草拟、批判、修复/上报和发布。
- 通过进化记忆学习用户的选图、图组、卖点顺序、场景、构图、审美、保真、提示词颗粒度与协作节奏。
- 支持根据用户提供的外部生成结果定位失败层，并只修订受影响的分镜提示词。
- 提示词交付后提供显式可选生图闸门，支持按分镜设置候选数量与结果追溯；本技能不保证当前环境已安装或开放生图工具。

## 现代架构

全技能使用统一结构：

`状态 → 合同 → 循环 → 工作包 → 提示词编译器 → 发布闸门 → 生图闸门 → 追溯记录 → 进化记忆`

- 状态：当前可计算状态。
- 合同：商品、参考图、范围、结构、方向、分镜与提示词的版本化约束；统一携带标识、类型、版本、状态、负责人、父版本和来源追溯记录。
- 循环：草拟 → 批判 → 修复/上报 → 发布。
- 工作包：主控与专业子智能体之间的最小结构化交接。
- 提示词编译器：把已发布合同编译成单义、可执行的图生图提示词。
- 发布闸门：真实性、事实、参考能力、图组、视觉、生产与格式放行。
- 生图闸门：提示词发布后的可选生图范围、候选数量与结果诊断。
- 追溯记录：参考图来源、合同版本、提示词版本与返修补丁的来源链。
- 进化记忆：带证据、范围、冲突、衰减和撤销能力的分镜偏好记忆。

合同依赖固定为：`任务（TC） → 商品（PC） → 参考图（RC） → 范围（SC） → 结构（ST） → 方向（DC） → 分镜槽位（FS） → 分镜发布（FR）+ 提示词发布（PR） → 进化记忆`。分镜槽位通过发布闸门后，才物化绑定当前上游及 FS 版本的不可变分镜草案产物；它不是合同、不进入发布库，也不会造成“必须先发布分镜才能编译提示词”的循环依赖。

合同版本使用独立前缀：`TC-nnn / PC-nnn / RC-nnn / SC-nnn / ST-nnn / DC-nnn / FS-nnn / FR-nnn / PR-nnn`。`P0-P4`只表示参考图能力，`Q0-Q3`只表示发布问题严重度，`E0-E3`只表示偏好证据。提示词内部闸门通过后，分镜与提示词以相同`release_pair`和分镜草案`source_artifact_id`同时进入`PENDING`；用户确认或自动内审通过时，两者才原子进入`RELEASED`并写入发布库。最终闸门逐项核对当前版本、状态、`parent_versions`、来源草案的`input_contract_versions`和 FR/PR 配对。

## 最小相关加载

- 运行时只加载能直接改变当前范围、结构、方向、分镜、提示词或生图字段，或解除商品事实阻塞的文件。
- 商业、运营、营销、产品和美学模块只有在结论能转译为“做什么图、为什么、怎样画”时才读取；不能映射到分镜字段就不加载。
- 路由模块只选择当前问题命中的最少子文件，不因目录存在或角色知识面广而预读整套资料。
- `ecommerce-detail-page/references/test-scenarios.md`仅用于维护与回归验证，正常分镜任务不读取；README中的安装和使用教程也不进入运行时推演。

## 分镜控制面

- 分镜任务解读：先把任务读成“对象/平台 + 买家决策 + 商品事实/证据 + 参考能力 + 主视觉语法”，避免直接套模板。
- 推演旋钮：内部推断保真严格度、证据严格度、视觉差异、信息密度、场景真实度、转化直接度和文案密度；不要求用户填写，不把分数写进分镜。
- 反套路边界：主动排除无依据的紫蓝/黑金/米黄套壳、万能圆台、粒子水花、随机人物、伪实验室、重复居中构图和伪剖面；只有品牌、任务、证据与生产共同支持时才能覆盖。
- 分镜槽位合同：先确定画布状态、产品锚点/占比/裁切、文案/品牌/证据安全区，再编译提示词；比例或尺寸未知时只删除相应子项，不能删除整个槽位。
- Q0-Q3 发布严重度：Q0/Q1阻塞，影响任务或执行的Q2必须修复，Q3只做不改变合同的润色；P0-P4仍只表示参考图能力。

## 固定主链

新商品必须按以下顺序运行：

1. 建立并确认商品卡。
2. 确认真实输出对象、组合、数量和用途。
3. 多图确认递进、并列或混合结构。
4. 固定推演 5 个综合方向。
5. 编排图组与每张唯一任务。
6. 逐图确认，或在全自动/直出模式内部逐图放行。
7. 关键节点提供 `0–9` 动态动作。
8. 无损聚合全部已发布提示词，输出正式 Markdown 分镜。
9. 提示词交付后按用户选择进入生图闸门，或直接结束。

全自动与直出只改变闸门是否对用户显示，不允许跳过商品、范围、结构、5 个方向和逐图发布。

## 商品参考图与保真

### 稳定索引

所有原始附件先按到达顺序编号，再去重和筛选：`参考图1`、`参考图2`……。重复图、排除图或后续被替换的图片保留原编号；新图片只追加，永不复用旧编号。

每组最终分镜先列出：

`参考图编号 → 附件名或上传轮次+原始序号 → SKU/状态 → 角色`

### 商品视觉 DNA

视觉 DNA 覆盖：轮廓、结构、比例、可观察材质表面、颜色、品牌文字、包装配件和缺失视角。每个锚点记录来源参考图、局部区域、可信度与冲突状态。

不同 SKU、颜色、型号、开合、装配和包装版本使用：

`shared_dna + sku_state_delta`

### 参考图角色

- 身份母图：固定商品/SKU 身份。
- 视角/几何主参考图：定义当前图的机位和可见结构。
- 辅参考图：只补材质、颜色、文字、包装、配件、交互或证据等声明能力轴。

辅图不能覆盖身份母图定义的 SKU，也不能借不同 SKU 图片篡改结构、颜色或包装。

### 未知面与精确文字

- 只有正面图时，不能生成真实背面、底部、内部或拆解。
- 多角度照片不等于准确 3D 几何，也不证明内部结构。
- 复杂 LOGO、型号和包装文字优先保留真实商品像素层或后期合成。
- 图像模型主要生成背景、空间、人物、道具、光影、阴影和文字安全区。

## 循环 + 提示词

每个关键节点统一执行：

`INPUT → DRAFT → CRITIQUE → REPAIR / ESCALATE → RELEASE`

每张提示词固定运行：

1. 提示词草拟：装配参考图、商品锁定、允许变化、最终画面、镜头、场景、光影、文字安全区和动态负面约束。
2. 提示词批判：检查商品漂移、未知面、文字重绘、物理错误、指令冲突和内部术语泄漏。
3. 提示词修复：只修失败层；上游出错则回到对应合同负责人。
4. 提示词发布：删除候选、空字段、括号、流程词和解释，生成同一`release_pair`的`分镜：PENDING + 提示词：PENDING`；确认后原子发布，只保留正式生产指令。

循环记录不进入最终源码块，提示词编译器不能补充未确认事实。

## 多智能体分工

- 商品图法证：参考图索引、视觉 DNA、能力轴、冲突与可靠生产范围。
- 事实与合规红队：删除无依据主张、危险画面和授权风险。
- 需求与图组策略：决定该做哪些图、每张解决什么、不做的代价。
- 电商转化与产品思维：审查理解、选型、信任、误点、退货与任务增量。
- 视觉导演：场景、人物、镜头、构图、光影、色彩和组内连续性。
- 图生图生产监制：锁定层、重建层、生成层与后期职责。
- 提示词编译：把已裁决工作包编译为正式提示词。
- 提示词对抗审查：只读取产物与合同，证伪歧义、越界、槽位冲突和不可执行要求。
- 生图结果审计：对比实际图片、参考图、分镜合同和提示词版本，区分随机候选差异与可重复失败。
- 提示词失败诊断：定位最早失败层并生成最小补丁。
- 个人偏好捕获：从用户原话、选择、否定与返修形成偏好事件。
- 进化仲裁：用对比归因裁决范围、证据、冲突、衰减和是否进入`preference_profile`偏好配置。

只有主控可以确认核心合同、解释菜单、裁决冲突和交付最终分镜。子智能体不能各自向用户交付报告。

## 进化记忆

学习范围包括：当前图、当前任务、当前图组、当前商品/SKU、品牌/系列、类目、平台×输出对象、用户通用。默认只在当前会话捕获和应用；跨任务、项目级或长期持久化必须先获得用户明确授权。

证据等级：

- E0：AI 推断，不进入长期首推。
- E1：本轮选择，只影响窄范围。
- E2：至少两个独立任务重复确认，可稳定应用。
- E3：用户明确长期规则。

每条记忆记录保存规则、正向/否定/例外、范围、置信、来源追溯、提示词目标、冲突、覆盖、衰减和状态。用户可以查看、撤销或声明“这次例外”。未经持久化授权的记录不会写入跨任务记忆；历史记忆不能覆盖新商品事实，也不能绕过本轮商品卡。

## 最终分镜字段

每组先写参考图索引。每张正式分镜包含：

- 输出对象
- 成图任务
- 图组角色
- 画布与槽位（每张必有产品锚点/占比/裁切与实际信息安全区；比例/尺寸仅在已确认时写）
- 身份母图
- 主参考图
- 辅参考图
- 产品锁定
- 允许变化
- 视角与事实边界
- 最终画面
- 镜头与构图
- 场景与人物
- 光影、材质与色彩
- 最终上图文案
- 生产与后期
- 图生图提示词
- 动态负面提示词

最终源码块不包含模型名、评分、策略报告、多智能体意见、测试标签、确认状态或循环日志。

## 可选生图

正式分镜提示词交付后提供以下选择；实际生成要求当前环境存在可用图片生成工具，否则只保留已交付提示词并返回明确的执行环境失败状态：

- 暂不生图。
- 生成指定分镜。
- 生成当前图组全部分镜。
- 生成全部图组。
- 为每张分镜分别设置候选图片数量。

每个候选绑定 `storyboard_id + frame_release_version + prompt_release_version + release_pair + source_artifact_id + render_variant`；执行前必须确认 FR/PR 属于同一当前原子发布对，且共同指向未陈旧的分镜草案。生图结果不会直接覆盖正式提示词；若发现商品漂移、结构变形、文字错误、人物物理问题或指令冲突，先定位最早失败层，创建最小提示词补丁。即使只修改提示词，也会复制未改变的分镜正文并创建新的原子 FR/PR 配对；只有用户明确要求时才重生受影响分镜。用户对候选图的明确选择或否定会先增量合并到本轮学习快照，再在暂不生图或生图终态后完成最终学习封包。

生图状态覆盖`NOT_OFFERED / OFFERED / CONFIGURED / GENERATING / REVIEWED / ACCEPTED / PATCH_REQUIRED / FAILED / INVALIDATED / CANCELLED`。提示词或分镜版本更新会使绑定旧版本、尚未进入`ACCEPTED/CANCELLED`终态的请求转为`INVALIDATED`；历史终态只保留追溯记录。选择暂不生图进入`CANCELLED`。正式提示词交付后停止通用`0–9`菜单，只保留上述生图选择。

## 安装

### 1. 克隆仓库

```powershell
git clone https://github.com/GOOOXG/ecommerce-detail-page-skill.git
Set-Location .\ecommerce-detail-page-skill
```

### 2. 安装技能

把仓库中的 `ecommerce-detail-page` 文件夹安装到 Codex skills 目录。下面的命令会先把同名旧版本移动到 `skill-backups`，不会修改项目目录中的分镜偏好文件：

```powershell
$codexHome = if ($env:CODEX_HOME) { $env:CODEX_HOME } else { Join-Path $env:USERPROFILE '.codex' }
$skillsDir = Join-Path $codexHome 'skills'
$source = Join-Path (Get-Location).Path 'ecommerce-detail-page'
$target = Join-Path $skillsDir 'ecommerce-detail-page'

if (-not (Test-Path -LiteralPath $source -PathType Container)) {
    throw "未找到技能目录：$source"
}
New-Item -ItemType Directory -Force -Path $skillsDir | Out-Null
if (Test-Path -LiteralPath $target) {
    $backupRoot = Join-Path $codexHome 'skill-backups'
    $backupName = 'ecommerce-detail-page-' + (Get-Date -Format 'yyyyMMdd-HHmmss-fff')
    $backup = Join-Path $backupRoot $backupName
    New-Item -ItemType Directory -Force -Path $backupRoot | Out-Null
    Move-Item -LiteralPath $target -Destination $backup
    Write-Host "旧版本已备份到：$backup"
}
Copy-Item -Recurse -Force -LiteralPath $source -Destination $target
```

安装后重新打开 Codex 或新建任务，让技能目录重新扫描。更新时先在仓库执行 `git pull --ff-only`，再重新运行安装命令。

## 完整使用教程

### 1. 使用前准备

至少提供一张能够确认商品身份的清晰参考图。资料越完整，商品保真、图组逻辑和提示词可执行性越高。

| 资料 | 建议内容 | 作用 |
|---|---|---|
| 商品参考图 | 正面、侧面、背面、细节、包装、配件、不同SKU或开合状态 | 锁定商品身份、结构、材质、颜色、文字和可用视角 |
| 商品事实 | 名称、品牌、型号、尺寸、材质、成分、功能、适配关系 | 决定哪些卖点和画面可以安全使用 |
| 输出要求 | 主图、SKU图、详情页、海报或产品素材图，以及数量、平台和用途 | 确定真实交付范围和每张图的职责 |
| 视觉约束 | 品牌色、参考风格、人物要求、构图、画布、禁止元素 | 控制整组视觉语言与生产边界 |
| 业务事实 | 真实价格、活动、赠品、认证、检测、售后或授权 | 只有存在可靠依据时才进入文案和证据画面 |

不知道的字段直接省略或标记“未知”，不要为了让资料看起来完整而猜测。精确长文字、参数表、LOGO和包装原文优先交给真实商品层或后期排版。

### 2. 最快开始

上传商品图后，直接输入：

```text
使用 $ecommerce-detail-page，根据这些商品参考图，先识别商品并确认资料，再推演应该制作的图片，最终输出逐张中文图生图分镜提示词。暂不生图。
```

技能会先确认商品事实，再确认输出对象、图组结构和综合方向，不会直接套用固定电商模板。

### 3. 完整任务模板

需要精确控制任务时，按下面的模板填写；没有的信息删除对应行：

```text
使用 $ecommerce-detail-page。

商品名称：【名称】
商品与SKU：【单品 / 多SKU关系 / 套装关系】
参考图说明：【每张图对应的SKU、角度、状态或用途】
输出对象：【主图 / SKU图 / 详情页 / 海报 / 白底图 / 透明图 / 无字场景图】
数量：【按对象分别填写】
平台与位置：【淘宝 / 天猫 / 京东 / 拼多多 / 抖音 / 小红书 / 亚马逊 / 独立站等】
画布要求：【比例、像素、横竖版；未知则删除】
已确认事实：【材质、尺寸、功能、适配、认证等】
核心卖点：【只写有依据的卖点】
必须保持：【结构、比例、颜色、材质、LOGO、包装原文、配件等】
允许变化：【背景、人物、道具、光影、摆放、留白等】
禁止内容：【未知背面、虚构内部、夸张效果、错误文字等】
协作方式：【智能推荐 / 逐图确认 / 半自动 / 全自动 / 直出 / 深度 / 脑暴】
提示词交付后：【暂不生图 / 指定分镜生图 / 全部生图，每张N个候选】
```

### 4. 选择协作模式

| 模式 | 可直接使用的说法 | 实际行为 |
|---|---|---|
| 智能推荐 | “先推荐让我选” | 默认模式；确认商品、范围、结构和综合方向，再逐张设计 |
| 逐图确认 | “一张一张确认” | 每次完整展示一张单图卡，确认或返修后才进入下一张 |
| 半自动 | “关键步骤让我确认” | 保留核心选择，但把零散问题合并，减少对话轮次 |
| 全自动 | “你直接完成，遇到硬冲突再问” | 商品真实性确认后自主完成其余推演和内部放行 |
| 直出 | “只要最终提示词，不要过程说明” | 内部仍完成必要检查，外部只交付正式分镜；硬性冲突仍会询问 |
| 通版 | “先做快速通版” | 快速形成可执行样板，不主动扩展精细参数和大量方向 |
| 深度 | “完整深度推演” | 提高商品法证、证据、场景、视觉和生产审查深度 |
| 脑暴 | “先给更多方向” | 扩展候选并收敛，未确认的候选不会进入最终分镜 |
| 返修 | “只改第2张” | 定位最早失败层，只重算受影响分镜和必要依赖 |

用户没有指定模式时使用“智能推荐”。“全自动”和“直出”只减少可见确认，不会跳过商品真实性、图组结构、5个综合方向和逐图质量检查。

### 5. 一次完整任务的流程

1. **参考图建档**：系统按上传顺序建立稳定编号，区分身份母图、角度图、细节图、包装图和SKU图。后续新增图片只追加编号。
2. **商品卡确认**：系统列出已确认事实、可见特征、冲突和高价值补充项。信息正确时回复“确认商品卡”；有错误时直接指出“哪一张图、哪个字段、正确值是什么”。
3. **输出范围确认**：系统根据商品和买家任务展示主图、SKU图、详情页、海报和产品素材图的需求地图。选择实际需要的对象、数量、平台和用途即可，不会静默扩大范围。
4. **图组结构选择**：多图任务选择递进式主次、等量并列或混合结构；不确定时回复“采用推荐”。单张任务自动使用单张闭环。
5. **综合方向选择**：系统固定推演5个产品专属方向。可选单一方向，也可说“以方向1为主，采用方向4的视觉”，系统会检查组合冲突后再发布。
6. **逐张设计与确认**：逐图模式下，每张都会给出任务、参考图、商品锁定、场景、构图、人物、光影、文案、生产方式、正向提示词和动态负面提示词。回复“确认本张并继续”，或直接说明需要修改的字段。
7. **正式分镜交付**：全部图片放行后，系统按真实编号聚合为正式中文Markdown分镜。最终结果只保留生产所需字段，不附带内部评分、角色讨论或隐藏思考链。
8. **可选生图**：正式提示词全部交付后，才选择是否调用当前环境的生图工具；默认不会自动生图。

### 6. 如何回复选择和菜单

自然语言始终优先，不必记忆编号。数字只绑定最近一次屏幕上可见的菜单，进入下一阶段后旧编号立即失效。

| 常见编号 | 通常表示 | 使用提醒 |
|---|---|---|
| `0` | 采用AI当前首推 | 存在商品或合规阻塞时，会改为优先解除阻塞 |
| `1` | 确认当前节点并继续 | 单图阶段只确认当前一张，不会确认整组 |
| `2` | 优化或返修当前内容 | 单图阶段可继续选择具体返修字段 |
| `3` | 返回上一环节 | 系统会先说明可能受影响的后续内容 |
| `4` | 商品资料 | 新增、纠正、删除事实或补充参考图 |
| `5` | 输出控制 | 调整对象、数量、顺序、平台、画布或范围 |
| `6` | 营销与文案 | 调整人群、卖点、证据、购买阻力或文案 |
| `7` | 视觉设计 | 调整风格、场景、人物、视角、构图、光影或生产方式 |
| `8` | 后续与模式 | 预览下一张、切换逐图/自动或让剩余图片自动完成 |
| `9` | 自定义 | 直接说明要保留、删除、替换、补充或重做什么 |

常用回复：

- `继续`：推进当前合法步骤；有待确认单图时只确认当前图。
- `采用推荐`：采用当前结构或综合方向的首推，不代表扩大输出范围。
- `确认本张，剩余自动完成`：发布当前图，并让剩余图片转为自动内审。
- `返回结构选择`：回到图组结构，并先检查哪些已设计内容会失效。
- `第2张保留商品和构图，只改人物动作`：进行定向返修，不重做整组。

### 7. 常用任务示例

**主图组：**

```text
使用 $ecommerce-detail-page，根据已上传商品图制作主图10张，用于天猫搜索和详情入口。采用逐图确认；每张解决不同购买问题，商品结构、颜色、LOGO和包装原文不得改变。最终只交付逐张图生图分镜提示词，暂不生图。
```

**多SKU详情页：**

```text
使用 $ecommerce-detail-page，为这组多SKU商品制作详情页。先确认每张参考图对应的型号和颜色，再推演递进式详情结构；不要编造尺寸、适配和效果。逐张确认并输出完整中文分镜提示词。
```

**白底、透明和无字场景素材：**

```text
使用 $ecommerce-detail-page，基于商品参考图生成白底图2张、透明图1张、无字场景素材图3张的分镜提示词。所有图片保留商品原有文字，不新增广告文案；采用全自动，提示词完成后暂不生图。
```

**直出最终提示词：**

```text
使用 $ecommerce-detail-page。商品资料和参考图关系已确认准确，请采用直出模式完成主图6张；内部完成5个方向比较和逐图检查，外部只输出最终Markdown分镜提示词，不生成图片。
```

**分析外部生成结果并返修：**

```text
这是“主图-02”按当前提示词生成的结果。商品主体正确，但手指接触、接触阴影和握持尺度错误。保留商品、背景、机位、留白和文案安全区，只修人物物理关系与相关正负提示词；先重发本张分镜，暂不重新生图。
```

### 8. 提示词交付后选择是否生图

正式分镜全部交付后，可以直接回复：

0. `暂不生图`：保留提示词并结束。
1. `生成指定分镜`：例如“生成主图-01和主图-03，每张3个候选”。
2. `生成当前图组全部`：例如“当前主图组每张2个候选”。
3. `生成全部图组`：例如“全部图组每张1个候选”。
4. `自定义数量`：为不同分镜分别指定候选数。

实际生图要求当前环境已经提供可用的图片生成工具。没有工具、配额不足或生成失败时，已交付的提示词仍然有效；系统不会伪造图片，也不会把工具故障误判为提示词错误。

### 9. 返修与重新生图

返修时同时说明“目标分镜、保留项、修改项、禁止联动项、是否重新生图”，最容易得到稳定结果：

```text
返修【详情页-04】。
保留：商品、主参考图、页面任务、背景色和上下页衔接。
修改：主体占比从45%提高到60%，缩短标题，强化材质近景和接触阴影。
禁止：不要改变SKU、机位和原有LOGO。
交付：只重发第4张分镜和提示词；确认后重新生成2个候选。
```

系统会先判断问题来自商品识别、参考图、图组任务、场景构图、人物物理、提示词冲突还是生成工具，再做最小修改。仅修改提示词不会默认重跑整组；需要重新生图时必须明确说出目标和候选数量。

### 10. 让技能学习长期偏好

当前任务中的选择、否定和有效返修会用于本轮后续首推。只有明确授权时，技能才会把偏好写入项目根目录的 `ecommerce-storyboard-memory.md`。

```text
记住：以后为本品牌制作主图时，优先真实使用场景和大比例商品，不使用悬浮圆台。适用范围：本品牌所有主图。请持久化保存。
```

管理偏好时可以说：

- `查看分镜偏好`：按适用范围查看紧凑摘要、证据等级和冲突。
- `撤销偏好：本品牌主图不使用悬浮圆台`：停止使用对应规则并保留撤销记录。
- `这条只适用于当前SKU`：限制范围，避免错误泛化到其他商品。

候选图片数量、工具故障、未评价结果和随机差异不会被学习；偏好也不能覆盖真实商品事实、合规边界或本轮明确要求。

### 11. 常见问题

**只有一张商品图能否使用？**

可以，但只允许使用该图能够证明的角度、结构和状态。未知背面、内部、配件或开合状态不会被补画成事实。

**没有完整参数怎么办？**

先确认已知商品卡。缺失参数对应的卖点、对比、适配和证据组件会被删除或降级，不会用行业常识冒充商品事实。

**为什么精确文字被安排到后期？**

图像模型容易改错LOGO、包装原文、长文案和参数表。技能优先保护真实商品层，并把精确排版交给后期，以提高商用可靠性。

**多个SKU怎样避免串款？**

上传时明确每张图对应的型号、颜色、套装和状态。技能会分别绑定身份母图与主参考图；存在冲突时先停止设计并重新确认SKU关系。

**能否只返修一张？**

可以。使用最终分镜真实编号并说明保留项和修改项。只有共享结构、方向或商品事实被改变时，系统才会标记其他受影响分镜。

**没有生图工具怎么办？**

直接选择“暂不生图”，把正式提示词交给支持参考图的外部图生图模型。核心交付始终是分镜提示词，不依赖当前环境必须能够生图。

**任务暂停后怎样继续？**

在同一任务中回复“继续当前分镜”或点名待确认编号。系统会从当前图和已发布内容继续，不会从第1张重新推演。
