# 商品与参考图判断

只回答三个问题：核心售卖对象是什么，哪些参考视觉能证明什么，哪些画面能够真实制作。必须实际查看每份可访问参考视觉；低清、严重遮挡、损坏或无法读取的内容不能作为事实依据。实体商品可用实拍、包装、结构图和可靠三维资料；数字权益或服务可用真实界面、权益页、流程截图、授权页、已授权服务场景和品牌视觉。完全没有可访问参考视觉时停止本图生图技能并只请求最小必要素材，不进入与下游模板不兼容的纯文本概念稿旁路。

## 内部证据追踪

1. 可以按附件到达顺序在内部临时编号，用于识别错误纠正、冲突定位和用户指代；编号不进入正式分镜。
2. 为每张图片记录可见附件名、上传轮次或原始顺序。不要猜测缺失信息。
3. 保留重复图、排除图和被替换图的内部位置，新图只追加，避免纠错时指向错误图片。
4. 同时记录每份视觉对应的商品形态、核心对象、SKU或权益版本、颜色/型号/容量或档位/时长/地区/账号类型、状态、包装或交付版本、配件或权益组合，以及拍摄视角或界面/流程状态。无法确认时明确写“未知”，不要强行归组。
5. 正式分镜不输出参考图索引或固定参考图编号，只说明当前画面怎样综合使用一张、多张或全部有效参考图。

## 锁定商品、SKU与状态

1. 先判断商品形态是实体、数字权益还是服务，再识别品类、名称、品牌、型号或版本、数量或权益、组合关系和可见用途，区分不同SKU、权益档位、服务版本与状态。
2. 实体商品分别核对颜色、容量、尺寸、包装、配件、开合、安装和使用状态；非实体商品分别核对档位、时长、地区、账号/设备范围、交付、激活/预约、有效期、续费、退款/取消和服务状态。不要把多个版本平均成一个虚构对象。
3. 每张待制作图片只指定一个目标SKU/版本与状态。总览可以并列展示多个真实选项，但不能融合实体部件，也不能混合不同权益、界面功能、交付条件或服务承诺。
4. 用户指定SKU后，把其他SKU视为防串款反例；只有确认结构和材质完全相同时，才允许借用相应局部依据。
5. 图片与文字在型号、数量、套装、适配或关键规格上冲突，且可能导致买错时，停止下游设计，只问一个能够解除冲突的问题。

## 提取可见商品特征

从有效参考图中提取可复核的共享特征，并为每个SKU或状态记录差异：

- 实体商品锁定轮廓、长宽高关系、重心、部件数量、连接方式和可见几何；数字权益或服务锁定真实界面结构、权益层级、流程顺序、交付状态和品牌视觉边界。
- 锁定可观察的表面表现，如哑光、高光、透明、半透明、金属反射、织物纹理或细粗纹；没有资料时不要把表面观感升级为具体材质名称。
- 锁定主体色、辅色、透明区、金属色、不可改色区域和可能受白平衡影响的颜色。
- 锁定品牌标志、型号或版本、包装/界面/权益原文、标签位置、真实配件或权益和数量关系。
- 记录能可靠判断的尺度、握持、穿戴、安装和接触关系；没有比例依据时不要制造精确尺寸感。

为每个锚点指出来源参考图和具体区域，并标记可信程度与冲突。优先保留多图一致且清晰的特征；不要用行业常识补齐图片没有展示的结构。

## 综合全部有效参考图

先完整读取所有有效参考视觉，再为每个SKU/版本/状态建立统一证据集合：

- 汇总多图一致的商品身份、轮廓、结构、颜色、可观察表面、文字、包装、配件、尺度和状态。
- 把清晰局部用于补充细节，把完整视角用于约束整体几何；局部证据不得改写整体比例或SKU。
- 把场景图中的空间、光线、人物和氛围作为视觉候选，不让它覆盖真实商品外观、真实界面、权益原文或服务边界。
- 把低清、严重遮挡、错误SKU、失真、重复或来源不明的图片标为排除证据，并记录原因。
- 先从全部图片深度提炼可证实卖点、购买顾虑、使用情境和文案方向，再把缺少参数、功效或认证依据的表达列为待补证，不能直接采用。

推理阶段必须先分析全部有效参考视觉，但“分析范围”不等于“向生成模型提供的输入范围”。每张分镜再按任务选择一张、多张或全部同一目标SKU/版本的有效资料作为实际生成参考输入；其他SKU默认不传入单SKU生成，只在内部用于识别差异和形成明确禁区。SKU总览或比较图需要多个SKU时，分别锁定、分层生成或使用真实商品层后期合成，不能让模型平均或融合。发生冲突时依次保护核心对象身份、目标SKU/版本、可见几何或界面、颜色材质、文字包装或权益原文和局部补充；无法解除时回到商品卡询问。冲突一旦解除，后续分镜必须写出采用的具体结论和舍弃项，不能只留下“服从商品卡”。

## 区分事实、观察与推断

- 把用户明确提供且不与可靠参考视觉冲突的资料记为“已确认事实”。
- 把图片中可直接看见的轮廓、颜色、表面、文字、数量和位置记为“可观察内容”。
- 把人群、使用情境、购买阻力、视觉表达和构图选择记为“策略推断”，只用来决定怎样画，不得改写参数、功效、适配或认证。
- 把缺少来源、彼此冲突或需要猜测的内容记为“待验证或禁用”，从正式画面和文案中删除。

用户对真实商品事实的纠正可以更新判断；用户要求概念改色、改款或创意变形时，只把它记录为本次允许变化，不要反向改写真实SKU。

## 保护未知面与真实证据像素

1. 先判断目标是否属于实体商品、真实存在且与当前任务有关。数字权益、服务及没有相应物理面的对象直接标为“不适用”，不评分、不显示写实视图确认卡。
2. 用户已经提供可确认的同SKU真实背面、底部、内部或拆解图片时，对应目标直接作为证据使用，不评分、不进入序列号确认；仍需核对SKU、状态与其他资料冲突。
3. 缺少目标视图的同SKU直接资料时，只对适用的背面、底部、内部和拆解分别判断还原置信度；只有超过80分的目标才列入“写实视图确认”清单，用户用序列号确认后才允许进入写实分镜。置信度不超过80分的目标不列入清单，改用可靠角度、真实商品像素合成、补拍、三维资料或明确概念稿；不能用一个总分一次放开所有未知结构。
4. 多角度照片不等于精确三维模型；禁止镜像替代真实另一侧，也不能把品类常识当作同款结构证据。
5. 复杂标志、型号、参数表、包装长文字、真实UI、订单/到账状态、授权文件、人员资质、二维码和编号优先保留真实证据像素或后期排版；图像模型只负责其外部的背景、设备框、场景、光影和文字安全区，不重绘看似真实但不存在的界面、文档或服务结果。

主体识别、AI预构建、编号选择、商品卡和逐目标置信度的完整交互规则，统一读取 [prebuild-and-product-card.md](prebuild-and-product-card.md)，本文件不重复定义第二套确认流程。

## 交给图组推演

只交付必要摘要：商品形态、目标核心对象与SKU/版本或状态、全部有效参考视觉的综合结论、逐张实际生成参考输入、可见特征或真实证据像素、不可改变项、允许变化、实体商品适用目标视图的直接证据或独立置信度、写实视图确认结果、事实边界、可靠生产方式和唯一未解除风险。商品卡确认前不进入正式分镜。
