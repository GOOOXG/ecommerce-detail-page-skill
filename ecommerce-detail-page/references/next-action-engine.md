# 下一步决策引擎

本文件是每个交互节点的动作推荐、排序、数字菜单绑定和阶段推进规则的唯一来源。不负责理解原始输入、专业推演、返修执行或最终分镜正文。

## 目录

`目标` / `输入状态` / `十类动作槽位` / `选择卡质量契约` / `动作排序` / `阶段适配` / `行为自适应` / `阻塞与非阻塞` / `数字菜单绑定` / `输出格式` / `输出接口`

## 目标

在正式提示词交付前，用编号`0`到`9`的10个互不重复动作帮助用户以最少对话轮次推进、补充、返修或自定义任务。`0`始终是AI结合当前状态计算出的首推动作；其余槽位保持稳定认知。推荐只展示结论和必要依据，不展示内部思考链。正式提示词交付后停止本模块，只能转入`render-gate.md`的紧凑选择或结束。

## 输入状态

从执行模块读取：当前阶段、运行模式、商品/范围/结构/方向合同版本与状态、待确认合同、硬性阻塞、输出对象、单图游标、当前单图状态、最近可见菜单、用户连续行为、被否定动作和返修记录。

## 十类动作槽位

每次需要导航时，将以下10个槽位改写成当前阶段的具体操作，统一使用`0`到`9`。不能只写“优化一下”或“继续看看”，也不能用近义动作凑数。

0. **AI推荐推进**：选择当前收益最高、风险最低的动作；存在硬性阻塞时改为解除阻塞，并用一句话说明依据。
1. **确认并继续**：确认当前节点并进入下一个合法节点；不得越过商品卡、结构、方案或单图确认闸门。
2. **当前优化**：提高当前阶段最影响结果的一项内容或合同字段。
3. **上一步返修**：回到最近一个可能导致当前结果偏差的上游合同或草案，并说明影响范围。
4. **商品资料**：补充、修改、删除或重新打开商品字段、来源、证据和图片资料。
5. **输出控制**：调整输出对象、组合、张数、平台、用途、画布或交付范围。
6. **营销文案**：调整人群、卖点、购买阻力、转化路径、文案命题和证据表达。
7. **视觉设计**：调整风格、色彩、字体、场景、人物、视角、构图、生产方式或保真级别。
8. **模式控制**：切换逐图/自动模式、剩余自动或查看当前阶段的必要候选；不得借此静默扩大正式分镜范围。
9. **自定义要求**：直接输入要保留、删除、替换、补充、返修或新增的要求。

10项必须全部显示并保持编号语义稳定。某槽位在当前阶段不能直接执行时，改写为该职能最接近的合法动作或影响预览，不得显示“不可用”；用户选中后才按需加载对应专业文件，未选择的槽位不加载模块。

## 选择卡质量契约

结构、综合方案、画布、场景、美学和其他专项选择卡都必须先给AI首推，再说明产品化依据、选择后影响和一个主要风险。设计需求预判/输出对象卡属于业务范围确认：必须展开所有对象的可能职责和条件，不用单一AI首推替用户决定。其余候选必须包含：

- 1个明确首推，不用“都可以”回避判断。
- 2到4个实质不同的可选方向；数量由当前专业文件决定，不为凑数制造近义项。
- 每项的适用条件和对后续卖点、文案、视觉、证据或交付的影响。
- 自定义入口；用户可以修改某个候选，也可以从零描述。
- “查看更多”入口只在用户要求扩展时出现；展开最多10条，随后重新收敛。

已确认内容不再作为候选重复出现；非关键专业细节由AI在选定方向内自主补齐。

## 动作排序

内部为候选动作评分，评分只用于排序，不向用户展示计算过程：

| 维度 | 判断 |
|---|---|
| 依赖可行性 | 当前合同与工作包是否足以执行，是否会被缺失事实阻断 |
| 预期提升 | 对点击、理解、信任、选型、转化、防退货或复用的提升 |
| 风险紧迫度 | 是否涉及主体、事实、合规、画布、对象范围或编号错误 |
| 意图匹配 | 是否符合用户最近的提速、发散、纠偏、补证或直出行为 |
| 执行成本 | 是否能用较少输入和较小重算范围完成 |
| 重复惩罚 | 是否已完成、被否定、刚展示过或会重复询问已确认内容 |

排序优先级：硬性阻塞与高风险修复 > 用户明确动作 > 推荐推进 > 高收益低成本优化 > 发散探索。

## 阶段适配

| 当前阶段 | `0` AI首推 | `1` 确认推进 | `2` 当前优化 | `3` 上一步返修 | `4`到`8`重点适配 |
|---|---|---|---|---|---|
| 接单 | 建立商品文档草案 | 确认已捕捉输入 | 优化商品线索解析 | 修正目标理解 | 资料、输出意向、营销目标、视觉禁区、运行模式 |
| 信息建库 | 生成含建议的商品卡 | 确认识别草案 | 优化建议价值排序 | 重新识别主体 | 补资料、暂存输出、卖点证明、补图方向、深度模式 |
| 信息确认 | 按最高价值建议补充或确认现状 | 确认并跳过未补充建议 | 修正当前卡 | 返回识别草案 | 字段资料、输出预览、卖点边界、视觉锚点、建议扩展 |
| 需求预判与输出确认 | 采用最符合用户意向的范围 | 确认对象与数量 | 优化对象分工 | 返回商品卡 | 新增字段、数量画布、转化目标、视觉用途、组合扩展 |
| 初步推演 | 进入结构选择 | 确认推演结论 | 优化投放用途 | 修改输出范围 | 商品事实、交付控制、营销任务、视觉目标、推演深度 |
| 结构选择 | 采用系统首推结构 | 确认当前结构 | 优化角色顺序 | 返回输出任务 | 补事实、数量画布、营销链路、视觉节奏、结构变体 |
| 综合方案选择 | 采用首推方案 | 确认选定方案 | 组合或比较方案 | 重选结构 | 补证据、输出约束、营销文案、视觉方向、查看更多 |
| 图组编排 | 确认编排并设计第1张 | 确认当前编排 | 优化任务分工 | 返回方案 | 更新字段、调整图组、文案矩阵、视觉节奏、自动模式 |
| 单图确认 | 确认或修复当前最高影响项 | 确认本张并继续 | 定向返修当前图 | 返回上一张或共享合同 | 更新事实、调整图组、营销文案、视觉提示词、剩余自动 |
| 校验 | 修复失败项并交付 | 确认校验结果 | 查看高影响风险 | 返回受影响合同 | 更新事实、输出范围、文案风险、视觉质量、局部重算 |

正式提示词交付后不使用本表或通用`0`到`9`菜单：源码块外只显示`render-gate.md`定义的“暂不生图 / 指定分镜 / 当前图组全部 / 全部图组 / 每张自定义候选数量”。用户直接要求返修时进入失败诊断与最小补丁，不先展示扩展菜单。

## 行为自适应

- 连续两次“继续、好的、确认”或短数字确认：商品卡信息识别内容必须先完成一次确认；其余节点压缩解释并采用当前首推。在逐图模式下仍逐张展示下一张确认卡，不自动越过未确认图片。
- 用户要求“更多、脑暴、差异化”：当前优化槽位可给10条候选，经聚类后只把首推、3个高差异备选和自定义入口放入可见菜单。
- 用户连续两次返修同一问题：不继续表层改写，自动回到最近的上游原因合同或草案。
- 用户补充事实或证据：先更新商品文档草案并重发确认卡；确认后更新商品合同，只重算引用该事实的页面。
- 用户要求提速或只要提示词：商品信息确认后不展示其他非阻塞菜单，采用首推进入最终校验。
- 用户否定某方向：记录为偏好事件，本轮及后续相邻节点不再推荐同一方向或近义变体。

## 阻塞与非阻塞

- 商品信息库未确认，或存在主体冲突、事实冲突、合规硬风险、产品保真不足时，`0`必须是确认商品文档或解除阻塞，不能写“选择输出对象”或“继续出稿”。
- 画布、风格、平台或普通创意缺失通常不阻塞；AI先给首推，用户不选择时按当前模式处理。
- 需要用户补充时，只索取能解除当前阻塞的一个最小信息，不把参数清单一次性抛给用户。

## 数字菜单绑定

- 每次展示菜单时建立一次临时菜单绑定记录：菜单编号、动作、作用合同/草案、影响范围和有效阶段。
- 数字只绑定最近一次可见且仍处于当前阶段的菜单；阶段推进、重新展示菜单或用户自由输入后，旧菜单失效。
- 用户输入多个数字时，按顺序执行兼容动作；动作冲突时以最后一个明确选择为准，并提示被覆盖项。
- 数字后附加自然语言时，数字决定基础动作，自然语言作为该动作的新约束。
- 没有有效菜单时收到孤立数字，不猜测历史选项；结合当前状态给出一次最小确认。
- 通用下一步菜单的`0`到`9`只绑定当前节点；其中`0`的实际动作必须在菜单中明示，不能只写“AI推荐”。
- 单图菜单的`1`只确认当前图；`2-1`到`2-10`绑定当前图字段返修；阶段进入下一张后，上一张字段菜单失效。
- 结构选择卡可见时，`1`到`5`只绑定 `structure-selection.md`；结构合同发布后该菜单立即失效，不能与单图菜单共用。
- 商品卡信息识别内容可见时，`0`到`9`只绑定 `product-dossier.md` 的商品卡动作；卡片确认或重建后旧菜单失效。
- 设计需求预判卡可见时，`1`到`7`只绑定当前输出对象菜单；范围合同发布后旧菜单失效。
- 综合方向卡可见时，`1`到`5`只绑定当前5个方向；方向合同发布后该菜单立即失效。用户自然语言自定义不需要编号。
- 商品信息确认、设计需求预判/输出对象、结构、综合方案、单图、画布/专项选择和普通导航菜单必须互斥；若意外同时可见，以当前阶段最新生成的菜单为准，并使其余菜单失效。

## 输出格式

正常节点最多用一句首推说明，然后完整输出`0`到`9`：

```text
0. 【AI推荐】[当前收益最高且合法的具体动作与一句依据]
1. 确认并继续：[进入的真实下一节点]
2. 优化当前：[当前阶段最高影响动作]
3. 返修上一步：[最近上游动作及影响]
4. 商品资料：[当前可补充、修改或删除的字段/素材]
5. 输出控制：[对象、组合、张数、平台、用途、画布或范围]
6. 营销文案：[人群、卖点、路径、证据或文案动作]
7. 视觉设计：[风格、场景、人物、视角、构图或生产动作]
8. 模式控制：[逐图/自动、剩余自动或当前阶段必要候选]
9. 自定义：直接说明要保留、修改、删除或新增什么
```

必须把方括号内容替换为当前任务的真实动作。最终 Markdown 分镜源码块内部禁止出现菜单；正式提示词交付后不得再显示本菜单，只能在源码块外显示生图闸门选择。

结构选择节点不使用通用五项措辞，直接读取 `structure-selection.md` 的选择卡：递进式主次、等量并列、混合结构、采用系统首推、自定义。每项必须带当前输出对象的具体注解。
商品信息确认节点不使用普通措辞，直接读取 `product-dossier.md` 的`0`到`9`商品卡动作；`1`只有在关键冲突清零时可确认现状，补充或修改后必须重发整卡并再次确认。设计需求预判/输出对象节点直接读取 `interaction-engine.md` 的全对象预判卡，不显示单一“AI建议做某对象”。


综合方向选择节点不使用通用十类动作，读取 `reasoning-engine.md` 的5个综合方向并按下列格式正常渲染：

```text
【综合设计方向选择｜[输出对象][数量]张】
- 产品判断：[产品、主要人群、买家任务和最大阻力]
- 系统首推：[方向编号与名称]
- 首推理由：[两条产品化依据]

1. [转化稳妥方向；标记是否推荐]
   人群/卖点：[目标人群、核心利益]
   路径/证据：[中文转化阶段、现有证据与待补证据]
   视觉/文案：[场景、视觉锤、美学、信息密度和语气]
   代价/风险：[主要取舍和合规边界]
2. [平台适配方向：填写完整人群、卖点、路径/证据、视觉/文案、代价/风险]
3. [价值与品牌方向：填写完整人群、卖点、路径/证据、视觉/文案、代价/风险]
4. [视觉差异方向：填写完整人群、卖点、路径/证据、视觉/文案、代价/风险]
5. [情绪与场景方向：填写完整人群、卖点、路径/证据、视觉/文案、代价/风险]

回复1到5选择；也可直接说“以方向1为主，采用方向4的视觉”，或输入自定义人群、卖点、场景、风格和禁区。
```

方向内容必须替换为当前产品的真实结论，不能保留模板说明。多输出对象优先用一组活动级方向说明各对象分工，不重复输出多组近义卡。方向确认后不再单独询问同义的营销路线、场景和美学；只有用户主动返修某一维度时，才展示该维度的专项候选。

单图待确认节点改用以下`0`到`9`动作；`2`继续承载`2-1`到`2-10`字段级返修：

```text
0. 【AI推荐】根据当前自检结果确认本张，或先修复最高影响问题
1. 确认本张并继续第n+1张
2. 定向返修本张：进入任务、卖点、文案、视觉、场景、构图、事实、提示词或画布/槽位子项
3. 返回上一环节：修改上一张、共享合同或方向，并先查看影响范围
4. 商品资料：新增或修正准确字段，重发商品卡后定向重算
5. 输出控制：调整本组张数、顺序、结构、画布或交付范围
6. 营销文案：调整本张人群、卖点、转化任务、证据或文案
7. 视觉设计：调整场景、人物、视角、构图、美学、光影或生产方式
8. 后续与模式：预览下一张、调整剩余角色、切换剩余自动或生成测试变体
9. 自定义：直接说明当前张要保留、修改、删除或新增什么
```

当前为最后一张时，第1项改为“确认本张并进入整组校验”，不能推荐不存在的下一张。

## 输出接口

向交互与执行模块交付：首推动作、当前有效专业选择卡或`0`到`9`动作菜单、临时菜单绑定记录、动作目标合同/草案、商品信息确认动作、结构选择动作、综合方向动作、当前单图动作、预计影响范围、是否推进一张和是否切换剩余自动。不得输出评分明细或完整思考链。
