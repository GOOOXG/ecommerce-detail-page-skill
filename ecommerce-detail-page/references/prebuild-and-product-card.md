# 预构建与已确认商品卡

本文件只负责把“图片识别”整理成可由用户确认的商品依据。它不是运营报告，也不是最终分镜；商品卡确认后，才允许进入图片需求判断和逐张提示词编写。

## 唯一顺序

`识别主体 → AI预构建 → 编号建议 → 用户选择或纠正 → 商品卡（待确认） → 用户确认或明确直出授权 → 已确认商品卡 → 设计需求预判与输出范围 → 多图结构 → 自适应综合方向（最多比较5个） → 图组编排与逐图确认 → 最终分镜提示词 → 可选生图`

不能跳过商品卡，也不能在商品卡尚未确认时把推测卖点、参数、材质或隐藏结构写进正式提示词。明确直出授权只能压缩建议菜单：系统仍先形成待确认卡并做冲突检查；单一清晰目标且无关键冲突时可把授权视为确认，多SKU、相似款、主体/SKU/状态不确定或关键卖点、素材、授权未证实时必须展示待确认卡，等待用户确认或纠正。

## 第一步：识别参考图

先实际查看每份可访问参考视觉；可以按上传顺序在内部建立稳定编号用于用户纠正和证据追踪，但正式分镜不输出编号。先判断商品形态是实体、数字权益还是服务，综合全部有效参考内容，再按SKU/版本/状态分组。识别结果至少包括：

- 核心对象：品类、商品形态、主要用途和画面中最可能的售卖对象。
- 商品身份：实体记录品牌、型号、SKU、颜色、容量、尺寸、套装关系和状态；非实体记录品牌、权益/服务版本、档位、时长、地区、账号或设备范围、交付与激活/预约状态；看不清的内容不猜。
- 可见事实：实体记录轮廓、结构、部件数量、表面表现、颜色、标志、原文、包装、配件和使用状态；非实体记录真实界面、权益层级、流程、原文、交付状态、授权页和服务场景。
- 内容贡献：各图对身份、视角、细节、文字、包装、配件、尺度或场景提供什么证据，以及怎样与其他图互补或冲突。
- 证据边界：图片直接证明的内容、用户明确提供的内容、合理推断和目前不能使用的内容。

图片识别置信度只描述“识别得像不像”，不等于隐藏结构已经被证实。主体、SKU或状态无法合理区分时，先在对话中说明冲突，不进入分镜。

用户已明确只做一个目标SKU/版本且不要求总览或比较时，预构建和商品卡只完整展开目标对象；其他款合并为防串款反例，只记录会串入的颜色、部件、包装、权益或状态，不猜名称、不为无关款追加问卷。只有总览、比较或多SKU分别交付才展开全部对象。

## 第二步：AI预构建

完成主体候选识别后，AI在对话中一次性预构建与本次商品相关的候选信息，避免把零散问题反复追问。只展示真正可能改变分镜的内容：

1. **候选卖点**：从可见结构、用户资料和可验证证据提炼；没有证据的卖点标为“待补证”，不能当成事实。
   预构建可按需调用 [marketing-reasoning.md](marketing-reasoning.md) 的营销模型加速层，先做“特征 → 可能优势/利益 → 待证据”的后台推演，再把结果压缩成候选卖点；模型只帮助排序和发现缺口，不改变本文件的确认顺序。
2. **需要的事实与内容**：可能影响识别、选型、防错、信任、使用或场景尺度的字段，例如尺寸、容量、材质、适配、数量、安装方式和包装清单。
3. **可用素材**：现有参考图、参数表、包装、证书、实拍、三维资料、真实商品层或后期能力；分别说明它承担商品身份、结构细节、包装/界面文字、尺度使用、视觉灵感还是反例职责，以及真正能证明什么。
4. **缺失素材**：补拍角度、细节、参数、配件、使用动作或授权资料；没有补齐时要怎样安全降级。
5. **建议制作的图片**：读取 [image-type-index.md](image-type-index.md) 的轻量导航，为每项写明推荐图型、唯一买家问题、可能适用的输出对象与目标SKU/版本、所需证据、实际生成参考输入、生产方式、独有信息增量、主要风险，以及不能制作或需要降级的原因。这里的建议图片只是待确认的需求假设，用来判断哪些买家问题值得进入商品卡和后续范围阶段；即使用户选择，也不在此确认正式输出对象、分镜数量、最终图型或顺序。商品卡确认前不加载完整排序和图组编排规则。
6. **视觉与生产条件**：允许的角度或界面状态、核心视觉载体占比、场景、人物、画布、真实证据像素层、后期排版和图生图可行性。
7. **写实视图确认候选**：仅实体商品启用。先判断背面、底部、内部和拆解是否真实存在；不适用目标直接跳过。适用目标有同SKU直接证据时不评分，缺少直接资料时逐项评分。当前原始意向足以判断与本次任务有关时，超过80分才列出序列号，等待用户确认是否纳入写实分镜；输出范围尚不清楚时只记为“待范围判断”，不为提前发卡而猜测任务相关性。

AI只能建议“需要什么资料”，不能替用户填写未知数值。先匹配已有图型，再主动检查空间适配、收纳携带、到手内容、清洁维护、SKU选择、接口兼容、使用边界、信任证据、利益行动和可诚实形成的视觉记忆是否有关键遗漏；数字权益或服务还要检查交付内容、发放/预约方式与时效、激活/有效期、权限与地区、退款/取消/续费、授权与异常处理。用户给出的类型和案例是思维起点，不是默认上限。建议按“防买错与安全 → 商品真实性 → 核心卖点证明 → 场景与视觉 → 生产效率”排序；简单且资料充分时只展示首推和真正会改变分镜的少量备选，复杂任务通常展示3到5项。

## 第三步：编号选择与手动纠正

AI先给出首推，再给可见的编号选项。编号只用于当前这张建议卡；看到新的建议卡后按新卡重新选择，用户也可以完全不用编号，直接用自然语言纠正。

建议卡中的字段使用字段名限定编号，例如“主体：1、卖点：1,2、素材：2、建议图片：1”。裸单个数字只表示当前可见建议卡的操作项，不跨阶段沿用；没有字段名的多个数字可能对应多个列表时，只问一句“这些数字要选择哪个字段”，不自行猜测。每张数字卡都用一句话提示“本卡数字只对当前【卡名】有效，下一卡自动失效”；进入设计需求、结构、方向或逐图确认后，必须按新卡解释数字。

建议卡采用紧凑格式：

```text
【AI预构建建议】
商品形态：实体商品
主体候选：1. 不锈钢保温杯（高）  2. 旅行水壶（中）
候选卖点：1. 杯盖可见开合结构（图片可见）  2. 保温性能（待补证）
需要补充：1. 准确容量  2. 材质证明  3. 包装清单
采用素材：1. 参考图1正面  2. 参考图2杯盖细节
建议图片：1. 首屏识别  2. 杯盖结构细节  3. 使用尺度场景
写实视图：发现1项超过80分候选；当前输出意向明确时完成本卡后显示确认卡，否则记为待范围判断

请选择或纠正：
1. 采用AI首推并生成商品卡（待确认）
2. 只修改主体或SKU
3. 只修改卖点
4. 只补充事实或素材
5. 只修改建议图片假设
6. 逐项重新选择
7. 直接输入纠正，例如“容量是750ml，参考图1和2是同一SKU”

本卡数字只对当前【AI预构建建议】有效，下一卡自动失效；选择上方字段时请带字段名。
```

主建议完成选择或纠正后，如果缺少直接证据、超过80分且当前任务相关性已经明确，再单独显示一张不会与其他菜单共存的确认卡：

```text
【写实视图确认】
1. 背面｜92分｜依据摘要：可见侧边连续、同SKU结构一致｜主要限制：不得新增未出现的接口或配件

请只回复要纳入本次写实分镜的序列号，例如“1”；不采用可回复“无”。
```

用户可以用一行完成选择，例如：

```text
主体：1；卖点：1,2；补充：1=750ml；图片：1,2,3
```

这行紧凑格式只属于当前“AI预构建建议”卡，不能提前填写尚未显示的写实视图序列号。`图片：1,2,3`只把对应需求假设带入待确认商品卡，不等于承诺最后做3张，也不替代商品卡后的对象、分镜数量、平台、画布和SKU映射确认。严格按条件处理：先完成主建议选择；当前任务相关性已经明确且存在候选时，再显示独立“写实视图确认”卡并分配序列号，用户只在这张卡出现后回复序列号；范围尚不清楚时把候选记入商品卡的“待范围判断”，商品卡确认和正式范围明确后再筛选并发卡。

“全部采用AI推荐并直接确认”“直接出”“只要提示词”“不要逐步问”或其他无歧义的直出表达，都可以压缩建议菜单，但不能替用户自动确认写实视图，尤其不能确认尚未编号的候选。直出模式默认排除所有未获序列号确认的候选；交互模式中因范围未明而延期的候选，待范围明确后只对确实相关者发卡。用户明确要纳入时，必须先显示独立确认卡，再由用户回复卡内序列号。只有独立确认卡已经是当前唯一可见卡时，`写实视图：1,3`或裸序列号才有效。系统仍先生成并记录“商品卡（待确认）”，完成商品事实、素材和视图选择冲突检查；单一清晰目标且无关键冲突时，才把用户明确直出授权作为该卡确认；多SKU、相似款、主体/SKU/状态不确定或关键卖点、素材、授权未证实时必须展示卡并等待确认，不能把直出当成模型自行确认。如果用户只选择了建议而没有明确直出或确认，仍必须展示“商品卡（待确认）”并等待确认。如果用户指出错误，必须以用户纠正为准并重发受影响部分。

## 隐藏视图的独立置信度

先做物理适用性判断：只有实体商品中真实存在的背面、底部、内部或拆解才可能评分；数字权益、服务以及没有相应物理面的对象标记“不适用”，不计分、不显示确认卡。再做任务相关性判断：原始意向已经说明具体输出时可在预构建阶段判断；意向尚不清楚时允许先评分，但只标记“待范围判断”，等输出范围明确后再决定是否发卡。只有正面图或缺少适用目标视图的同SKU直接资料时，各目标分别评分，不能用一个总分放开所有未知结构。用户已经提供可确认的同SKU真实目标图片时，作为直接证据使用，不进入81–100分序列号确认；仍需检查SKU、状态和冲突。其余缺失目标按以下因素综合判断：可见几何确定性、对称与结构连续性、同SKU线索、品类结构稳定度、冲突数量和隐藏复杂度。

为了让分数可复核，内部按五项零到五分记录：可见几何确定性30%、对称与结构连续性20%、同SKU直接线索20%、品类结构稳定度15%、无冲突与低隐藏复杂度15%，加权后向下取整为整数百分制。统一使用锚点：`0=没有依据或明确冲突，1=极弱，2=局部线索，3=基本但仍有关键未知，4=强且关键结构可闭合，5=近乎直接证据`，不使用4.2之类假精度。该分数表示“能否精确还原当前同款而不发明结构”，不是“能否生成看起来合理的同类商品”。没有直接证据时，品类稳定度不能替代同SKU线索；任一会改变接口、开孔、连接、零件数量或安全关系的关键特征低于4分时，总分上限为80分；出现结构冲突时先降低对应项，再决定是否降级。分数只在商品卡和写实视图确认卡中显示，正式分镜不显示数字。

- **81–100分（严格超过80分）**：列入“写实视图确认”清单，分配稳定序列号，向用户说明视图、分数、依据摘要和主要限制；不得自动写入写实分镜。
- **0–80分**：不列入写实视图确认清单，不写入写实分镜；改用已证实角度、补拍、真实商品层合成、三维资料或明确概念稿。
- **恰好80分**不进入确认清单；门槛是严格高于80分。

写实视图确认卡只允许用户确认“哪些目标可以进入本次写实分镜”，不把未提供的结构变成新的商品事实。卡内只显示超过80分并可操作的目标；低分与不适用目标不分配序列号。用户回复序列号（例如“1、3”）后，仅将对应目标记为“已确认写实视图”；回复“无”则全部保留在备选外。序列号只绑定当前确认卡，不等同于商品卡确认，也不跨卡复用。商品卡整体确认后，已确认写实视图才进入正式分镜编译；正式分镜不写分数、置信度或推定性质标签。

## 商品卡确认与已确认商品卡

用户选择或纠正后先生成一张标明“待确认”的紧凑商品卡，作为一次核对草稿。若实体商品存在超过80分、当前任务相关性已明确且显式选择尚未完成的隐藏视图，才附上一次独立的“写实视图确认”序列号清单；范围尚不清楚时在卡中记录“待范围判断”，不附序列号。已经选择过时只汇总结论，不重复发卡。用户只回复序列号时，只确认对应视图，不确认商品卡。待确认卡阶段不提供商品卡裸数字确认菜单；用户只回复“1”等数字时，若当前上下文不是写实视图确认清单，不视为商品卡确认，必须回问“确认商品卡”或字段纠正。当前唯一可见确认对象就是商品卡且没有歧义时，“确认”“没问题”“按这个”“就这样”与“确认商品卡”等价；“继续”和裸数字仍不确认。用户明确确认后，或单一清晰目标在完成冲突检查后收到明确直出授权，才将同一张卡标记为“已确认商品卡”；多SKU、相似款、主体/SKU/状态不确定或关键事实未证实时，必须让用户看到卡并确认/纠正。该卡是后续需求预判、范围确认和图片规划的唯一事实依据。商品卡至少包含：

- 商品形态、核心对象与识别置信度。
- 品类、品牌、型号或版本，以及当前输出需要的SKU/权益档位清单；单目标模式只完整展开目标对象并把其他款汇总为防串款反例，多SKU总览或比较才展开全部差异。实体商品绑定颜色、容量、状态、套装关系，非实体绑定档位、时长、地区、账号/设备范围、交付与激活/预约状态。
- 图片可见事实与用户确认事实。
- 已采用卖点、待补证卖点和已跳过内容。
- 已有素材、缺失素材和每项素材职责；风格、场景或竞品灵感与商品事实证据分开记录。
- 用户原始输出意向（如果有，只标为“待范围确认”，不当作已确认对象、数量或平台）。
- 必须保持、允许变化与自由探索、必要边界，以及用户明确禁止的内容；真实UI、权益原文、订单/到账状态、授权文件、二维码、编号等需要保留的证据像素单列职责。
- 实体商品记录适用的背面、底部、内部、拆解的直接证据状态、缺失目标独立还原置信度，以及“已确认、未选择或待范围判断”的结论；只有实际显示过确认卡的目标才记录序列号，不适用目标只写一次“不适用”，不逐项打分。
- 数字权益或服务记录交付内容、发放/预约方式与时效、激活/有效期、权限与适用范围、退款/取消/续费、授权/资质和异常处理边界；未知字段只能删除对应主张或请求补证。
- 用户手动纠正记录的结论摘要，不保留冗长对话。

商品卡不是独立交付报告。只有标记为“已确认商品卡”后，才进入 [confirmation-workflow.md](confirmation-workflow.md) 的设计需求预判和输出范围确认，再把必要结论传给图组规划和提示词编写；商品卡和写实视图确认卡可以显示分数，正式分镜只保留已确认视图所需的事实边界，仍只交付逐张中文图生图分镜提示词。

## 进入下一步的条件

商品主体、目标SKU/状态、用户采用的卖点与素材边界已经明确，且没有会误导购买的冲突时，才读取图片需求和输出对象规则。若只是缺少非关键资料，按用户选择跳过或降级，不重复追问；若主体或SKU仍不成立，只问一个最小关键问题。
