# 预构建与已确认商品卡

本文件只负责把“图片识别”整理成可由用户确认的商品依据。它不是运营报告，也不是最终分镜；商品卡确认后，才允许进入图片需求判断和逐张提示词编写。

## 唯一顺序

`识别主体 → AI预构建 → 编号建议 → 用户选择或纠正 → 商品卡（待确认） → 用户确认 → 已确认商品卡 → 设计需求预判与输出范围 → 多图结构 → 固定5个综合方向 → 图组编排与逐图确认 → 最终分镜提示词 → 可选生图`

不能跳过商品卡，也不能在商品卡尚未确认时把推测卖点、参数、材质或隐藏结构写进正式提示词。

## 第一步：识别参考图

先实际查看每张可访问图片，并按上传顺序建立稳定编号：`参考图1、参考图2……`。识别结果至少包括：

- 商品主体：品类、形态、主要用途和画面中最可能的主体。
- 商品身份：品牌、型号、SKU、颜色、容量、尺寸、套装关系和状态；看不清的内容不猜。
- 可见事实：轮廓、结构、部件数量、表面表现、颜色、标志、原文、包装、配件和可见使用状态。
- 参考职责：身份图、视角图、细节图、文字图、包装图、配件图、尺度图或场景图。
- 证据边界：图片直接证明的内容、用户明确提供的内容、合理推断和目前不能使用的内容。

图片识别置信度只描述“识别得像不像”，不等于隐藏结构已经被证实。主体、SKU或状态无法合理区分时，先在对话中说明冲突，不进入分镜。

## 第二步：AI预构建

完成主体候选识别后，AI在对话中一次性预构建与本次商品相关的候选信息，避免把零散问题反复追问。只展示真正可能改变分镜的内容：

1. **候选卖点**：从可见结构、用户资料和可验证证据提炼；没有证据的卖点标为“待补证”，不能当成事实。
2. **需要的事实与内容**：可能影响识别、选型、防错、信任、使用或场景尺度的字段，例如尺寸、容量、材质、适配、数量、安装方式和包装清单。
3. **可用素材**：现有参考图、参数表、包装、证书、实拍、三维资料、真实商品层或后期能力，以及每项素材能证明什么。
4. **缺失素材**：补拍角度、细节、参数、配件、使用动作或授权资料；没有补齐时要怎样安全降级。
5. **建议制作的图片**：每张图解决的买家问题、所需参考图、独有信息增量和不能制作的原因。
6. **视觉与生产条件**：允许的角度、主体占比、场景、人物、画布、后期排版和图生图可行性。

AI只能建议“需要什么资料”，不能替用户填写未知数值。建议按“防买错与安全 → 商品真实性 → 核心卖点证明 → 场景与视觉 → 生产效率”排序，通常给出3到5项；资料已经充分时减少建议。

## 第三步：编号选择与手动纠正

AI先给出首推，再给可见的编号选项。编号只用于当前这张建议卡；看到新的建议卡后按新卡重新选择，用户也可以完全不用编号，直接用自然语言纠正。

建议卡中的字段使用字段名限定编号，例如“主体:1、卖点:1,2、素材:2、建议图片:1”。裸数字只表示当前可见建议卡的首选动作，不跨阶段沿用；进入设计需求、结构、方向或逐图确认后，必须按新卡解释数字。

建议卡采用紧凑格式：

```text
【AI预构建建议】
主体候选：1. 不锈钢保温杯（高）  2. 旅行水壶（中）
采用卖点：1. 双层保温结构  2. 防漏杯盖
需要补充：1. 准确容量  2. 材质证明  3. 包装清单
采用素材：1. 参考图1正面  2. 参考图2杯盖细节
建议图片：1. 首屏识别  2. 杯盖防漏证据  3. 使用尺度场景
视图推定：背面 92分，底部 68分，内部 54分，拆解 41分

请选择或纠正：
1. 采用AI首推并生成商品卡（待确认）
2. 只修改主体或SKU
3. 只修改卖点
4. 只补充事实或素材
5. 只修改建议图片和数量
6. 逐项重新选择
7. 直接输入纠正，例如“容量是750ml，参考图1和2是同一SKU”
```

用户可以用一行完成选择，例如：

```text
主体：1；卖点：1,2；补充：1=750ml；图片：1,2,3；背面采用高置信推定；底部不做
```

“全部采用AI推荐并直接确认”可以压缩可见交互，但仍先生成并记录“商品卡（待确认）”，完成事实冲突检查后把这句话视为用户明确确认并标记已确认；如果用户只选择了建议而没有明确确认，仍必须展示“商品卡（待确认）”并等待确认。如果用户指出错误，必须以用户纠正为准并重发受影响部分。

## 隐藏视图的独立置信度

只有正面图时，背面、底部、内部和拆解分别评分，不能用一个总分放开所有未知结构。每个目标视图按以下因素综合判断：可见几何确定性、对称与结构连续性、同SKU线索、品类结构稳定度、冲突数量和隐藏复杂度。

为了让分数可复核，内部按五项零到五分记录：可见几何确定性30%、对称与结构连续性20%、同SKU直接线索20%、品类结构稳定度15%、无冲突与低隐藏复杂度15%，加权后换算为百分制。没有直接证据时，品类稳定度不能替代同SKU线索；出现结构冲突时先扣除冲突项，再决定是否降级。分数只在商品卡确认阶段显示，正式分镜不显示数字。

- **91–100分**：允许写入“高置信推定/示意”分镜，但不能表述为官方已证实结构；提示词必须保留事实边界。
- **0–90分**：不得生成写实未知结构。改用已证实角度、补拍、真实商品层合成、三维资料或明确标注的概念稿。
- **恰好90分**也不放行；“高于90分”才是门槛。

“写实”只表示画面制作方式，不表示资料已经证明。若用户补充同款背面、底部、内部或拆解资料，重新独立评分并更新商品卡。正式分镜只写“高置信推定/示意”或“已证实视图”，不重复商品卡里的分数。

## 商品卡确认与已确认商品卡

用户选择或纠正后先生成一张标明“待确认”的紧凑商品卡，作为一次核对草稿。待确认卡阶段不再提供裸数字确认菜单；用户只回复“1”等数字时，不视为确认，必须回问“确认商品卡”或字段纠正。用户明确回复“确认商品卡”后，才将同一张卡标记为“已确认商品卡”，作为后续需求预判、范围确认和图片规划的唯一事实依据。商品卡至少包含：

- 商品主体与识别置信度。
- 品类、品牌、型号，以及 SKU 清单；每个 SKU 绑定身份参考图、颜色、容量、状态、套装关系和与其他 SKU 的差异。
- 图片可见事实与用户确认事实。
- 已采用卖点、待补证卖点和已跳过内容。
- 已有素材、缺失素材和每项素材职责。
- 用户原始输出意向（如果有，只标为“待范围确认”，不当作已确认对象、数量或平台）。
- 必须保持、允许变化、禁止内容。
- 背面、底部、内部、拆解的独立还原置信度及事实边界。
- 用户手动纠正记录的结论摘要，不保留冗长对话。

商品卡不是独立交付报告。只有标记为“已确认商品卡”后，才进入 [confirmation-workflow.md](confirmation-workflow.md) 的设计需求预判和输出范围确认，再把必要结论传给图组规划和提示词编写；商品卡阶段可以显示分数，最终分镜只保留必要的事实边界和“高置信推定/示意”结论，仍只交付逐张中文图生图分镜提示词。

## 进入下一步的条件

商品主体、目标SKU/状态、用户采用的卖点与素材边界已经明确，且没有会误导购买的冲突时，才读取图片需求和输出对象规则。若只是缺少非关键资料，按用户选择跳过或降级，不重复追问；若主体或SKU仍不成立，只问一个最小关键问题。
