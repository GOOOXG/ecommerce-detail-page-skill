# 预构建候选图型导航

本文件只在商品卡确认前使用，帮助AI快速发现值得让用户选择的图片方向。它不是完整图型库，不在这里确定最终对象、数量、结构、顺序或正式分镜。商品卡和输出范围确认后，再读取 [image-set-planning.md](image-set-planning.md) 做证据淘汰、必要时定量排序、新增价值去重和图组编排。

## 使用方法

1. 先从全部有效参考视觉识别商品形态、核心对象、SKU/版本、状态和证据边界。
2. 从下面导航中选择与当前买家问题有关的类别，不按行业名整套套用。
3. 每个候选只写：解决什么问题、需要什么证据、怎样画、怎样生产、缺资料时如何降级。
4. 简单且资料充分时只显示首推和真正会改变分镜的少量备选；复杂任务通常显示3–5项。
5. 导航是发散起点，不是上限。若关键买家问题没有合适类别，可以提出商品专属新图型，但仍接受同样的事实、风险和生产检查。

## 十三类发现入口

| 候选类别 | 优先发现的问题 | 预构建时先找的依据 |
|---|---|---|
| 商品标准呈现 | 用户能否一眼认出商品、包装和真实到手外观 | 清晰主体、真实颜色、包装版本、配件和可用机位 |
| 结构拆解 | 价值是否藏在内部层级、连接、装配或核心部件 | 拆解实拍、工程图、可靠三维或适用隐藏视图证据 |
| 细节质感 | 哪个局部最能支撑做工、品质和定价 | 足够分辨率的纹理、边缘、接口、缝线或工艺局部 |
| 功能验证 | 抽象卖点能否变成可观察、可复核的证据 | 真实测试、说明、工作状态、条件、数值与安全边界 |
| 参照认知 | 用户是否难以理解尺寸、容量、重量或空间关系 | 准确尺寸、参照物、人体/空间比例和容纳关系 |
| 选择适配与防错 | 用户最容易买错哪个SKU、尺寸、接口、版本或套装 | 每个SKU独立资料、差异字段、兼容清单和不适用边界 |
| 使用教学与维护 | 用户是否担心不会装、不会用、不会清洁或更换 | 说明书、步骤、部件、工具、动作顺序和安全限制 |
| 场景呈现 | 谁在何时何地怎样使用，场景能否建立尺度与代入 | 真实使用关系、空间、人物动作、接触和必要道具 |
| 创意视觉 | 商品自身哪个特征能形成专属记忆而不改写事实 | 独特轮廓、材质、颜色、动作、品牌资产或可证实利益 |
| 组合包装与到手 | 用户是否关心收到什么、数量、赠品、补充装或包装层级 | 对应售卖版本、清单、数量、标配/选配/赠品条件 |
| 信任背书与来源 | 哪个客观证据最能降低真伪、品质或服务顾虑 | 有效资质、检测、授权、来源、真实用户许可或服务条款 |
| 利益与行动 | 是否有真实价格、优惠、权益、活动或下一步入口 | 平台、地区、时间、条件、数量和当前有效活动资料 |
| 数字权益与服务交付 | 用户如何理解权益、真实体验、发放/预约和服务边界 | 真实界面、权益页、流程、交付状态、授权和有效条款 |

## 主动补漏问题

完成初筛后再问一遍，不需要逐项向用户输出：

- 是否还有会导致认错、买错、装不上、不会用或收到后预期不符的问题？
- 是否缺少能把核心卖点变成画面证据的资料？
- 是否需要真实尺度、空间、人体、接口、到手内容或版本差异帮助理解？
- 是否存在清洁维护、收纳携带、耗材更换、交付激活、退款取消或异常处理顾虑？
- 是否有商品独有而非类目通用的视觉记忆点？
- 这个候选除“好看”外，是否增加事实、证据、选择帮助、场景理解或顾虑解法？

答不出最后一个问题的候选不进入建议卡。候选需要补拍、建模、真实证据像素或后期排版时，必须同时写明，不能包装成可以立即生成的现成分镜。
