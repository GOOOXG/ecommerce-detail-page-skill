# SKU图场景系统

本文件只负责SKU图场景。张数读取执行模块的范围合同。

## 目标

SKU图目标是降低选错风险，清楚展示规格、颜色、型号、容量、套装、尺码或适配关系。

## 子场景

1. SKU总览场景：所有可选项统一排列，清楚显示差异。
2. 规格对比场景：尺寸、容量、型号、功率、数量等理性字段对齐比较。
3. 颜色/款式场景：同款不同色、不同版型、不同材质需要统一角度和光影。
4. 套装组合场景：单件、组合装、补充装、配件包关系清楚，不制造虚假赠品。
5. 适配防错场景：适配机型、人群、空间、宠物体重、尺码等边界明确。

## 执行规则

- 正式设计前读取 `structure-selection.md` 的SKU图结构合同；未发布时停止，不在本文件重新判断或切换结构。
- 递进式主次结构的SKU信息不得重复：每张只解决一个选型问题，按“总览 -> 差异 -> 适配 -> 防错/套装”的顺序拆开；未知或不准确字段自动跳过并删除，不得写待确认或为了递进而编造规格。
- 等量并列结构不要求递进，但每张独立SKU图必须从不同SKU、不同规格、不同适配场景或不同防错角度展开，并保持同一视觉系统。
- SKU图优先保证信息准确和对比清楚，不追求过度视觉冲击。
- 所有SKU使用统一视角、光影、比例、标签样式和排序规则。
- 没有准确值的规格自动跳过，不得进入分镜说明、源码块或消费者文案；用户中途补充后，先更新商品卡，再定向重算引用该规格的SKU图。
- 不得把不同颜色、型号、容量、口味、尺码或套装关系混在一起。
- 图内文案以“规格名 + 差异点 + 适配建议”为主。
- SKU不确定时先做“SKU上下文卡”：列出已知SKU、未知SKU、可能混淆项和需要用户确认的字段，再进入分镜。

## 素材槽位

SKU名称槽、差异字段槽、规格参数槽、适配范围槽、防选错提示槽、套装关系槽、真实产品对齐槽。

## 组内角色

- 递进式主次结构：按实际任务写“SKU总览图、规格对比图、型号识别图、套装关系图、适配防错图”等语义角色。
- 等量并列结构：每张都写“独立SKU图”，并保持统一视角、标签、字段和比较逻辑。
- 混合结构：总览、对比和防错页使用语义角色，独立SKU页写“独立SKU图”，并保持同一字段和比较系统。
- 不得输出机械编号式组内角色；必须使用能说明本张选型任务的语义角色。
