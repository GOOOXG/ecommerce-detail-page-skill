# 转化框架系统

本文件只负责十类转化框架、框架组合公式、输出映射、策略合成和分镜表达规则。

## 目录

`转化框架库` / `框架组合公式` / `模型到框架映射` / `定价与促销表达路由` / `策略合成` / `AI框架选择算法` / `自动推荐接口` / `下游表达规则` / `禁止`

## 转化框架库

每张图只选择1个主框架，最多补1个辅助框架；不要把多个框架堆进同一张图。

### 框架一：首屏截停

目标：让用户在前三秒知道“这和我有关、值得继续看”。

技法：认知反差、强对比展示、隐形问题可视化、精准圈层喊话、悬念钩子、情绪共鸣。

### 框架二：痛点递进

目标：让用户意识到“我确实需要解决这个问题”。

技法：SPIN递进、隐形风险提醒、沉没成本警醒、旧方案问题盘点、懒人省心路径。

### 框架三：竞品差异化

目标：阻断“随便买一个都一样”的比价心智。

技法：行业信息清单、伪概念识别、USP独特主张、盲测/雷达对比、缺陷图鉴。

### 框架四：感官转译

目标：把抽象参数、功能和工艺变成用户能看懂的画面。

技法：FABE利益前置、剖面透视、流体/阻尼捕捉、解压瞬间定格、五感通感、微观放大镜、悬浮展示。

### 框架五：场景穿透

目标：让用户在多个真实场景中想象自己会使用它。

技法：全天候/全空间、极端条件测试、圈层语言、特殊人群适配、独处经济、办公解压、生态搭配。

### 框架六：合规信任

目标：用真实证据降低用户防备。

技法：销量/榜单墙、证据链、研发过程、UGC真实图鉴、专家证言、坦诚边界、第三方测试。缺失证据时自动跳过对应技法。

### 框架七：价值解释

目标：让用户理解“为什么值得买”。

技法：比例/绝对值表达、跨界锚点、时间折现、生命周期平摊、阶梯对比、隐形成本对冲。

### 框架八：情绪溢价

目标：让产品不只解决功能问题，也提供情绪价值和身份表达。

技法：礼赠包装、东方美学/在地文化、价值观表达、环保承诺、品牌初心。

### 框架九：行动促进

目标：给用户一个清楚、低阻力、合规的下一步。

技法：限时机制、阶梯赠品、默认选项助推、损失提醒、轻量行动阶梯。活动必须有依据。

### 框架十：顾虑兜底

目标：在用户下单前处理最后的风险感。

技法：顾虑分层、选型防错、零风险承诺、期望值管理、开箱惊喜、会员锁客、参数留白。

## 框架组合公式

- 点击型：首屏截停 + 感官转译 + 价值解释。
- 证明型：痛点递进 + 感官转译 + 合规信任。
- 选型型：场景穿透 + 顾虑兜底 + 价值解释。
- 高客单型：合规信任 + 价值解释 + 情绪溢价 + 顾虑兜底。
- 种草型：场景穿透 + 情绪溢价 + 首屏截停。
- 促销型：价值解释 + 行动促进 + 顾虑兜底。
- 复购型：场景穿透 + 价值解释 + 行动促进。
- 教育型：首屏截停 + 痛点递进 + 感官转译 + 合规信任。
- 高信任型：合规信任 + 竞品差异化 + 价值解释 + 顾虑兜底。
- 情绪种草型：首屏截停 + 场景穿透 + 情绪溢价 + 行动促进。
- 防退货型：场景穿透 + 顾虑兜底 + 合规信任 + 期望值管理。
- 新品类破冰型：认知教育 + 感官转译 + 场景穿透 + 合规信任。

输出映射：

- 主图优先：首屏截停、感官转译、竞品差异化、价值解释、合规信任。
- SKU图优先：顾虑兜底、选型防错、场景穿透、价值解释。
- 海报优先：首屏截停、情绪溢价、场景穿透、行动促进。
- 产品素材图优先：不使用营销框架，只服务资产复用。
- 详情页优先：首屏截停、痛点递进、感官转译、场景穿透、合规信任、价值解释、顾虑兜底。

## 定价与促销表达路由

只有用户提供真实价格、活动、赠品、套餐或可验证权益时才启用；没有依据时自动跳过，或改为不依赖该字段的价值解释。

| 目标 | 优先表达 | 使用边界 |
|---|---|---|
| 降低贵感 | 生命周期平摊、使用频次换算、隐形成本对冲 | 不虚构使用寿命、节省金额或竞品价格 |
| 强化划算 | 真实折扣、赠品价值、套装权益 | 不编造限时、前N名、平台补贴 |
| 引导套餐 | 折中效应、默认推荐、适配人群分层 | SKU必须真实存在，推荐理由必须可解释 |
| 解释高价 | 价格-质量信号、工艺证据、服务兜底、品牌资产 | 高客单不做低价牛皮癣，优先留白和证据 |
| 提升行动 | 目标梯度、轻量行动阶梯、领券/加购/咨询 | 行动入口要合规且不制造虚假紧迫 |
| 防止促销伤品牌 | 赠品优先、会员权益、长期价值 | 高频促销会降低参考价格，谨慎用于高端品 |

## 策略合成

每次策略输出必须合成5层：

1. 模型层：用哪个购买路径和销售表达模型。
2. 心理层：解决买家的什么渴望、防御或顾虑。
3. 证据层：当前有哪些准确参数、实测、报告或用户反馈可直接使用；没有准确依据时删除对应证据组件。
4. 视觉层：建议放在哪一类页面、哪个顺序、用什么画面证明。
5. 框架层：每张图优先调用哪个转化框架，避免框架堆叠。

## AI框架选择算法

内部按以下规则选择，不把算法全文输出给用户：

1. 先判断购买阶段：不知道产品用“首屏截停/认知教育”；知道但不信用“合规信任/感官转译”；想买但犹豫用“价值解释/顾虑兜底”；准备买用“行动促进”。
2. 再判断购买阻力：看不懂用感官转译，怕买错用顾虑兜底，怕贵用价值解释，怕没效果用合规信任，怕不适合用场景穿透。
3. 再判断输出对象：主图重截停，SKU重选型，海报重情绪和行动，详情页重路径完整，素材图重资产复用。
4. 再判断证据强度：证据充足可上信任和对比；证据不足只做不依赖缺失字段的场景、结构和利益表达，并删除强背书组件。
5. 最后控制密度：一张图只解决一个购买问题；框架冲突时保留更接近用户当前目标的框架。

标准和轻量任务只输出首推框架组合、关键理由、页面主线和可修改位置。深度、脑暴或用户明确要求10条时，才按产品身份、行业路径、平台投放、页面主线、购买路径、卖点表达、转化框架、视觉美学、证据合规、行动收口输出10条建议。

深度建议每条包含：建议内容、阶段性质、构设方式、适配理由、推演依据、页面落点、事实与合规风险、是否建议采用。推演依据可以出现模型名，但建议内容必须是中文可执行方案。

## 自动推荐接口

交给 `reasoning-engine.md` 的营销结论必须包含：

- 主购买路径：1个。
- 购买路径阶段演练：每个阶段的用户心理、页面任务和画面构设。
- 销售表达组合：2到4个。
- 卖点表达阶段演练：特征、优势、利益、证据如何落到页面。
- 业务模型组合：1到3个。
- 心理模型组合：1到3个。
- 主转化驱动力：1个，必要时补1个次驱动力。
- 主要人群心理：1到2类。
- 买家任务：1句话。
- 产品经理判断：核心价值主张、最大流失风险和页面验收标准。
- 内容编排主张：一句主张、视觉锤、证明方式和行动收口。
- 转化框架组合：3到7个，按页面顺序排列。
- 定价促销策略：价值解释、真实活动、套餐引导或不启用。
- 页面主线：一句话说明从第1张到最后一张的转化逻辑。
- 关键证据缺口：最多5项。
- 实验建议：主图、标题、卖点或场景中最值得A/B测试的1到3项。
- 可修改位置：购买路径、框架组合、转化驱动力、页面主线、行动收口。

自动推荐输出不得要求用户理解模型名，必须把模型翻译成可执行话术。

## 下游表达规则

主框架、辅助框架、核心购买阻力、证据方式和行动方向只写入营销工作包，用于决定逐张任务、信息顺序、正式文案和视觉承载。最终分镜不得出现模型名、转化框架字段、推导过程或行动方向，只保留经事实闸门通过的最终成图内容。

## 禁止

- 不把模型名当成页面文案直接上图。
- 不用未经证实的数据、排行、认证或评价制造信任。
- 不为追求转化制造不实恐惧、医疗化暗示或夸大承诺。
- 不让一个页面同时承担太多模型任务。
