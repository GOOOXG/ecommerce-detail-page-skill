# 交互引擎

本文件只负责理解用户输入、识别输出对象和模式、组织必要确认、解释数字回复和显示轻量状态。不负责动作排序、专业推演、返修执行、视觉规则或最终分镜；下一步动作统一读取 `next-action-engine.md`。

## 输入转译

先把自然语言压缩为：

- 用户动作：新建、继续、选择、补充、返修、审查、直出、研究或保存。
- 输出意向草案：用户显式点名的主图、SKU图、海报、产品素材图、详情页、组合、数量和用途；商品信息确认前不建立范围合同。
- 数量：按素材组记录；未指定交给输出规则。
- 结构：递进式主次、等量并列、混合结构、单张闭环、采用推荐或自定义。
- 商品信息确认：确认整卡、修改身份、修改视觉特征、新增准确事实或自定义纠正。
- 综合方案：方案编号、采用首推、局部组合或自定义方向。
- 模式：智能推荐、逐图确认、全自动、半自动、直出、通版、深度、返修或脑暴。
- 产品线索：名称、品牌、型号、用途、图片、卖点、参数和参考风格。
- 显式约束：平台、画布、字体、颜色、禁止元素、事实和证据。
- 最关键缺口：只保留会影响当前阶段的一个问题。

可合理推断的内容先形成首推；只有影响真实性、合规或产品一致性时才追问。

用户未指定模式时写入“智能推荐”：AI先建立商品文档草案并完成对话确认，再展示设计需求预判卡并确认输出对象，随后依次输出结构选择卡和综合方案选择卡；四项确认后完成图组编排与逐图设计。

## 输出意向解析

| 命中词 | 输出对象 | 数量处理 |
|---|---|---|
| 主图、首图、列表图、搜索图、点击图、商品卡、直播入口图、短视频封面 | 主图 | 用户可指定；否则读取范围合同默认数量 |
| SKU、sku、规格图、颜色图、款式图、型号图、套装图 | SKU图 | 用户可指定；否则读取范围合同默认数量 |
| 海报、活动图、种草图、直播海报、私域海报、社媒图、内容流图 | 海报 | 用户可指定；否则读取范围合同默认数量 |
| 详情页、详情图、长图、分屏详情 | 详情页 | 用户可指定；否则系统推演 |
| 素材图、白底图、透明图、无字场景图、产品场景素材 | 产品素材图 | 用户可指定子类型/张数；否则读取范围合同默认数量 |

商品合同发布前，单一或多个对象命中时只写入输出意向草案，不直接建立范围合同，也不加载对象专属场景。只有“全部设计/全套/所有类型都做”等明确范围指令才把“全部”写入意向草案。

产品素材图未指定子类型时只记录“产品素材图意向”，不虚构子类型；明确只说白底、透明或无字场景时，草案只记录被点名子类型和用户指定数量，不自动补齐其他子类型。

用户只上传图片、只给商品信息或只说“设计一下/做图”且没有输出对象时，不先询问做哪类图。先完成商品识别、卖点参数体检和商品卡信息识别内容；只有商品信息库确认后，才展示：

```text
【设计需求预判卡】
- 已确认商品：[名称、品类、商品关系和核心视觉锚点]
- 用户原始设计意向：[仅在已捕捉到对象、数量或用途时显示；否则删除本行]
- 买家任务与主要阻力：[只写结论和依据]
- 主图可能职责：[适用条件、可承载信息、现有素材基础、主要风险]
- SKU图可能职责：[基于现有准确字段判断适用条件、选型/规格任务和主要风险；无准确SKU关系时说明当前不启用，不列缺失字段]
- 详情页可能职责：[基于现有准确事实判断需要解释的决策链、可用证据和主要风险]
- 海报可能职责：[传播场景、主题空间、活动事实边界、主要风险]
- 产品素材图可能职责：[白底/透明/无字场景的复用价值和当前图片可用性]
- 人物使用潜力：[是否适合手部、局部、半身、全身、人像或第一视角，以及人物能证明什么]
- 组合关系：[哪些对象共享商品合同，哪些信息不能重复，哪些对象当前没有充分依据]
- 说明：以上是LLM根据商品做出的设计需求预判，不替代你的真实业务需求。

请选择实际要设计的内容：
1. 主图：可同时指定张数、平台和投放位置
2. SKU图：可同时指定张数、型号、规格或套装关系
3. 详情页：可同时指定页数、平台和决策深度
4. 海报：可同时指定张数、渠道、主题或活动目的
5. 产品素材图：可选白底、透明、无字场景及张数
6. 全部设计：按素材组分别编排，共享商品合同与品牌约束
7. 自定义组合：直接输入对象、张数、用途和优先级
```

预判卡必须覆盖所有可能对象，不用“AI建议做详情页”之类的单项结论代替需求地图。用户原始输入已明确对象时，在对应项标记“已捕捉需求”，仍让用户确认、增减或组合；用户回复“默认/都做”时才选择全部设计。用户回复“继续”时推进当前任务，不把“继续”解释为全部设计。若预判卡可见且用户原始意向明确，“继续”确认原始意向，否则要求选择对象。

## 商品信息确认输入

- 新商品文档草案形成后，读取 `product-dossier.md` 并展示商品卡信息识别内容；信息不完整时，事实字段之后给出3到5项跨主图、SKU图、详情页、海报和素材图统筹得到的高价值可选补充建议。资料已经充分时不为凑数制造建议；卡片未确认时不进入设计需求预判。
- 商品卡使用`0`到`9`动作：`0`执行当前AI首推；`1`确认当前准确字段并跳过未补充建议；`2`修改商品身份；`3`修改视觉特征；`4`补充最高价值建议；`5`批量补充或自由新增准确字段；`6`删除或禁用；`7`增加图片与资料来源；`8`调整建议范围；`9`自定义。用户可一次补充多项，也可只补一项。
- “确认、正确、没问题、继续”仅在没有未解决关键冲突时等同于`1`；不能把推断候选或补充建议自动升级为事实，未补充建议必须关闭对应卖点和设计组件。
- 选择`2`到`5`或自然语言修改后，更新草案并完整重发确认卡；新卡再次确认前不得继续。
- 用户只选择中置信Top3候选时，先重建该候选对应的商品文档和信息卡，不视为确认整卡。
- 用户明确声明所给完整结构化资料准确且图片无冲突时，可输出确认摘要并直接发布商品合同；仅说“直接出”不满足此条件。
- 商品信息确认菜单可见时，`0`到`9`优先绑定该菜单；确认或重建后旧菜单失效。
- 商品卡信息识别内容确认后，把已补充准确值写入商品合同，把其余建议写入跳过字段清单并关闭对应卖点与组件，再进入设计需求预判与范围确认，不直接进入结构选择或逐图设计。

## 输出对象确认输入

- 设计需求预判只允许读取状态为“已确认”的商品信息库，不得在商品卡前生成。
- 用户从预判卡选择对象、组合和数量后建立正式范围合同；数量未指定时才读取范围合同默认值。
- 用户原始要求已明确对象和数量时，确认商品卡后仍展示紧凑预判卡，并把原要求标为“已捕捉需求”；用户确认原意向后直接发布范围合同，不重复要求输入相同信息。
- 用户修改输出范围只影响范围合同及其下游，不反向修改商品事实；若修改内容包含新型号、适配或参数事实，先返回商品卡信息识别内容。
- 输出对象确认菜单可见时，数字只绑定当前1到7项；范围合同发布后菜单立即失效。

## 结构选择输入

- 主图、SKU图、海报或详情页数量大于1且用户未明确结构时，商品合同和范围合同均为`RELEASED`后读取 `structure-selection.md` 并展示结构选择卡。
- `1`、`2`、`3`分别选择递进式主次、等量并列、混合结构；`4`采用系统首推；`5`进入自定义结构。
- 结构卡可见时，数字优先绑定结构菜单，不解释为单图确认或其他历史菜单。
- 用户说“递进式、每张逐步讲、主次结构”时直接采用递进式；说“每张都当主图、独立投放、等量设计”时采用等量并列；说“前几张递进、后几张测试/独立”时采用混合结构。
- 用户回复“继续、采用推荐、你来选”时等同于选择`4`，但必须显示已发布结构和一句下游影响。
- 单张自动采用单张闭环；产品素材图默认资产角色并列，不展示三选一。
- 多输出对象支持`主图1，SKU2，海报3，详情页3`或“全部采用推荐”；未选择组保持“尚未选择”，不开始设计。

## 综合方案输入

- 结构合同发布后，智能推荐、半自动、逐图确认、深度和脑暴模式展示5个综合方向；`1`到`5`选择对应方向，自然语言要求用于自定义或组合。
- 用户回复“采用推荐、你来选、继续”时采用系统首推，并显示已发布方向的一句话定位和对后续编排的影响。
- 用户可以回复“以方向1为主，使用方向4的视觉”进行局部组合；AI必须检查人群、卖点、证据和视觉是否冲突，再写入一个合并后的方向合同。
- 用户已在原始要求中明确目标人群、核心卖点、场景和风格时，不重复展示5个方案；只输出方案确认摘要，并按当前模式推进。
- 方向合同发布后，旧方向菜单立即失效；返修综合方向时读取 `repair-engine.md` 计算受影响单图。

## 模式识别

- “自动推荐、你来推演、先推荐让我选”：智能推荐，先确认商品信息，再确认输出对象、结构并从5个综合方案中选择，随后逐图确认。
- “全自动、你直接完成”：全自动，除硬性阻塞外自主推进；若同时说“让我选”，按智能推荐处理。
- “每步确认、一步步来”：半自动，但仍使用合并确认，不逐字段盘问。
- “逐张确认、一张一张来、每张确定后继续、先看第1张”：逐图确认。
- “直接出、不要再问、只要提示词”：直出。
- “通版、快速样板、不细化参数”：通版。
- “深度研究、完整推演、专家分析”：深度。
- “脑暴、更多方向、10条建议”：脑暴。
- “返修、改第2张、只改文案/风格”：返修。

模式冲突时优先级为：明确返修 > 明确直出 > 明确选择/确认方式 > 深度或脑暴 > 默认智能推荐。

## 数字与自然语言

- 数字只在最近一次可见选项中生效，不使用跨阶段永久编号。
- `1`、`2` 等短回复必须结合当前选项和任务状态解释；没有可见选项时不得猜测旧菜单。
- “返回/重选/修改”回到最近受影响合同或草案；“返修第2张”只修改当前素材组第2张。
- “SKU”和“sku”不区分大小写；品牌、型号和产品原文保留原始大小写。
- 用户自定义输入优先于候选编号，并转成结构化合同候选。
- 当前存在待确认单图卡时，“继续、确认、可以、下一张”只确认当前图并推进一张；不会确认整组或跳到全部设计。
- `1-全部`、“剩余自动完成”或“后面直接出”才切换剩余图片为自动确认。
- `2-1`到`2-10`优先解释为当前单图字段返修路径，具体字段读取 `frame-confirmation.md`。
- 菜单优先读取当前阶段和最近一次可见菜单：商品信息确认、设计需求预判/输出对象、结构、综合方案、单图、画布/专项选择、普通导航互斥生效；不能跨阶段猜数字。

## 用户行为判断

| 行为 | 推断 | 交互处理 |
|---|---|---|
| 确认、纠正、新增或补充商品信息 | 希望保证商品事实和使用边界正确 | 更新商品文档；自动跳过不准确字段，只有整卡明确确认后发布商品合同并进入设计需求预判 |
| 选择、增减或组合输出对象 | 希望确定真实设计任务 | 以已确认商品卡为基础更新范围合同；不把AI预判当成用户命令 |
| 连续确认、短数字、继续 | 希望提速 | 商品卡信息识别内容先完成确认；单图节点确认当前张并展示下一张；其他节点采用首推推进，不重复解释 |
| 选择或重选结构 | 希望控制图组逻辑 | 更新结构合同；未设计时进入策略编排，已有单图卡时先计算失效范围 |
| 选择或组合综合方向 | 希望控制人群、卖点、场景或风格 | 更新方向合同；只把确认后的方向展开为逐张任务 |
| 要更多、脑暴、差异化 | 希望扩展 | 给10条候选，聚类后首推1条 |
| 连续修改同一处 | 当前合同或草案不稳定 | 暂停扩展，重建对应合同或草案并给3个修正方向 |
| 补参数、证书、型号、平台 | 希望提高真实性 | 商品事实先更新草案并重新确认；平台偏好写入范围合同，确认后只重算受影响页面 |
| 更高级、更真实、更能卖 | 结果不满意但表达模糊 | 转成专业动作并调用对应视觉、证据、营销或文案模块 |
| 只要提示词、不要再问 | 希望直出 | 切换直出，非阻塞缺口直接删除相关字段和组件，只用现有准确事实推进 |
| 质疑产品识别 | 商品合同失效 | 回到产品分析，不继续分镜 |

用户在任何阶段新增准确字段时，先更新商品文档并重发商品卡信息识别内容；确认后只重算引用该字段的输出。只有字段名没有值时询问一个具体值，不创建空字段。

## 确认策略

- 半自动采用“商品信息确认 + 设计需求预判与输出确认 + 结构选择 + 综合方案选择 + 逐图确认”：先保证商品事实正确，再让用户决定实际设计任务，之后合并确认专业方向，不拆成逐字段问卷。
- 逐图确认不是逐字段盘问；AI先把当前图全部推演完成，再让用户整体确认或定向返修。
- 全自动不要求用户理解模型或逐项选择，但新商品信息仍需一次确认；已明确声明准确的完整资料可用确认摘要直接发布商品合同。
- 直出、通版不展示10条方案；脑暴或关键决策才展示10条。
- 已确认的对象、张数、画布、字体和风格不重复询问；用户原始点名对象在商品卡确认前只是意向，不算已发布范围合同。
- 连续两次简短确认后，跳过非必要发散并进入下一可执行阶段。
- 连续确认只压缩解释，不跳过下一张单图确认卡；用户明确切换剩余自动完成时才停止逐张展示。

## 轻量状态

仅在分步交互或阻塞时显示：

```text
【详情页生成引擎 运行中】
- 进度：[阶段]
- 主体：[名称/待识别]
- 商品信息库：[草案/待确认/已确认/已失效/阻塞]
- 输出：[意向待确认/对象与数量]
- 状态：[可继续/待确认/需补充]
- 当前图：[第n张/共m张；草案/待确认/已确认/返修中]
- 图组结构：[待选择/递进式主次/等量并列/混合结构/单张闭环]
- 综合方案：[待选择/方案名称/用户自定义]
```

直出和最终交付不重复状态面板。

## 输出接口
