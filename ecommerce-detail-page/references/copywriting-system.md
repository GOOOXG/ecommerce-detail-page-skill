# 文案推演系统

本文件只负责把产品事实、营销策略和页面任务转成差异化电商文案，并完成候选生成、证据校准、跨页编排、语义去重和返修。不负责产品识别、营销模型选择、视觉规范或最终分镜格式。

## 目录

`启用时机` / `输入接口` / `命题推演链` / `正式营销文案准入` / `文案策略工作包` / `页面文案矩阵` / `素材类型表达策略` / `候选生成与择优` / `中文文案质量规则` / `语义去重与连续性` / `文案审稿循环` / `反馈进化` / `返修规则` / `输出接口`

## 启用时机

- 主图、SKU图、海报或详情页需要图内文案、文案包、标题优化或卖点重写时读取。
- 商品合同必须为`RELEASED`；文案不得使用草案中的推断候选、冲突字段、自动跳过字段或无准确来源的强主张。
- 用户反馈文案重复、空泛、生硬、不像人话、不够能卖或缺少递进时读取。
- 产品素材图默认不读取；无字场景图禁止调用文案生成。
- 最终分镜前，只要包含文案包，就必须生成已裁决文案工作包并通过本文件检查。
- 多张主图、SKU图、海报和详情页必须先发布结构合同与方向合同；任一合同未发布时不得建立页面文案矩阵。

## 输入接口

只接收上游确认摘要，不重新运行完整营销分析：

- 产品事实：产品名、品牌/型号原文、结构、材质、用途、已确认参数。
- 卖点分层：已确认、可观察、合理推断、自动跳过、禁用表达。
- 用户洞察：买家任务、真实渴望、主要顾虑、使用场景和语言习惯。
- 营销任务：购买阶段、转化驱动力、页面主线、当前图唯一购买问题。
- 输出约束：素材类型、图序、组内角色、平台、客单价、品牌语气和字数限制。
- 证据状态：实物图、参数、报告、评价、销量、活动和售后依据。

## 命题推演链

先构建内部“事实到表达”链，不把完整推理链展示给用户：

`产品事实 -> 使用任务 -> 用户阻力 -> 可感知利益 -> 证明方式 -> 情绪结果 -> 当前行动`

每张图只从链中选择一个核心命题。核心命题必须回答：对谁、解决什么、凭什么、看完做什么。信息不足时缩短链路，不用形容词补洞。

### 证据与措辞等级

| 等级 | 依据 | 可用表达 | 禁止表达 |
|---|---|---|---|
| 已证实 | 用户明确提供或图片清晰可见 | 直接陈述事实，可写明确参数 | 超出依据的效果、因果和比较 |
| 可观察 | 结构、颜色、形态、接口等可直接观察 | “可见、采用、呈现、便于识别”等客观描述 | 推导寿命、性能、安全或功效 |
| 合理推断 | 符合品类常识但无专属证据 | 只用于后台选择人群、场景、语气、构图和信息顺序 | 进入最终上图文案、卖点、参数、功效、适配或证据表达 |
| 自动跳过 | 型号、适配、参数、认证、销量、活动等没有准确依据 | 从商品卡、分镜说明和图内文案中删除；用户后续补充后再恢复 | 保留占位、主动追问或作为确定文案上图 |
| 禁用 | 与图片冲突、违法违规或无法证明 | 删除或改成事实边界提示 | 任何形式的变体、暗示和视觉伪证 |

无法证明的商品字段自动跳过，不进入文案。页面可改用准确结构、真实场景或其他已有事实，但不得把替代表达伪装成原卖点证据，也不得使用模糊词把推断包装成可上图卖点。

## 正式营销文案准入

- 最终上图文案只使用用户明确确认、可靠资料明确记载或商品图片直接可见的事实。
- 每条主标题、副标题和核心卖点在后台绑定来源字段；来源缺失、冲突、过期或不足以证明当前措辞时整条淘汰。
- 品类常识、买家心理和营销模型只用于寻找表达角度，不得升级为产品属性、性能、功效、适配或证据。
- 删除无依据文案后同步删除关联标签、图标、数字、对比和视觉暗示，再用已有事实重新平衡信息层级。
- 事实不足时减少文案或生成无新增文字的正式画面，不用“可能、大约、预计、或许、疑似、建议、仅供参考、待补充”等措辞填空。

## 文案策略工作包

生成单句前，先确定整组文案策略：

- 一句话价值主张：全组最想让买家记住什么。
- 目标读者：当前最值得优先说服的人群，不做无边界喊话。
- 语言人格：专业克制、清晰务实、温和生活、审美悦己、轻快促销等，只选一个主语气。
- 关键词资产：产品名、核心品类词、一个记忆词、必要型号原文。
- 禁用词组：无依据承诺、空泛大词、重复高频词、平台和行业风险词。
- 信息密度：根据素材类型、平台、客单价和移动端阅读距离决定。
- 叙事关系：递进式、等量并列、混合结构或单张独立。

品牌原文和型号原文允许按识别需要重复；概念、利益和句式不得机械复用。

## 页面文案矩阵

逐张建立矩阵后再写文案包：

| 字段 | 要求 |
|---|---|
| 图序/角色 | 对应真实图序和语义角色 |
| 心理阶段 | 注意、理解、欲望、信任、选型、行动或顾虑消除 |
| 唯一购买问题 | 本张只回答一个问题 |
| 核心命题 | 本张独占的利益、证据、场景或顾虑 |
| 文案角度 | 痛点、结果、机制、证据、场景、质感、身份、选择或行动 |
| 标题句式 | 陈述、提问、对比、指令、场景、数字、判断或留白式；相邻页不重复 |
| 副标题职责 | 解释对象、补利益、补场景、补证据或补边界，只承担一种 |
| 卖点职责 | 1到3条分别承担事实、利益、证据/边界；信息不足时宁缺勿凑 |
| 内部行动方向 | 只用于判断页面希望推动的心理阶段，不生成具体话术，不进入文案包或提示词 |
| 语义指纹 | 核心名词、核心动词、利益结果、证据类型、情绪词和句式 |

递进式按“识别 -> 相关 -> 理解 -> 相信 -> 代入 -> 选择/行动”编排；张数不足时合并相邻阶段，张数增加时扩展新证据、新场景或新顾虑，不复制旧命题。等量并列不强制阶段顺序，但每张语义指纹必须显著不同。混合结构先保证主链命题连续，再让独立变体使用不同人群、场景、平台或单一视觉变量；变体不得复写主链标题。

## 素材类型表达策略

- 主图：标题负责截停和识别，副标题只补一个购买理由；少术语、强主体、小图可读。递进图组逐张切换利益、结构、场景和防错任务。
- SKU图：先说差异和适合谁，再说选择动作；用准确标签和并列短句，不用情绪化夸张词代替规格。
- 海报：围绕一个主题写“情绪钩子 + 产品利益”；行动方向只在内部决定传播收口，平台语境可以变化，事实边界不能变化。
- 详情页：标题承担段落推进，副标题承担解释；前段短而强，中段证据具体，尾段清楚兜底，形成阅读节奏。
- 产品素材图：默认无营销文案；白底图和透明图只保留真实产品原文，无字场景图完全无字。

## 候选生成与择优

候选数量服从 `execution-engine.md` 的循环预算，不向用户展示无效草稿：轻量任务在命题清晰时可直接生成，存在歧义时生成2个候选；标准任务为关键标题生成3个不同角度候选；深度或返修任务为高影响页面生成3到5个候选。候选必须是不同命题或不同表达策略，不能只是同义词替换。

按以下维度内部评分并选择首推：

1. 相关性：是否直指当前买家任务和页面问题。
2. 具体性：是否有对象、动作、场景或可感知结果。
3. 可信度：措辞是否与证据等级一致。
4. 区分度：是否与相邻页面、竞品套话和旧版本明显不同。
5. 画面感：文字是否能与当前构图和视觉锤互相证明。
6. 清晰度：移动端一眼可懂，少术语、少绕句、主谓明确。
7. 品牌感：是否符合品类、价格带和已确认语气。
8. 合规性：是否避免绝对化、恐吓、虚假比较和无依据背书。

任一候选在可信度或合规性上失败，直接淘汰，不用总分补偿。

## 中文文案质量规则

- 先写用户得到的变化，再补产品如何做到；参数型页面可先给事实再解释意义。
- 用具体名词和动作替换“高端、升级、品质、实力、匠心、黑科技”等空泛词。
- 不重复用户已经知道的产品名；只有身份识别、搜索匹配或型号区分需要时保留。
- 标题只承载一个重音，副标题不改写标题，多条卖点不彼此释义。
- 保留自然汉语语序，避免堆砌四字词、伪专业术语、过度押韵和强行感叹号。
- 不把营销模型名写给消费者，不写“痛点、转化、赋能、用户”等后台术语。
- 消费者可见文案禁用“核对、确认、检查、查验、验证、自检、审核、待确认”等流程化措辞；改用“了解、看清、比较、选择、适配、咨询”等自然购物语言，无法自然改写时直接删除。
- 最终上图文案必须肯定、准确、单义；命中不确定措辞时回查来源，有准确值则改成事实，没有则删除整句及关联视觉。
- 文字必须能被对应画面证明；画面无法承载的文案改写或移到其他页面。
- 精确文字默认后期排版，图生图提示词只需预留文字安全区，避免依赖模型正确生成长文字。

## 语义去重与连续性

去重检查概念，不只检查字面：

- 相邻页面不得重复同一购买问题、同一利益结果或同一证据类型。
- 同一组内，标题核心名词、动词、句式连续重复时必须重写。
- 多条卖点若能互换顺序且含义不变，说明职责未拆开，必须删减或重写。
- AI内部行动方向随阶段变化，但不生成“立即购买、咨询客服、点击查看”等行动话术。
- 有意重复的品牌名、型号或主记忆词必须承担识别或记忆作用，并改变上下文职责。
- 递进组后一张必须新增信息；若只是在解释上一张同一句话，应合并页面或换新命题。

## 文案审稿循环

按 `loop-control.md` 的预算最多执行2轮：

1. 首轮生成：完成文案策略工作包、页面矩阵和候选择优。
2. 反向审稿：假设买家快速扫图，检查是否看懂、相信、记住且知道下一步。
3. 失败归因：标记为空泛、重复、错位、证据越界、语气冲突、信息过密或画面不可证。
4. 定向改写：只重写失败字段，保留已发布商品事实、页面任务和已经通过的文案。
5. 退出条件：每张唯一命题成立，证据匹配，语义不重复，字数适配，行动连贯。

连续两轮仍失败时，不继续堆文案：关键事实阻塞交付时在源码块外索取一个最小事实；非关键缺失直接删除相关主张，用准确事实完成画面。

## 反馈进化

用户采用、拒绝、删改或返修文案后，内部比较变化并更新当前会话文案工作包：

- 归因维度：语气强弱、信息密度、利益/证据偏好、句式、常用词、禁用词和行动方式。
- 采用内容：提炼可复用的表达原则，不机械复制原句。
- 拒绝内容：记录失败原因，后续候选避开同类空泛、重复、夸张或生硬表达。
- 局部返修：只更新受影响页面及其前后连续性，不重写已通过页面。
- 多次反馈：优先使用稳定偏好；新指令与旧偏好冲突时，以用户最新明确要求为准。

默认只在当前会话复用；用户明确要求长期保存时，才交给 `persistence-evolution.md`，不得声称模型已经自行训练或永久学习。

## 返修规则

- “文案重复”：重建语义指纹和页面矩阵，不只替换近义词。
- “不够能卖”：先判断缺的是相关性、利益、证据、价值还是行动，不默认加夸张词。
- “更高级”：减少口号和促销腔，增加材质、细节、留白和克制表达。
- “更直接”：保留核心利益和动作，删掉背景解释与抽象修饰。
- “更生活化”：改用真实场景、日常动作和用户口吻，不虚构评价。
- “返修指定图序”：保留其他页面已裁决文案，只检查新文案与前后页的关系。

## 输出接口

向下游只交付文案工作包摘要：

- 文案策略工作包。
- 页面文案矩阵。
- 每张首推文案包：主标题、副标题和1到3条核心卖点；行动方向仅作为内部页面推进变量，不进入文案包或最终提示词。
- 每张语义指纹和禁止重复项。
- 跳过字段清单及不依赖这些字段的安全替代表达；仅供内部依赖控制，不向消费者展示。
- 文案自检结果和受影响页面。

最终分镜格式仍由 `storyboard-template.md` 唯一负责。
