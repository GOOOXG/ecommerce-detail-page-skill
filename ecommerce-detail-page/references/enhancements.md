# 后台增强能力

只在任务复杂、多SKU、高风险、需要深度推演或用户明确要求多子智能体时读取本文件。增强能力必须服务商品判断和分镜提示词，不能形成第二套流程或额外交付。

## 最小子智能体团队

按问题选择最少角色，不为显示复杂度而增加人数：

| 角色 | 负责问题 | 必须返回 |
|---|---|---|
| 商品识别与证据 | 商品主体、SKU、状态、全部参考图怎样综合、事实边界是什么 | 内部证据追踪、按SKU分组的综合事实、识别置信度、冲突、各目标视图置信度 |
| 预构建与需求 | 哪些卖点、资料、素材和图片建议值得让用户选择 | 编号建议、缺口、可用素材、用户需要补充的准确内容 |
| 范围与结构 | 真正输出哪些对象、每组多少张、采用何种递进关系 | 预判卡摘要、分镜数量、平台/用途、结构首推与风险 |
| 图组策略 | 真正需要哪些图、每张解决什么、怎样避免重复 | 用户决策六维诊断、候选图、定量比较、必要图片清单、顺序与删除理由 |
| 视觉与提示词 | 每张怎样画、怎样写成可执行中文提示词 | 分镜字段、正向提示词、动态负面提示词、生产边界 |
| 独立审查 | 哪一处最可能不真实、不可执行或造成误购 | 失败位置、依据摘要、最小修复建议 |

事实冲突或高风险主张需要反证时使用独立审查角色；实际生图出现稳定失败时使用视觉与提示词角色。只有主控合并结论并向用户交付最终分镜。商品识别与预构建结论必须先进入用户可见的编号建议，不能由子智能体直接替用户确认。

### 按问题增配的专业角色

只有基础角色无法覆盖当前难点时才增配，不固定全开：

| 角色 | 触发条件 | 只回答的问题 |
|---|---|---|
| 全行业适配与买家任务 | 跨类目、陌生商品或输出对象很多 | 当前商品的高风险决策特征是什么，哪些是必需图片任务 |
| 选择适配与防错 | 多SKU、尺码、接口、车型、版本或套装复杂 | 用户最容易买错哪里，怎样用一张图清楚消除歧义 |
| 场景与人物关系 | 真实空间、穿戴、操作、人宠或情绪场景决定成败 | 谁在何时何地怎样使用，尺度、动作、接触和道具怎样成立 |
| 创意视觉与品牌记忆 | 需要差异化主图或海报，但不能牺牲商品真实性 | 哪个商品专属记忆点可被转成创意，除吸睛外增加什么决策价值 |
| 结构、测试与生产 | 涉及内部、机制、性能、复杂后期、三维或补拍 | 当前证据能做什么，最可靠的生产方式和降级方式是什么 |
| 类目合规与主张证据 | 功效、食品、健康、母婴、工业、安全、促销或证书敏感 | 哪个画面或文案缺直接依据，怎样删除、补证或安全改写 |

这些角色只提供主控需要的判断，不分别向用户输出报告。一个角色不能同时负责提出方案和最终独立审查同一方案；没有独立上下文时由主控执行对抗性复核并标记为内部降级。

## 委派方法

给子智能体最小必要资料：当前任务、相关参考图、已确认商品事实、要回答的一个问题和禁止越界项。不要把预期答案、主控评分或其他角色结论提前告诉独立审查者。

子智能体只返回结论、证据摘要、假设、风险和建议，不返回隐藏思考链。无法提供独立上下文时，由主控做第二遍对抗性自审，并如实视为降级，不冒充独立审查。

## 推演循环

所有关键判断统一使用 `SKILL.md` 的“证据观察 → 问题建模 → 发散候选 → 跨域组合 → 反证淘汰 → 收敛排序 → 阶段落位 → 缺口回看”循环，不再建立第二套步骤。预构建阶段只落位为编号建议；范围与结构阶段只落位为输出对象、数量、结构和方向；图组阶段只落位为必要图片清单；只有提示词阶段才把采用结论编译进最终分镜字段。比较图片候选时使用 [image-set-planning.md](image-set-planning.md) 的硬门槛、一百分排序和新增价值分；检查分镜与提示词时使用 [safety-and-quality.md](safety-and-quality.md) 的结构化清单，不再叠加额外评分。

反证要主动寻找串SKU、伪事实、低置信未知视图、重复页面、物理错误、文字重绘、指令冲突和不可生产点，并只修最早错误层。无法继续时改用补图、实拍、真实商品层合成、三维资料、概念稿降级，或询问一个关键问题。
