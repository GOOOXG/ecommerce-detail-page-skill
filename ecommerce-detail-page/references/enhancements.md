# 后台增强能力

只在任务复杂、多SKU、高风险、需要深度推演或用户明确要求多子智能体时读取本文件。增强能力必须服务商品判断和分镜提示词，不能形成第二套流程或额外交付。

## 最小子智能体团队

按问题选择最少角色，不为显示复杂度而增加人数：

| 角色 | 负责问题 | 必须返回 |
|---|---|---|
| 商品与参考图 | 商品是什么、参考图能证明什么、哪里会串款或越界 | 稳定索引、可见商品特征、参考职责、冲突、未知面 |
| 图组策略 | 真正需要哪些图、每张解决什么、怎样避免重复 | 候选图、定量比较、必要图片清单、顺序与删除理由 |
| 视觉与提示词 | 每张怎样画、怎样写成可执行中文提示词 | 分镜字段、正向提示词、动态负面提示词、生产边界 |
| 独立审查 | 哪一处最可能不真实、不可执行或造成误购 | 失败位置、依据摘要、最小修复建议 |

事实冲突或高风险主张需要反证时使用独立审查角色；实际生图出现稳定失败时使用视觉与提示词角色。只有主控合并结论并向用户交付最终分镜。

## 委派方法

给子智能体最小必要资料：当前任务、相关参考图、已确认商品事实、要回答的一个问题和禁止越界项。不要把预期答案、主控评分或其他角色结论提前告诉独立审查者。

子智能体只返回结论、证据摘要、假设、风险和建议，不返回隐藏思考链。无法提供独立上下文时，由主控做第二遍对抗性自审，并如实视为降级，不冒充独立审查。

## 推演循环

所有关键判断统一使用 `SKILL.md` 的推演循环，不再建立第二套步骤。比较图片候选时使用 [image-set-planning.md](image-set-planning.md) 的一百分排序和新增价值分；检查分镜与提示词时使用 [safety-and-quality.md](safety-and-quality.md) 的结构化清单，不再叠加额外评分。

反证要主动寻找串SKU、伪事实、未知面、重复页面、物理错误、文字重绘、指令冲突和不可生产点，并只修最早错误层。无法继续时改用补图、实拍、真实商品层合成、三维资料、概念稿降级，或询问一个关键问题。
