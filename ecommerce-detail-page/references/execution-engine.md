# 执行与决策内核

本文件是任务状态、风险、自主性、阶段、数量和模块调度的唯一来源。核心正式交付物是根据商品参考图推演出的逐张图生图分镜提示词；提示词发布后可按用户明确选择进入可选生图闸门。商业、运营、产品、营销、美学与多智能体结论只作为内部决策输入。

## 状态与合同词汇

全流程只使用任务、商品、参考图、范围、结构、方向、分镜槽位合同，以及原子配对的分镜发布版本和提示词发布版本。候选分析留在草案或工作包，只有正式合同状态能够推进流程。

合同状态统一为：`DRAFT / PENDING / RELEASED / INVALIDATED / BLOCKED`。只有`RELEASED`可被下游消费；状态变化必须记录负责人、来源、版本、影响范围和失效原因。

每个负责模块输出的合同必须携带同一版本信封：

```yaml
contract_id: stable-id
contract_type: TASK/PRODUCT/REFERENCE/SCOPE/STRUCTURE/DIRECTION/FRAME_SLOT/FRAME/PROMPT
contract_version: TC-001/PC-001/RC-001/SC-001/ST-001/DC-001/FS-001/FR-001/PR-001
status: DRAFT/PENDING/RELEASED/INVALIDATED/BLOCKED
owner: owner-module-or-main-controller
parent_versions: {upstream_contract: version}
source_trace: [user/image/file/decision identifiers]
updated_at: ISO-8601
invalidation_reason: optional
```

分镜与提示词信封还必须携带同一配对字段：

```yaml
release_pair: {frame: FR-001, prompt: PR-001}
source_artifact_id: frame-draft-001
```

分镜合同与提示词合同的`parent_versions`都精确绑定当前任务、商品、参考图、范围、结构、方向与分镜槽位，不把尚未发布的分镜合同作为提示词父依赖。两者使用相同`release_pair`和`source_artifact_id`，该标识必须解析到同一个未`STALE`的不可变分镜草案；草案的`input_contract_versions`使用同一精确集合并逐项等于当前发布库版本。两者只能在一次原子事务中同时从`PENDING`转为`RELEASED`，也必须在任一成员失效时使配对成员同步失效。

对已`RELEASED`配对的任何返修都创建新 FR/PR 配对，禁止单边升级：如果只修改提示词，分镜正文原样复制到新的`FR-nnn`；如果只修改分镜，未受影响提示词也必须基于新分镜重新检查并产生新的`PR-nnn`。旧 FR/PR 在新配对原子发布时同步转为`INVALIDATED`并保留追溯记录；“最小”只表示语义修改最小，不表示只更新一个版本信封。

分镜草案是分镜槽位已`RELEASED`后才物化的不可变产物，不是合同：它只包含从已`RELEASED`上游与分镜槽位派生的单图任务、最终画面、视觉和生产草案，携带`artifact_id`，并在`input_contract_versions`中精确记录任务/TC、商品/PC、参考图/RC、范围/SC、结构/ST、方向/DC与分镜槽位/FS，但不携带合同状态、不进入发布库，也不能被伪装成`RELEASED`分镜。为形成分镜槽位而使用的早期构想只叫“槽位前布局草案”，不得作为提示词输入。提示词编译器可读取版本仍为当前版本的分镜草案产物，但其合同父依赖只指向已`RELEASED`上游。

版本前缀是独立命名空间：`P0-P4`只表示参考图能力，`Q0-Q3`只表示发布问题严重度，`E0-E3`只表示偏好证据。任何工作包或分镜草案产物的`input_contract_versions`必须逐项复制实际信封版本；上游版本变化后，旧产物/工作包与下游合同转为`STALE/INVALIDATED`，不得原地替换版本。

## 核心原则

1. 先判断任务，再决定流程；不要把所有请求塞进同一条生产线。
2. 确认用于建立本技能固定的商品、范围、结构、综合方向和单图合同；风险与模式决定确认是显示给用户还是内部完成，不额外增加同义闸门。
3. 低风险未知项采用保守默认、明确假设或删除；只有影响身份、安全、合法性、适配或商用保真时阻塞。
4. 用户已明确的信息直接写入状态，不重复询问。
5. 先形成资产组合与组内职责，再逐张设计；返修回到最早错误层。
6. 下游只消费摘要，不重新展开全部上游材料。
7. 每个阶段都由循环控制“生成候选/批判/修复/放行”，最终提示词只读取已放行状态；不得用冗长提示词代替缺失事实，也不得用循环制造额外交付。

## 八个状态域

维护一份轻量任务状态；每个域拥有明确职责。

| 状态域 | 内容 | 唯一拥有者 |
|---|---|---|
| 任务 | 用户动作、交付目标、优先级、时限、自主性、当前游标 | 本文件 |
| 事实 | 商品身份、属性、素材、证据、来源、冲突、禁用项 | `product-dossier.md` |
| 需求 | 买家任务、情境、触发、阻力、选型风险、生命周期与机会 | `demand-opportunity-system.md` |
| 策略 | 主决策、价值主张、证据路径、渠道承接、差异支点与失败条件 | `strategic-intelligence.md` |
| 资产 | 输出对象、数量、结构、各资产职责、跨渠道承接与复用关系 | `asset-portfolio-system.md` |
| 创意 | 场景、文案、视觉栈、人物、空间、构图与品牌表达 | 对应营销/视觉模块 |
| 生产 | 输入资产、保真方式、生成/实拍/合成边界、提示词、待确认配对与发布库 | 制作/提示词/逐图模块 |
| 学习 | 分镜选择、返修、稳定偏好、禁区与适用范围 | `persistence-evolution.md` |

内部状态依赖固定为：

`任务 -> 事实 -> 需求 -> 资产范围/结构 -> 策略方案 -> 创意 -> 生产`

面向分镜的合同依赖为：

`任务（TC） → 商品（PC） → 参考图（RC） → 范围（SC） → 结构（ST） → 方向（DC） → 分镜槽位（FS） → 分镜发布（FR）+ 提示词发布（PR） → 进化记忆`

学习是全程旁路：任务开始读取适用偏好，选择/否定/返修后捕获差异，任务结束只强化最终采用项与有效修复。学习不得成为主链闸门，不得覆盖事实或自动确认任何阶段。

允许三类旁路：

- 明确的简单生产任务可压缩需求、策略与创意分析，但任务/商品/参考图/范围/结构/方向/分镜槽位合同仍按主链建立并发布；“直接进入”只表示不展开非必要报告或模块，不表示跳过合同。
- 页面诊断、返修或复盘可从现有资产进入对应状态域，只重算受影响下游。
- 偏好学习在各阶段提供首推调整和禁区，但不改变阶段顺序与合同状态。

禁止下游反向改写事实；新增事实必须回到事实域。禁止把学习域中的单次结果自动泛化为永久规则。

## 任务类型

| 类型 | 典型输入 | 最短合法路径 |
|---|---|---|
| 新建资产 | 做主图、详情页、海报、SKU或素材图 | 任务 -> 事实 -> 需求/策略按需 -> 资产 -> 创意 -> 生产 |
| 全部分镜 | 全套设计、跨平台、活动或品牌统一图组 | 完整八域，最终仍输出分组分镜提示词 |
| 分镜诊断 | 为什么这张图不对、帮我审查现有分镜 | 任务 -> 事实/现有图片 -> 最早失败域 -> 返修提示词 |
| 局部返修 | 改第3张、文案更具体、背景更真实 | 找最早错误域 -> 定向重算 -> 回归校验 |
| 图组探索 | 还能做什么图、还有什么场景、怎么差异化 | 事实 -> 需求 -> 策略 -> 候选图组 -> 分镜提示词 |
| 概念探索 | 脑暴、创意方向、概念稿 | 事实边界 -> 需求/策略 -> 创意；清楚标记非商用假设 |

## 风险等级

先定风险，再定确认强度。

| 等级 | 条件 | 行为 |
|---|---|---|
| R0 低风险 | 无字场景、概念方向、视觉风格探索，不含敏感主张 | 压缩可见交互；仍建立对应内部合同和假设摘要 |
| R1 常规 | 商品身份清楚、主张保守、普通电商资产 | 把用户已明确内容写入紧凑卡；交互模式确认、自动模式内部过闸 |
| R2 重要 | 多SKU、高客单、复杂参数、跨平台、强投放、品牌资产 | 确认会改变成本或策略的关键选择；运行经营与红队检查 |
| R3 高风险 | 医疗健康、母婴安全、食品功效、适配安全、资质、价格活动、授权/IP | 逐项验证相关事实；无法证明的主张删除或阻塞 |
| R4 阻塞 | 主体/型号冲突、合法性无法成立、素材不足以商用保真且无降级许可 | 只问一个解除阻塞的关键问题 |

风险是按“当前主张与交付”判断，不是按整个品类一刀切。医疗器械的纯白底保真图可以是R1；带治疗承诺的详情页是R3或R4。

## 自主性等级

| 等级 | 触发 | 行为 |
|---|---|---|
| A0 审查 | 用户只要分析/建议 | 不生成超出请求的正式资产 |
| A1 引导 | 默认、先推荐让我选 | 只确认高影响选择；默认首推+2备选 |
| A2 代办 | 全自动、你决定、直接做 | 除R4外自主完成，记录关键假设 |
| A3 共创 | 一步步、一张张确认 | 每个高影响节点或单图可确认，不拆成字段问卷 |
| A4 探索 | 脑暴、更多可能、创新 | 发散后聚类收敛，正式生产前重新过事实与风险门 |

用户要求“直接出”代表A2，不代表允许编造事实。用户未指定模式时采用“智能推荐”（A1）；任务非常明确且风险低时可压缩解释和确认卡，但不能删除核心闸门。

## 核心闸门

以下核心闸门不可删除、倒置或用记忆替代；自主性只决定显示确认还是内部确认：

1. **商品信息确认闸门**：新商品先建立商品卡并确认商品身份、参考图、视觉DNA、事实、冲突和禁用边界。
2. **输出对象确认闸门**：商品确认后才确认主图、SKU图、海报、产品素材图、详情页的真实范围、组合、用途与数量。
3. **结构选择闸门**：多张主图、SKU图、海报和详情页必须在递进式主次、等量并列、混合结构中确认一种；自动模式内部确认。
4. **综合方案选择闸门**：结构后固定推演5个产品专属综合方向；交互模式让用户选择，自动模式内部择优。
5. **逐图提交规则**：逐图模式当前图确认后才进入下一张；自动模式逐张执行内部确认；最终只聚合已放行单图卡。
6. **0到9动作闸门**：关键交互节点由主控调用 `next-action-engine.md` 生成编号0到9的10项动态动作；子智能体不得解释数字、代替用户选择或自行推进分支。自动模式可内部采用0号首推，但必须记录所采用动作。

闸门依赖固定为：

`商品信息确认 -> 输出对象确认 -> 多图结构选择 -> 固定5个综合方案 -> 逐图确认/自动内审 -> 0到9动作 -> 最终分镜聚合`

用户已在当前消息明确的对象、张数、结构或方向可直接写入对应卡片，但仍要建立状态并检查冲突，不重复询问同一事实。

## 深度预算

| 预算 | 适用 | 策略深度 |
|---|---|---|
| 快速 | 单图、通版、明确返修 | 事实 + 当前任务 + 最小视觉/生产 |
| 标准 | 常规主图、SKU、海报、详情页 | 核心需求、策略、资产和创意链 |
| 深度 | 高客单、复杂SKU、强竞争或用户要求深度推演 | 多情境、证据矩阵、多智能体与红队，再收敛为分镜 |
| 全案 | 多对象、跨平台、整店/活动/品牌统一图组 | 分组图组、渠道差异、复用与统一视觉，再输出分镜 |

深度意味着多做影响决策的分析，不意味着增加页面、模型、文字或确认。

## 标准阶段

非核心分析阶段可以压缩或按需省略；核心闸门只能压缩展示，依赖和合同记录必须成立。

| 阶段 | 核心产出 | 是否通常需要用户确认 |
|---|---|---|
| 1 接单与分类 | 输出意向草案、风险、自主性、预算与约束 | 否 |
| 2 商品识别与商品卡 | 商品事实、参考图编号、视觉DNA、补充建议、冲突与禁用项 | 新商品必须确认；完整结构化资料可用确认摘要 |
| 3 全对象需求预判与范围 | 主图/SKU/海报/素材图/详情页职责、风险、对象和数量 | 必须建立范围合同；用户已明确时紧凑确认 |
| 4 多维策略推演 | 买家任务、证据、图组目标和结构依据 | 否，作为结构推荐输入 |
| 5 图组结构 | 递进式、等量并列、混合或单张闭环 | 多张主图/SKU/海报/详情页按结构合同确认；自动模式内部确认 |
| 6 五个综合方向 | 人群、卖点、路径、场景、美学、文案、证据与风险 | 交互模式确认；自动/直出内部择优 |
| 7 图组与逐张编排 | 每张任务、参考图、视觉栈和生产方式 | 无独立同义闸门；进入逐图工作流 |
| 8 逐图提示词 | 单图卡、图生图提示词、负面词和后期说明 | 逐图模式显示确认；自动模式内部确认 |
| 9 动作与整组放行 | 0到9动作、事实、合规、连续性、对象范围和格式 | 交互节点由用户选择；自动模式采用内部首推 |
| 10 最终聚合与学习快照 | 最终Markdown分镜；截至提示词交付时的选择、否定、返修与适用范围 | 分镜对外交付；内部学习快照保持可增量合并，不提前封包 |
| 11 可选生图闸门 | 指定分镜/当前图组/全部图组、每张候选数量、冻结配对与结果追溯 | 仅用户明确选择时执行；默认不生图 |
| 12 学习收口 | 合并用户对生图候选的有效选择/否定，或确认本轮没有后续生图反馈 | 暂不生图、用户结束生图或请求进入`ACCEPTED/CANCELLED`后完成最终学习包；后续恢复生图时增量刷新 |

每个阶段统一执行：`输入状态 → 草拟 → 批判 → 修复/回退 → 发布`。发布版本只保存结论、依据摘要、约束、风险和下游输入，不保存完整思考链。若批判阶段发现上游错误，回到最早错误域；不得在提示词末端用更多形容词掩盖。

## 确认决策规则

核心闸门必须建立；以下规则决定是否需要额外停下来确认：

1. 不同选择会改变商品身份、事实、合法性或安全边界。
2. 不同选择会显著改变交付范围、生产成本、平台适配或品牌定位。
3. 用户明确要求掌控该节点或逐图确认。
4. 多个方案没有可基于现有信息判断的明显优先级。
5. 选择不可逆，或错误后会造成大范围返工。

其余情况采用AI首推并继续，但仍建立对应合同。综合设计方向始终固定推演5个；交互模式展示5个，直出/全自动内部比较并记录采用结果。额外专项候选默认首推+2个备选，脑暴时扩展到10个；专项候选不能替代固定5个综合方向。

## 数量策略

用户指定数量时严格执行。未指定时按下表对象默认数量，再用最小充分原则保证每张有独立任务：

| 输出对象 | 常规建议 | 选择逻辑 |
|---|---|---|
| 主图 | 10张 | 识别、利益、证明、结构、场景、选型与信任；不能同义重复 |
| SKU图 | 5张 | 没有准确SKU关系时不生成伪SKU矩阵，改用现有真实选择任务 |
| 海报 | 5张 | 围绕真实主题、渠道、情境或视觉表达形成实质差异 |
| 产品素材图 | 3张：白底、透明、无字场景各1张 | 用户点名子类型时只做点名内容 |
| 详情页 | 由购买复杂度与证据链决定，通常6-12张 | 使用能完成理解、证明、选择与顾虑收口的最少页数 |

用户明确需要平台标准数量、整套轮播或批量投放时，按其张数执行。增加张数必须有新增任务；减少张数优先保留决策闭环。

## 模块调度

基础先读取：本文件、交互、同范围偏好摘要、商品分析/文档。偏好摘要只改变首推和表达，不改变商品事实、范围或闸门。随后按决策问题加载，不因目录存在就全部读取。

- 需求不清、要挖场景/人群/痛点：`demand-opportunity-system.md`。
- 需要策略、差异、反事实：`strategic-intelligence.md`、`reasoning-engine.md`。
- 已确认的货盘、价格、品牌或渠道条件会直接改变图组任务、证据或顺序时：读取 `business-models.md` 及最多两个必要子文件，并只把结论转译为图片任务。
- 多对象、跨平台或资产复用：`asset-portfolio-system.md`。
- 只做单一对象：只加载当前对象的场景、营销、视觉和生产模块。
- 最终图组内部运营审查：`operation-review.md`；分镜偏好从任务开始读取并持续更新：`persistence-evolution.md`。
- 最终输出：合规、终检和分镜模板。
- 提示词交付后用户明确要求生图：`render-gate.md`；它不得反向改变范围、结构或未修补的提示词。

## 硬阻塞

只有以下情况暂停：

1. 无法识别商品主体，且用户没有提供名称或用途。
2. 图片与文字在身份、型号、规格、适配、数量或套装关系上存在会误导购买的冲突。
3. 用户坚持使用无依据的高风险功效、认证、价格、活动、销量、售后或适配结论，且不允许删除/降级。
4. 用户要求商用级真实成品，但素材无法保持商品一致性，也不接受实拍、合成、补素材或概念稿降级。
5. 法律、平台、授权或人身安全无法在现有资料下成立。

其余缺口不阻塞：删除相关表达、使用可观察事实、降低生产范围或注明假设后继续。

## 返修与失效

把返修定位到八个状态域：

- 事实错误：使所有引用该事实的下游失效。
- 需求/策略错误：只重算相关资产职责与后续内容。
- 资产范围/结构变化：重算组内职责和依赖。
- 文案、背景、人物、构图等创意变化：只重算当前图及共享视觉约束影响项。
- 生产或画布变化：保留策略与文案，重算提示词、构图和后期说明。
- 实际生成结果与用户返修：更新学习域，再决定是否回到参考图、图组、创意或提示词层。

连续两次返修同一表面问题时，自动上移一层寻找根因，不继续换形容词。

## 输出契约

- 向每个下游交付当前任务/商品/参考图/范围/结构/方向/分镜槽位/分镜/提示词所需的合同版本信封；缺少必需上游版本时不得发放阶段令牌。
- 过程交互只为建立核心合同：先给结论，再给完成当前选择所必需的依据、风险、假设和动作；不形成独立分析报告。
- 诊断、策略、运营、商业、营销、美学和多智能体结果都保留在内部工作包；只有硬阻塞或当前闸门必须理解的结论可显示。
- 综合方案交互固定为5个；专项返修候选可用首推+2备选，但不能变成额外交付物。
- 核心正式输出是用户确认范围内的逐张图生图分镜提示词，服从 `storyboard-template.md`；可选生图结果按 `render-gate.md` 另行绑定版本，不进入源码块。
- 导航输出：关键节点由下一步引擎提供`0`到`9`动态动作；最终源码块不含菜单。
