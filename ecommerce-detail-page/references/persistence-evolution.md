# 分镜偏好学习与进化系统

本文件只学习用户如何判断商品图、选择要做的图片、安排图组、设定场景与构图、控制商品保真和编写图生图提示词。学习结果只优化分镜提示词，不扩展到其他业务咨询。

内部称为“进化记忆”。每条记忆必须是结构化记忆记录，拥有证据、范围、置信、冲突、覆盖、衰减、来源、可查看和可撤销属性；不得保存完整思考链。

## 每次任务都捕获

每轮任务持续记录用户的显式要求、选择、确认、否定、返修和最终采用结果。不要等用户说“记住”才理解本轮偏好；但持久化到项目文件时必须服从下文范围与隐私边界。

捕获九类思维信号：

1. **选图思维**：用户认为哪些参考图更可信、哪些角度更关键、哪些图应排除。
2. **图组思维**：倾向做哪些图、张数、递进/并列/混合、首图与收口逻辑。
3. **卖点思维**：先讲什么、后讲什么、什么不值得讲、需要什么证据。
4. **场景思维**：真实/棚拍/内容感/高级感、场景具体程度、道具与人物边界。
5. **构图思维**：主体占比、机位、留白、视线动线、文字区、远近与裁切偏好。
6. **审美思维**：风格、色彩、光影、材质、字体、信息密度和品牌气质。
7. **保真思维**：允许图生图改变什么，必须抠图合成什么，对文字、LOGO、包装、颜色、结构和未知视角的容忍度。
8. **提示词思维**：喜欢的颗粒度、顺序、术语、正负面约束、是否强调后期、是否偏简洁或全量。
9. **协作思维**：希望AI自主决定还是先给方案、是否逐张确认、返修时希望看差异还是直接重发。

## 思维证据与升级

每条偏好都保存“证据类型”，避免把猜测当规则：

- E3 明确规则：用户明确说“以后”“所有”“长期”“记住”“永远不要”，并指明适用范围。
- E2 重复确认：同一规则在至少两个独立任务中被用户明确确认；同一任务内重复点击或重复返修不算两个独立证据。
- E1 本任务确认：用户本次明确选择、确认，或修改后的最终版本被明确采用。E1默认只在当前任务或最窄对象范围生效。
- E0 AI推断：从上下文推测的候选，不能自动进入首推或持久化。

以下信号不得强化：用户静默、自动模式内部采用、未评价结果、随机生成差异、仅浏览但未确认。被拒绝方案只形成负向禁区；修改前版本不学习，只有修改后的最终采用版本才可成为正向规则。

## 五级核心范围

每条偏好先绑定以下五级主范围，再用`frame/group/category/platform_object`作为范围内限定器：

| 主范围 | 例子 | 生命周期 |
|---|---|---|
| 本轮输入 | “这句话里的高级感是暖白，不是黑金” | 当前输入处理并编译为明确规则后失效 |
| 当前任务 | 本任务所有分镜都不要人物 | 当前任务结束即失效，不写长期记忆 |
| 商品/SKU | 这个产品不能出现背面 | SKU、包装、参考图或商品版本变化时重新验证 |
| 品牌/系列 | 该系列长期使用暖白编辑感 | 新VI、系列定位变化或用户新指令时失效 |
| 用户通用 | 所有分镜都写身份母图和后期边界 | 跨任务应用，仍服从本轮明确要求 |

`frame`只限当前图片，`group`只限当前图组，`category`与`platform_object`只能作为候选上下文，不能自动升级为用户通用。范围冲突时更窄范围优先；局部例外不得反向改写品牌或用户通用规则。不确定范围时使用更窄范围。

## 捕获协议

每次用户输入后内部更新一次“思维差异”：

```text
新增：本轮第一次出现的明确偏好或约束
强化：与历史同范围规则一致的选择
覆盖：用户新要求替换旧规则
否定：明确不要的方向与近义变体
例外：只在当前图/商品成立，不改变长期规则
待验证：AI推断或一次含糊反馈
```

不要向用户反复展示完整记录；只在规则冲突、保存确认或用户要求查看时输出紧凑摘要。

偏好学习本身也执行循环：`捕获差异 → 检查证据与范围 → 合并/覆盖/例外 → 生成下轮提示词入口`。未通过证据与范围检查的信号只保留为E0/E1候选，不进入长期首推。放行后的偏好必须明确影响提示词的具体字段，如参考图选择、图组结构、场景人物、构图、信息密度、保真方式、正负面颗粒度或协作节奏，不能只保存“更高级”一类空标签。

## 偏好差异循环

每次反馈按以下状态运行：

`OBSERVE -> DIFF -> ATTRIBUTE -> SCOPE -> VERIFY -> PROMOTE | SUPPRESS | EXPIRE`

1. `OBSERVE`：保存可核验的用户原话、选择、否定、返修和最终采用状态。
2. `DIFF`：比较修改前后、选中/未选或失败/修复版本，只列真正变化的字段。
3. `ATTRIBUTE`：把用户明确说明的“因为”直接归因；未说明原因时只形成E0假设，不猜测隐藏心理。
4. `SCOPE`：采用能解释证据的最窄范围；当前图能解释时不升级到图组，商品能解释时不升级到品牌。
5. `VERIFY`：检查反例、历史冲突与最终结果；必要时在下一次可比任务只做一个低成本验证，不把用户拖入偏好问卷。
6. `PROMOTE/SUPPRESS/EXPIRE`：符合证据门才升级；错误归因、矛盾或过期候选被抑制/失效而不是堆叠相反规则。

这是一套可撤销的用户思维代理，不是模型训练，也不宣称改变底层权重。内部可以保留“表面修改 → 可归因标准 → 提示词字段 → 结果”的短追溯记录，不保存完整思考链。

## 对比归因规则

- 选中与未选候选共有的属性不能成为偏好证据。
- 一次比较同时改变场景、机位、人物、颜色和文案时，不能判断用户究竟偏好哪一项；只记最终选择事实，原因保持E0，或在会显著影响后续时问一个最小问题。
- 用户说“更高级”时，从实际改动中定位主体层级、材质光、信息密度、空间、字体或证据；无法定位时不创建“喜欢高级感”这类空规则。
- 用户返修后明确“这样对了”，只强化修复的差异和必要依赖，不强化未变化背景属性。
- 生图候选中的随机种子差异、工具故障、轻微噪点和未评价属性不能成为偏好证据。
- 下一任务静默应用某条规则后，没有用户评价不计为验证；被明确采用、否定或再次修正才更新证据。

## 偏好事件合同

每次明确反馈先记录为事件，再合并为记忆记录：

```yaml
event_id: stable-event-id
time: ISO-8601
raw_feedback: 用户原话或可核验反馈摘录
action: select/confirm/edit/reject/repair/revoke
dimension: reference/structure/selling_point/scene/composition/aesthetic/fidelity/prompt/collaboration
polarity: positive/negative/exception
normalized_rule: 可直接执行的规则
scope: turn/task/product/brand/user
evidence_level: E0/E1/E2/E3
confidence_state: candidate/active/suppressed/revoked/stale
target_object: 具体图片、图组、SKU、品牌或用户
invalidation: 失效条件
prompt_targets: [reference, structure, scene, composition, fidelity, copy, negative, collaboration]
attribution: explicit/contrastive/hypothesis
contrast_trace: [baseline-id, chosen-id, rejected-id]
verification_count: 0
persistence_authorized: true/false
authorization_scope: none/project/product/brand/user
authorization_trace: [用户明确授权原话或既有授权记录]
authorized_at: ISO-8601/null
supersedes: []
```

同一反馈可能拆成多个事件，但每个事件只能表达一个维度和一个极性。事件原话用于可追溯，不把隐藏思考链、子智能体推理或内部评分写入事件。

```json

  "scope_qualifier": "frame/group/category/platform_object/none",
  "scope_key": "具体对象",
  "created_at": "ISO-8601",
  "updated_at": "ISO-8601",
  "evidence_level": "E0/E1/E2/E3",
  "confidence": 0.0,
  "source_trace": ["任务/日期/用户原话或采用结果"],
  "attribution": "explicit/contrastive/hypothesis",
  "verification_count": 0,
  "last_validated": "ISO-8601/null",
  "prompt_targets": ["reference/structure/scene/composition/fidelity/copy/negative/collaboration"],
  "supersedes": [],
  "conflicts_with": [],
  "exceptions": [],
  "invalidation": ["触发陈旧或失效的条件"],
  "decay": "none/task_end/after_n_tasks/review_date",
  "status": "candidate/active/suppressed/revoked/stale",
  "persistence_authorized": false,
  "authorization_scope": "none/project/product/brand/user",
  "authorization_trace": [],
  "authorized_at": null,
  "revoked_at": null,
  "revocation_trace": []

```

- E0默认置信不超过0.35，只作观察，不进入首推。
- E1默认0.45到0.65，只在当前任务或最窄对象范围影响首推；一次明确采用不得直接跨任务。
- E2默认0.70到0.85，可在同范围稳定应用；长期未再次确认时按衰减规则降低。
- E3默认0.90以上，但仍服从当前明确要求、事实和安全合同。
- 否定、例外、覆盖和撤销是独立状态，不通过删除历史来源伪造一致性。

## 写入、查看与撤销

- 当前会话可自动捕获并复用turn/task及最窄对象规则；这叫捕获，不等于持久化。
- 只有用户明确说“保存”“记住”“以后长期使用”或已有明确持续学习授权，才可写项目记忆。记忆文件存在不代表自动获得写入授权。
- 用户可说“查看分镜偏好”，输出按范围分组的紧凑摘要、证据等级和冲突，不展示隐藏推理。
- 用户可说“忘记/撤销某条偏好”，将对应记录标记`revoked`并停止注入提示词；不得只在文本中追加一条相反规则。
- 用户可说“这次例外”，创建task/frame exception，不降低长期规则置信。
- 不保存完整推理、模型权重、子智能体思考链，也不宣称通过任务永久训练模型。

## 冲突、衰减与失效

冲突优先级固定为：

`商品事实/安全 > 当前明确要求 > 更窄作用范围 > 同范围E3 > 较新E2 > E1 > E0`

同范围下`明确否定 > 正向默认`。若仍冲突，只向用户询问一个能裁决的选择。

- 本轮输入规则在当前输入处理完成后失效。
- 当前任务规则在任务结束后失效。
- 商品规则在SKU、包装、参考图、颜色、结构或版本变化时转为`stale`并重新验证。
- 品牌规则遇到新VI、系列定位或用户新指令时失效或被覆盖。
- E2长期未验证时标记`stale`候选并停止默认注入；E3不因时间自动删除，但可设复核日期。
- 用户撤销时立即标记`revoked`，停止注入，并记录其覆盖/撤销关系。

## 返修学习

返修不是只记“不要这个结果”，必须提取根因：

- “不像商品” -> 参考图、视觉DNA、重绘范围或视角越界。
- “不够高级” -> 主体层级、材质光、信息密度、场景等级、字体或价值证据；不能只记录黑金偏好。
- “不够能卖” -> 图组任务、主利益、证据、点击相关性或选型，而非盲目加促销。
- “太假” -> 物理关系、人物动作、尺度、接触阴影、过度磨皮或场景不符合商品。
- “太乱” -> 一图多任务、主体占比、组件数量、文字密度或视觉动线。
- “提示词没效果” -> 指令冲突、参考图职责不清、正负面过载、模型与后期边界错误。

同类问题在两个独立任务中重复并得到用户确认时，才可升级为E2上游规则；同一任务连续两次只形成当前任务检查项。

## 任务结束学习包

提示词交付时，个人偏好学习智能体先生成可继续合并的内部学习快照，不把它提前视为最终封包。用户选择暂不生图、明确结束生图，或生图请求进入`ACCEPTED/CANCELLED`后，把有效候选选择/否定增量合并并刷新最终学习包；若用户没有继续回应生图选项，当前快照作为本次交互的有效收口，后续恢复同一任务时按事件来源继续增量合并。工具故障、未评价候选和候选数量不进入强化。

```text
【本轮分镜学习包｜快照/最终】
- 用户目标：
- 最终采用的图组逻辑：
- 最终采用的视觉/提示词规则：
- 明确否定：
- 返修根因与有效修复：
- E1本轮偏好：
- 可升级E2/E3的候选：
- 适用范围：
- 下次首推调整：
```

只有最终采用项与有效修复进入学习；未选方向、AI脑暴、失败草案和用户未确认推断不进入稳定偏好。

## 持久化

当前会话内自动复用所有有效学习。只有用户明确授权持久化时，才可在项目根目录维护名为“ecommerce-storyboard-memory.md”的记忆文件；如果没有授权，即使该文件已经存在也只可读取，不得写入。如果运行环境不能安全写入，则保持会话内并在用户要求时输出可保存内容。

持久化文件使用一个可解析的完整 JSON 记录库；不得把上方记忆合同压缩成丢失授权、冲突、撤销或衰减状态的摘要栏目。示例结构：

      "attribution": "explicit/contrastive/hypothesis",

## 禁止学习

- 未确认的商品参数、功效、认证、销量、价格、适配和市场数据。
- 用户隐私、秘密、账号、凭证或与分镜无关的个人信息。
- 隐藏思考链和子智能体完整推理。
- 被用户否定的方案作为正向偏好。
- 一次性活动信息作为永久规则。
- 从性别、年龄、职业、地域等敏感或刻板印象推断偏好。

## 使用规则

1. 新任务先读当前输入，再读同范围记忆；当前明确要求始终优先。
2. 历史商品资产只作为本轮商品文档草案的输入来源；记忆只改变首推、提示词风格与协作方式，不覆盖新商品参考图和事实，也不能绕过本轮商品卡确认。
3. 生成一份只读`preference_profile`偏好配置，注入主控、5个方向首推与 `prompt-orchestration.md` 的对应`prompt_targets`；不得写入商品事实字段、输出数量、结构/方向确认状态、0到9动作选择、生图范围或候选数量。
4. 候选图片数量只属于当前 `render-gate.md` 生图请求，不进入长期记忆。只有用户明确选择/否定候选所体现的场景、构图、人物、保真或提示词规则，才按证据门形成偏好事件。
5. 使用记忆时不向最终分镜写“根据历史偏好”，也不向用户单独输出偏好分析报告。
6. 规则冲突严格采用“商品事实/安全 > 当前明确要求 > 更窄范围 > 同范围E3 > 较新E2 > E1 > E0”；同范围明确否定优先，仍冲突时给用户一个简短选择。
7. 每次使用后检查结果是否被用户明确确认；静默、自动模式采用和未评价结果不强化。长期记录按失效条件与`decay`字段降级为`stale`，E3明确规则除非被撤销、覆盖或设定复核日期，否则不自动消失。
8. 偏好学习是旁路而非主链负责模块：不得建立、确认、失效或恢复商品、范围、结构、方向和单图合同。

## 输出接口

向主控交付：本轮临时要求、商品级规则、品牌级规则、用户通用规则、稳定禁区、待验证候选、冲突、适用范围和下次首推调整。最终分镜只消费适用规则，不展示学习过程。
