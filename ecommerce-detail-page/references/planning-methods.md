# 策划方法系统

本文件只负责产品经理视角、策划方法论、消费者洞察和内容编排方法。不写购买路径框架库、视觉规范、画布规则、合规清单或最终分镜模板。

## 使用时机

- 需要从产品经理、消费者、运营或策划角度重新判断商品价值时读取。
- 用户要求“更智能、更会卖、不要我一步步引导、重新策划、全自动推演”时读取。
- 营销系统需要买家任务、价值主张、内容编排主张或实验建议时读取。

## 产品经理视角

营销推演前先判断“这个商品为什么值得被设计”，避免只做漂亮画面。

| 方法 | 判断问题 | 详情页/素材落地 |
|---|---|---|
| JTBD买家任务 | 买家雇佣这个产品完成什么任务 | 页面主线围绕任务完成，不围绕功能堆砌 |
| 用户故事 | 谁在什么场景下为了什么结果使用它 | 场景页、SKU图和海报文案更贴近真实语境 |
| 价值主张 | 它比旧方案更快、更省、更稳、更美还是更安心 | 首屏和主图只打最强价值点 |
| 需求优先级 | 哪些是必须讲、应该讲、可选讲、不该讲 | 控制每张图只承担一个购买问题 |
| 风险假设 | 买家最可能因什么不下单或退货 | 提前安排证据、参数、边界和顾虑兜底 |
| 验收标准 | 用户看完后应该相信什么、能做什么决定 | 用于最终分镜自检和返修判断 |
| 变体策略 | 哪些主图、标题、卖点值得生成独立投放变体 | 后台保持单一变量，最终每张按正式成品交付 |

产品经理结论必须压缩成：买家任务、核心价值主张、必须证明的事实、最大流失风险、页面验收标准。

## 策划方法论

把方法论转为内容编排，不把理论名词直接写到画面上。

| 策划工具 | 用法 | 输出 |
|---|---|---|
| Campaign Brief | 明确目标、对象、平台、行动和限制 | 本轮设计目标 |
| Creative Brief | 明确一句核心主张、视觉锤和情绪基调 | 创意方向 |
| Message Hierarchy | 主信息、辅助信息、证据信息、行动信息分层 | 信息层级 |
| Hook-Proof-Close | 先截停，再证明，再收口 | 页面节奏 |
| Content Architecture | 将卖点、场景、证据、参数和顾虑分配到不同页面 | 分镜结构 |
| 模块化资产策略（Modular Asset Strategy） | 一套商品身份锚点复用到主图、SKU图、海报、素材图和详情页 | 素材复用策略 |

策划输出必须包含：一句主张、一个视觉锤、一个证明方式、一个行动收口、一个可复用素材方向。

## 消费者洞察方法

从买家角度重写产品表达：

1. 动机：用户真正想得到什么结果。
2. 障碍：用户为什么迟疑、怕什么、担心什么。
3. 触发：什么画面或一句话能让用户觉得“与我有关”。
4. 证明：什么证据能让用户相信，不需要编造。
5. 场景：在哪个生活空间、时间点或人群状态下最容易下单。
6. 情绪收益：使用后获得安心、体面、效率、掌控感、松弛感还是专业感。

消费者洞察必须转成可执行页面动作：首屏钩子、卖点排序、证据前移、场景选择、顾虑兜底和信息承接；购买行动方向只作为后台判断。

## 输出接口

交给 `marketing-system.md` 或 `reasoning-engine.md` 的策划结论必须包含：

- 买家任务：1句话。
- 核心价值主张：1句话。
- 内容编排主张：一句主张、视觉锤、证明方式、行动收口。
- 最大流失风险：最多3项。
- 页面验收标准：用户看完后应相信什么、能做什么决定。
- 变体假设：后台记录主图、标题、卖点或场景中最值得比较的1到3项；不得写入最终分镜或画面。

不得把策划推断写成产品事实；涉及参数、认证、销量、活动和售后时必须读取准确事实，否则自动跳过对应字段和组件。
