# 分镜运营内审系统

本文件只负责在后台用运营结果审查图组任务、顺序与逐张图生图提示词。所有商业、投放、转化和A/B判断都必须转译为“保留/删除/调整哪张图、该图证明什么、画面和提示词如何约束”，不得形成独立运营报告、复盘、评分单或A/B建议交付。

默认只作内部评估；用户点名运营视角时也只返回会改变分镜的结论与最小补丁，不生成独立运营交付。

## 使用时机

- 最终分镜前，需要从运营结果反推页面是否值得投放时读取。
- 用户要求“更能转化、从运营角度看、适合上架、适合投放、提升点击率/转化率/复购率/降低退货率”时读取。
- 需要判断单一变量是否值得形成备选分镜时读取；默认不向用户输出A/B测试建议。
- 产品素材图仅在用户要求素材复用、素材库规划或全店统一时读取。
- `reasoning-engine.md` 判断当前任务存在高客单、投放、大促、强促销、强选型、防退货、复购或全案经营需求时读取。

## 运营视角

| 输出对象 | 核心运营目标 | 主要检查 |
|---|---|---|
| 主图 | 提升点击与降低误点 | 搜索列表可识别、核心卖点3秒可读、主体清晰、差异化足够、不过度承诺 |
| SKU图 | 降低选错和咨询成本 | 规格关系真实、差异一眼看懂、价格带或套装不误导、适配边界清楚 |
| 海报 | 提升传播和活动承接 | 场景情绪明确、行动入口清楚、活动信息有依据、适合平台内容流 |
| 产品素材图 | 提高复用效率 | 白底/透明/无字场景图可二次排版、产品资产干净、光影统一 |
| 详情页 | 提升转化并降低退货 | 首屏承接、痛点准确、证据充分、参数清楚、顾虑兜底、期望值管理 |

## 运营评分

最终出稿前可内部按100分评估，不把长评分表写入最终源码块：

- 点击进入：主视觉识别度、列表环境辨识度、核心卖点清晰度，共20分。
- 理解效率：一屏一任务、信息层级、移动端可读、参数解释，共20分。
- 信任强度：证据链、事实边界、用户顾虑、平台合规，共20分。
- 转化动作：利益表达、行动入口、价格/赠品依据、下滑或加购动机，共20分。
- 复用与一致：产品保真、风格统一、组件统一、素材可扩展，共20分。

低于80分时，先优化影响最大的1到2项，不重跑全流程。低于70分时，回到对应负责模块重建合同或草案。

运营评估始终是后台质量闸门，只向下游交付运营工作包，不把完整评分、公式和推理过程展示给用户。即使用户在本技能内要求运营复盘，也只把结论转译为受影响分镜的最小修改；独立复盘不属于本技能交付。

## 商业复盘模型

需要更强经营判断时，先读 `business-models.md`，再按需读取 `ecommerce-operation-models.md` 或 `business-growth-brand-models.md`，用以下模型压缩成运营建议：

- 指标树：拆解点击、停留、加购、咨询、下单、退货和复购。
- 漏斗/路径/留存：判断流失发生在素材、详情页还是交易环节。
- ICE/RICE/PIE：选择最值得优先返修或A/B测试的页面。
- RFM/CLV：复购品和会员商品要区分新客、老客和高价值客。
- OODA：返修时形成观察、判断、决策、行动闭环。
- 事前验尸：最终输出前预判失败原因，优先修复最可能导致投放失败的点。
- Goodhart定律：不能为点击率牺牲真实性、退货风险和长期品牌信任。

## 运营终审

最终出稿前从经营结果反推，不要求用户提供模型名：

1. 流量是否精准：主图/海报吸引的是目标买家，还是会因夸张造成误点。
2. 承接是否一致：首图核心主张是否在详情页前段得到解释和证明。
3. 决策是否省力：买家能否快速判断这是什么、适合谁、为什么值得、买哪款。
4. 证据是否够用：高客单和高风险商品是否在犹豫发生前给出真实证据和边界。
5. 价格是否有理由：没有真实促销时，是否用价值、寿命、场景或服务解释，而非虚构优惠。
6. 退货是否可控：尺寸、型号、适配、色差、安装、使用限制和期望差异是否被提前处理。
7. 资产是否可复用：同一商品身份锚点能否延展到搜索、内容流、SKU、详情和后续A/B测试。

终审只修复影响最大的1到2项。若问题来自产品或事实，不用视觉包装掩盖；若来自承接顺序，只重排相关页面。

## 内部变量验证

以下内容只用于内部判断是否要形成备选分镜，不得在源码块外另附建议，也不得写入最终分镜、提示词或“可修改位置”。一次只改变一个能影响图片任务的变量，其余已发布合同保持不变；没有用户明确授权增加备选分镜时，不扩大输出范围。

- 主图：测试核心卖点表达、主体占比、背景深浅、痛点对比、场景人群。
- SKU图：测试总览顺序、标签颜色、规格对比方式、默认推荐款表达。
- 海报：测试情绪主题、行动文案、人物/无人物、活动强弱。
- 五维视觉栈：一次只测试主风格、核心主体、背景空间、转化组件或生产形式中的一个变量，其余保持为组级不变量，避免无法归因。
- 详情页：测试首屏标题、前3屏顺序、证据屏位置、参数解释方式、尾屏顾虑。
- 产品素材图：测试白底光影、透明边缘清晰度、无字场景氛围和后期留白。

## 运营工作包

向下游只交付摘要：

- 核心运营目标。
- 主要风险点。
- 最优先优化项。
- A/B测试方向。
- 上架或投放注意。

其中“A/B测试方向”只能作为内部候选变量；“上架或投放注意”必须转译成提示词硬约束、后期边界或删除项，不能成为附加建议。

运营工作包只供图组取舍、返修优先级和最终放行使用，不得进入最终分镜。最终分镜只由 `storyboard-template.md` 映射正式成图字段，不输出评分、评语、页面存在理由、顺序理由、可修改位置、运营结论或A/B建议。
