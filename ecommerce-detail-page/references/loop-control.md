# 循环控制系统

本文件是“循环 + 提示词”双引擎的控制面，只负责循环状态、预算、退出条件、失败回退和提示词放行。不写对话推理、营销方法论、视觉规范、画布规则或最终分镜模板。

## 目录

`核心原则` / `统一循环状态机` / `循环编排` / `提示词编译循环` / `提示词与循环质量闸门` / `预算规则` / `工作流接入` / `输出接口`

## 核心原则

1. 循环是节点内部控制方式，不是额外长流程。
2. 每个节点最多内部重复2轮；轻量预算最多1轮。
3. 循环失败后不能无限追问；商品主体、安全或合法性受阻时只问一个关键问题，其余不准确字段自动跳过，或退回受影响合同。
4. 循环说明不得进入最终分镜源码块。
5. 用户连续两次简短确认时，跳过发散探索，推进到下一合同闸门。
6. 每轮只改变一个失败层；若根因属于上游事实、参考图、图组或生产能力，必须回退，禁止靠冗长提示词补救。
7. 循环只输出结构化状态包，提示词编译器只消费`status: RELEASED`的上游合同；任何`DRAFT/PENDING/INVALIDATED/BLOCKED`合同不得编译。分镜草案是绑定这些已发布版本的非合同产物，可作为编译材料，但不得拥有合同状态或进入发布库。循环阶段名`RELEASE`不等于合同已`RELEASED`，只有对应负责模块完成规定的用户确认或自动内审后才能提交状态转换。

## 统一循环状态机

每个循环使用同一状态：

`INPUT -> DRAFT -> CRITIQUE -> REPAIR | ESCALATE -> RELEASE`

- INPUT（输入）：只读取当前节点所需摘要、硬约束和用户新输入。
- DRAFT（草拟）：生成一个主候选；综合方向节点按固定合同生成5个，不额外发散。
- CRITIQUE（批判）：从真实性、事实合规、任务增量、参考能力、视觉物理、提示词单义性和用户偏好范围检查。
- REPAIR（修复）：只修改失败层；最多按预算再进入一次批判。
- ESCALATE（上报）：上游错误回退；R4只向用户问一个最小问题。
- RELEASE（发布候选）：产出唯一候选、硬约束、风险与下游结构化输入，并请求负责模块提交状态转换；需要确认的结果先写`status: PENDING`，不得直接进入发布库。

严禁把批判过程、内部评分、角色争论、失败草案和循环状态写入最终分镜。

## 循环编排

| 循环 | 提示词目标 | 循环条件 | 退出条件 | 失败处理 |
|---|---|---|---|---|
| 输入理解循环 | 把图片和自然语言转成商品线索、模式、设计意向草案和约束 | 商品主体或用户动作不明 | 商品线索足以建立文档；输出对象可以暂时待预判 | 只问一个最关键商品问题，不在商品卡前追问输出对象 |
| 商品信息确认循环 | 聚合带来源、可信度、字段相关性和自动跳过决策的商品文档并获得整卡确认 | 新商品、识别不稳、用户否定、字段新增/补充或事实变更 | 商品合同为`RELEASED`，关键冲突清零，缺失字段已进入跳过字段清单 | 只问一个关键身份问题；更新商品文档并重发确认卡 |
| 设计需求预判循环 | 从已确认商品反推主图、SKU图、详情页、海报和素材图的职责与条件 | 输出对象未确认或用户增减范围 | 用户确认输出对象、组合、数量和用途 | 展示全对象需求地图，不用单一建议替用户决定 |
| 卖点重写循环 | 将普通卖点转成利益、证据、场景和视觉锤 | 卖点泛、不可视化或缺证据 | 得到1个主卖点和2到4个辅卖点 | 标注证据缺口并给候选 |
| 文案审稿循环 | 将页面命题转成可信、具体、差异化文案 | 文案空泛、重复、错位、过密或证据越界 | 文案工作包完整且语义去重通过 | 回到卖点、页面任务或商品证据，只问一个关键事实 |
| 策略推演循环 | 匹配购买路径、转化驱动力和框架组合 | 框架与品类、人群或输出对象冲突 | 得到可执行页面主线 | 降级为稳妥转化方案 |
| 视觉栈循环 | 匹配主风格、核心主体、背景空间、转化组件、生产形式、字体、视角和光影 | 五维系统冲突、与品类/价格带错位或产品被装饰压制 | 得到兼容、清晰、可生产的视觉栈 | 保留商品合同与方向合同，只重推视觉和制作工作包 |
| 制作可行性循环 | 检查实拍、图生图、背景合成、3D、插画或创意合成是否有足够资产 | 方向需要未知角度、模型、证据或后期能力 | 制作工作包明确输入、生成范围、后期范围和降级路径 | 降级为真实产品合成或概念预览，不伪造可交付能力 |
| 提示词编排循环 | 把已发布合同与已裁决工作包装配成逐张可执行图生图提示词 | 缺少任务、产品硬约束、构图、场景、光影、信息区、组内关系或事实边界 | 提示词层级完整、无冲突、无无效重复 | 只重编失败层；上游合同冲突时回到对应负责模块 |
| 单图确认循环 | 生成完整单图卡、处理字段返修并更新确认状态 | 当前图尚未确认或用户提出修改 | 当前 FR/PR 配对原子发布并推进一张 | 只重算受影响字段；共享合同或组级不变量变化时计算下游失效卡 |
| 分镜自检循环 | 检查页码、对象范围、画布、事实、合规和源码块纯净 | 页码占位、对象混入、事实越界或格式错误 | 分镜只含真实递增页码和当前对象 | 修正后再输出，不把错误说明写入源码块 |
| 返修循环 | 读取 `repair-engine.md`，判断事务快照、保留项、影响项和回退层级 | 用户改某页、某字段或同一问题反复出现 | 完成局部修正并通过返修回归 | 连续两次失败则提升层级或回到上游合同 |
| 偏好学习循环 | 从用户选择、否定和有效返修提取分镜思维差异 | 本轮产生新选择、例外、覆盖或冲突 | 形成带证据等级和适用范围的学习包 | 保留为当前任务规则或待验证候选，不错误泛化 |

## 提示词编译循环

每张图固定执行四步：

1. **提示词草拟**：从已放行工作包装配身份母图、视角主参考图、辅图能力轴、商品锁定、允许变化、画面、镜头、场景、光影、文字安全区和动态负面约束。
2. **提示词批判**：检查是否单义、可见、可执行；是否要求未知面、重绘精确文字、错误SKU、物理不可能人物关系；正负面是否冲突；是否泄漏后期流程和内部术语。
3. **提示词修复**：只改失败片段。身份/事实错回商品循环，视角/能力错回参考图或生产循环，图组重复回资产循环，视觉错回视觉循环。
4. **提示词发布闸门**：删除候选、括号、空字段、流程词和解释，从当前分镜草案与已放行分镜槽位生成`status: PENDING`的分镜/提示词配对候选，并为两者写入同一`release_pair: {frame: FR-nnn, prompt: PR-nnn}`。此时只进入待确认卡，不写发布库；用户确认或自动模式内审通过后，由分镜负责模块把分镜合同与提示词候选原子转换为`status: RELEASED`并写入发布库。最终 Markdown 只消费状态均为`RELEASED`、配对版本一致且父版本仍为当前版本的 FR/PR。

用户提供外部结果，或经 `render-gate.md` 可选生成结果后要求返修时，执行`结果 → 诊断 → 最小提示词补丁`：先定位身份漂移、几何变形、材质/颜色、文字、场景物理、人物交互、构图、指令冲突或负面过载，再只修改分镜提示词的最小语义片段；连续两次同层失败时，在提示词中改用合成生产方式、要求补素材、降低视角或回到上游合同。即使分镜正文不变，也必须复制为新 FR 并与新 PR 形成新的`release_pair`，旧 FR/PR 在新配对原子发布时同步失效。只有用户明确要求时才按新配对版本重生受影响目标，不自动重跑整组。

## 提示词与循环质量闸门

用于把大模型能力变成稳定工作流，不把以下闸门写进最终分镜源码块。

批判阶段按 `final-checklist.md` 的`Q0 → Q1 → Q2 → Q3`顺序记录最高严重度。Q0/Q1直接上报或修复；影响任务/执行的Q2不得发布；Q3不得触发上游重算。`P0-P4`只表示参考图能力，不能作为质量严重度。

| 闸门 | 检查问题 | 不通过时 |
|---|---|---|
| 提示管理 | 当前节点是否只加载必要文件，是否混入无关对象 | 回到场景命中或模块调度，缩小上下文 |
| 忠实性评估 | 参数、认证、销量、活动、功效是否有准确依据 | 非关键字段自动跳过；影响主体、安全或合规时询问一个问题 |
| 相关性评估 | 输出是否服务当前对象：主图、SKU图、海报、素材图或详情页 | 删除跨对象内容，只保留当前对象 |
| 成本与密度 | 是否出现模型堆叠、长解释或重复规则 | 保留主模型和最多2个辅助模型 |
| 视觉栈兼容 | 风格、主体、空间、组件和生产形式是否互相支持且服务当前任务 | 删除冲突系统，每维只保留一个主系统 |
| 制作可行 | 现有产品图、人物、3D、证据和后期条件是否足以实现 | 切换生产形式、补资产或明确概念预览 |
| 安全护栏 | 是否触碰广告法、平台红线、医疗化、虚假稀缺 | 回到合规审查并重写表达 |
| 执行闭环 | 是否给出可执行下一步、返修入口和确认项 | 调用 `next-action-engine.md` 生成编号`0`到`9`的10项序列化动作 |

## 预算规则

| 预算 | 允许循环 | 输出密度 |
|---|---|---|
| 轻量 | 输入澄清、商品信息确认、分镜自检；每个最多1轮 | 少解释，但不跳过商品事实确认 |
| 标准 | 卖点重写、策略推演、视觉定调、分镜自检；每个最多2轮 | 首推+少量备选 |
| 深度 | 完整循环，可输出10条建议后收敛 | 展开关键建议 |
| 全案 | 先做一次总对话推理，再按输出对象分组循环 | 分组推进，不混页 |
| 返修 | 只运行返修循环和受影响节点循环 | 说明保留项和影响项 |

## 工作流接入

主流程允许在关键节点使用本文件，但仍由 `execution-engine.md` 决定业务步骤顺序。

- 影响真实性、合规或产品一致性：暂停并向用户问一个关键问题。
- 只影响创意优劣：采用系统首推，把不确定性留在内部创意风险记录，不生成商品字段或消费者主张。
- 用户要求直出或通版：新商品仍完成一次精简商品卡确认；确认后不展开其他长循环，没有准确值的字段自动跳过并从下游删除。
- 用户连续两次简短确认：跳过发散探索，推进到下一合同闸门。

## 输出接口

循环完成后只向下游交付：

- 当前循环名称。
- 是否通过。
- 更新的合同或工作包。
- 保留不变的合同与工作包。
- 需要用户确认的一项内容。
- 若失败，记录阻塞原因和回退模块；不得用缺失字段占位继续推进。
- 标准`status`、版本号、变更原因和被替换版本；最终只保留当前`RELEASED`版本。
