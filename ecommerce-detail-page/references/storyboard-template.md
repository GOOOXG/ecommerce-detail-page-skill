# 图生图分镜交付模板

最终交付只包含逐张中文图生图分镜。只有用户指定数量无法真实成立时，才可在第1张分镜前增加一行`> 数量说明：实际交付数量与原因`。商业、运营、产品、营销、美学、评分、子智能体意见和学习过程都必须已经转化为分镜字段，不另附报告。

## 参考图综合使用

正式分镜不输出参考图索引，也不强制把商品身份、机位和细节固定到某一张编号图片。AI先读取并提取本次全部有效参考图中的商品身份、SKU、轮廓、结构、颜色、可观察表面、文字、包装、配件、尺度、场景与冲突，再以已确认商品卡形成统一依据。

每张用一个`参考图使用`字段说明本张怎样使用参考内容：可以只用一张最可靠图片，可以在同一目标SKU/状态内综合多张互补信息，也可以先读取全部有效参考图后按目标SKU/状态分别筛选。其他SKU只用于已确认差异与防串款，冲突服从已确认商品卡，不平均或融合成虚构商品。选择取决于当前任务、证据质量和冲突情况，不按固定模板强制单图或多图。正式字段和提示词不写固定参考图编号。

## 单张模板

````markdown
## 第1张（主图-01）：【填写：成图名称】
- 输出对象：【填写：主图 / SKU图 / 详情页 / 海报 / 白底图 / 透明图 / 无字场景图】
- 成图任务：【填写：本张唯一需要解决的问题】
- 画布与布局：【填写：画布比例或像素（仅在已确认时写）、商品在版面中的位置与相对占比、裁切边界、文案/品牌/证据安全区】
- 参考图使用：【填写：本张采用一张、多张或全部有效参考图；综合提取哪些商品身份、SKU、几何、颜色、材质、文字、包装、配件、尺度或场景信息；冲突如何服从已确认商品卡】
- 商品锁定：【填写：必须保持的轮廓、结构、比例、颜色、可观察表面、标志、包装、配件和状态】
- 允许变化：【填写：有条件可变与可自由探索的背景、道具、人物、摆放、构图节奏、光影、留白、视觉隐喻和后期层；用正向成功标准说明创作空间】
- 视角与事实边界：【填写：允许的角度与裁切；背面、底部、内部、拆解等目标必须已经由用户序列号确认或被参考图直接证实；未确认目标不得写实补画；以及无依据结构、参数、功效和配件禁区。正式分镜不写置信度数字或视图推断标签】
- 最终画面：【填写：主体数量、空间关系、动作、前中后景和唯一视觉焦点】
- 镜头与构图：【填写：景别、机位、俯仰、透视、焦点、景深、视觉动线和前后景关系】
- 场景与人物：【填写：空间、道具、人物身份、动作、接触、尺度、遮挡和安全；无人无场景时删除本行】
- 光影、材质与色彩：【填写：主光方向、光质、阴影、反射、表面表现和整组色彩关系】
- 最终文案：【填写：真实可用的短文案及层级；无字或未确认时删除本行】
- 生产与后期：【填写：图像模型、真实商品层、抠图、合成、三维、实拍、校字和精修的职责】
- 🎨 图生图提示词：
```text
【填写：一段完整、自然、可单张执行的中文正向提示词】
```
- ⚠️ 动态负面提示词：
```text
【填写：只针对本张高风险错误的中文负面提示词】
```
````

## 必需与可选字段

必需字段：输出对象、成图任务、画布与布局、参考图使用、商品锁定、允许变化、视角与事实边界、最终画面、镜头与构图、光影、材质与色彩、生产与后期、图生图提示词、动态负面提示词。

可选字段：场景与人物、最终文案。可选字段无内容时删除整行，不写“无”“不适用”“待定”或空占位。

## 编号规则

- 标题固定为`## 第N张（对象-编号）：成图名称`，例如`## 第3张（详情页-03）：材质与结构证明`。
- 完整图组的阅读页码从1开始连续递增；同一稳定编号只能出现一次。
- 不同输出对象分别使用`主图-01`、`SKU图-01`、`详情页-01`、`海报-01`、`白底图-01`、`透明图-01`、`无字场景图-01`等清晰编号。
- 局部返修保留原页码和稳定编号；只返修原第4张时仍输出`第4张`，不能改成新的`第1张`。

## 内容规则

- 每张只保留一个成图任务，所有构图、人物、光影、文案和生产说明都服务该任务。
- 事实、SKU、安全和平台使用必要硬边界；其余内容优先用正向目标、允许变化和成功标准引导，不用通用禁令压缩合理创意。
- 组内角色、前后承接和信息增量统一折入“成图任务”“最终画面”和相关提示词，不新增公开字段。
- `参考图使用`必须明确本张采用一张、多张或全部有效参考图，以及提取的身份、几何、颜色材质、文字或场景信息；不能只写“参考原图”“参考上传图片”等空泛内容。
- 画布与布局必须写商品在版面中的位置、相对占比、裁切边界和实际启用的信息安全区；画布比例与像素未知时只删除这些数值，不删除整个字段。
- 提示词正文要重述会影响生成的商品位置、占比、裁切和安全区，但不机械重复所有像素数值。
- 精确标志、包装原文、长文案和参数表优先由真实商品层或后期处理。
- 最终源码块不得出现固定参考图编号、模型名、内部评分、置信度数字、视图推断标签、候选方案、角色讨论、循环日志、测试标签、凭证或状态字段。
- 多图先确定整组任务和视觉语言，再按顺序输出；不要在聚合时重新润色或改变已确认画面。
