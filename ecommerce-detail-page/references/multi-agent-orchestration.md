# 多智能体分镜推演系统

本文件定义复杂商品图任务如何由多个专业子智能体分工，再由主控合并为唯一图组和逐张图生图分镜提示词。角色只提交工作包，不分别向用户输出长报告。

## 目录

`启用条件` / `主控智能体` / `编排拓扑` / `阶段准入与禁止越权` / `专家角色` / `分工编排` / `子智能体工作包合同` / `主控合并检查`

## 启用条件

- 单张、目标明确、风险低：主控独立完成，不为形式强行调用子智能体。
- 多张图、复杂商品、多个SKU、人物交互、未知视角、高保真、详情页或用户要求深度推演：调用2到4个必要角色。
- 全套、多平台、高风险、强创意或反复返修：调用核心角色并增加红队与失败诊断。
- 运行环境不支持子智能体时，由主控按相同工作包顺序完成独立审视，不能省略关键检查。

复杂或高风险任务若运行时支持推理强度配置，主控为商品图法证、事实红队、策略/视觉、提示词编译、独立审查、生图审计和进化仲裁使用最高可用推理强度；简单单图不为显示复杂而强行并发。推理强度只提高检查深度，不允许输出隐藏思考链或延长无意义讨论。

## 主控智能体

主控拥有：用户意图、最终范围、参考图编号、状态摘要、冲突裁决、模块调度、逐张任务、最终提示词和交付格式。

主控必须：

1. 只给每个角色最小必要上下文，避免把所有参考文件同时加载。
2. 要求角色返回结构化结论、证据、风险和可执行约束，不返回完整思考链。
3. 对相互冲突的建议按“商品真实性 > 事实/合规 > 用户要求 > 图组任务 > 生产可行 > 视觉创意”裁决。
4. 删除重复、空泛或不能进入提示词的建议。
5. 最终只交付一套连贯图组，不把多角色意见并排甩给用户。

## 编排拓扑

- **顺序流水**：商品/参考图 → 范围/结构 → 方向 → 分镜槽位 → 分镜草案产物 → 分镜/提示词发布配对；存在依赖时禁止并行猜下游。
- **并行发散/汇合**：同一已发布输入下，需求/转化/视觉或法证/合规可独立并行；主控按合同合并一次。
- **生成-审查**：G只编译提示词，J只尝试证伪；G根据可复现发现项做一次最小修复，J复查后停止。
- **结果诊断**：K只比较生成结果与冻结合同，H只把失败路由到最早负责模块；二者不得共同重写整段提示词。
- **记忆双控制**：I捕获偏好事件，L独立检查归因、范围、证据升级与冲突后，才可进入`preference_profile`偏好配置。

子智能体不得共享可变状态。每个工作包视为不可变版本；用户补图或上游合同更新后，旧包只能标记`STALE`，不能原地修补或与新包混用。分歧只允许一轮有证据的主张/反证；仍无法裁决时由主控按优先级选择或问一个最小问题。

## 阶段准入与禁止越权

本技能主链是唯一调度总线：`商品卡确认 → 范围确认 → 多图结构 → 固定5个综合方向 → 逐图确认/自动内审 → 0到9动作 → 最终分镜`。所有子智能体都必须在主控发放阶段令牌后工作；没有令牌时只可等待或指出缺失输入，不能预做下游决策。

- 商品卡确认前：只允许商品图法证与必要合规红队形成草案，不能推演生产范围或最终提示词。
- 商品卡后、范围确认前：只允许需求预判角色生成全对象职责候选，不能替用户建立范围合同。
- 方向确认后：先允许视觉与生产监制角色用槽位前布局草案建立分镜槽位合同候选；槽位通过内部闸门并为`RELEASED`后，再物化绑定该 FS 版本的不可变分镜草案产物。只有分镜草案的全部输入版本仍为当前版本，才允许提示词编译角色工作。提示词编译不得改商品、范围、结构、方向、分镜草案或分镜槽位合同。

| 阶段令牌 | 准入角色 | 必需输入 | 允许输出 | 禁止越权 |
|---|---|---|---|---|
| S1 商品卡草案 | A；高风险追加B | 原始商品图、用户资料、临时偏好禁区 | 商品事实候选、参考图DNA、冲突、风险 | 不得确认商品卡，不得决定输出对象、结构或文案 |
| S2 需求预判 | C、D只读运行 | 已发布商品合同/事实摘要 | 全对象职责候选、阻力、证据需求、范围建议 | 不得建立范围合同，不得把建议变成生产范围 |
| S3 范围已确认 | C | 范围合同、事实摘要 | 数量与最小充分图组、结构建议 | 不得提前选择结构，不得设计单图 |
| S4 结构已确认 | C、D、E、F、B并行 | 结构合同、范围合同、商品事实 | 固定5个综合方向的候选工作包与风险 | 不得减少为3个方向，不得自行选方向或写最终提示词 |
| S5 方向已确认/分镜编排 | E、F；B按风险红队 | 方向、结构、商品与参考图合同均为`RELEASED` | 槽位前布局草案、分镜槽位合同候选；槽位发布后物化绑定 FS 版本的分镜草案产物与视觉/生产工作包 | G不得消费槽位前草案或提前编译提示词；不得改事实、范围、结构或方向 |
| S6 提示词与逐图放行 | G后接J；B按风险复核 | 分镜槽位合同为`RELEASED`、绑定当前输入版本的分镜草案产物、前序连续性摘要 | 同一`release_pair + source_artifact_id`的`分镜：PENDING + 提示词：PENDING`、批判发现项、最小修复与待确认卡；确认后分镜/提示词原子`RELEASED` | 不得消费未放行槽位、把分镜草案伪装成合同、用旧草案套当前版本信封、跳图、静默改编号或让审查者重写策略 |
| S7 返修 | H后接最早失败层负责模块 | 用户反馈/生成结果、现有 FR/PR 配对与上游合同 | 失败层、最小语义修复、受影响合同和新的原子 FR/PR 配对候选 | 不得单边升级 PR、整组重写或借返修扩大范围 |
| S8 可选生图 | K后接H；生成由主控调用工具 | 已交付分镜、当前 FR/PR `release_pair`、共同`source_artifact_id`、用户生图请求与结果 | 配对与来源校验、结果比对、目标、候选数量、结果追溯、失败层或补丁 | 不得拼接错配 FR/PR、替用户选择范围/数量、改上游合同或自动重跑 |
| P 偏好旁路 | I后接L | 当前用户原话、已发生选择、采用/否定差异 | 偏好事件、归因、适用范围、候选强化或抑制 | 不得覆盖商品事实、改变合同、确认闸门或持久化未授权内容 |

只有主控可以：向用户展示或确认商品卡、输出范围、结构、5个方向与逐图卡；解释数字回复；调用 `next-action-engine.md` 生成0到9动作；裁决冲突；发布、失效或恢复合同；聚合最终分镜。子智能体不得直接与用户形成平行对话，也不得输出运营、商业、营销、美学或偏好报告。

每次委派必须携带：`阶段令牌 + 只读输入合同摘要 + 当前问题 + 允许输出字段 + 禁止越权清单`。工作包缺少输入合同时标记“待主控补齐”，不得自行假设上游已经确认。

## 专家角色

### A. 商品图法证智能体

读取：原始商品图、`product-analysis.md`、`reference-image-reasoning.md`。

职责：商品身份、参考图编号、图像冲突、可见事实、不可改变项、缺失视角、P0-P4参考能力。

输出工作包：

- 参考图清单与角色。
- 商品视觉DNA。
- 主/辅参考建议。
- 不可生成内容与硬阻塞。
- 可靠生产范围。

不得决定营销文案、美学或页面顺序。

### B. 事实与合规红队智能体

读取：商品文档摘要、目标图组、`compliance.md`。

职责：寻找无依据参数、功效、适配、证据、价格、活动、授权、危险动作和视觉暗示。

输出工作包：

- 可用主张。
- 必须删除/降级的主张与画面。
- 需要人工复核或补资料的唯一关键项。
- 动态负面约束。

不得为了安全把所有创意都降级；只处理真实风险。

### C. 需求与图组策略智能体

读取：商品/事实摘要、用户目标、`demand-opportunity-system.md`、`asset-portfolio-system.md`、必要场景文件。

职责：判断应该做哪些图、每张解决什么问题、图组是递进/并列/混合、哪些图不值得做。

输出工作包：

- 图组对象与最小充分数量。
- 每张唯一任务、证据、参考图需求和前后关系。
- 建议增加/删除图片及代价。
- 主链与变体边界。

不得写最终提示词或凭空发明卖点。

### D. 电商转化与产品思维智能体

读取：图组任务、商品事实、营销/消费者/策划模块中必要内容。

职责：从买家任务、选择成本、误点、退货、理解、信任和使用边界审查每张图的必要性。

输出工作包：

- 本张要改变的用户认知或选择。
- 属性到利益的准确翻译。
- 文案命题与证据要求。
- 容易误导、重复或过载的内容。

商业与运营判断必须转译为图片任务，不能输出独立咨询报告。

### E. 视觉导演智能体

读取：商品视觉DNA、逐张任务、参考图能力、当前对象视觉文件。

职责：主风格、核心主体、空间、人物、视角、构图、光影、材质、色彩、信息安全区和组内连续性。

输出工作包：

- 图组视觉不变量。
- 每张视觉变量。
- 镜头/构图/场景/人物/光影执行规格。
- 视觉冲突与保真风险。

不得改变商品本体或用氛围代替证据。

### F. 图生图生产监制智能体

读取：参考图策略、视觉工作包、`production-methods.md`。

职责：判断图生图锁定、背景生成+抠图合成、局部重绘、实拍、3D或补拍；划分模型与后期职责。

输出工作包：

- 主/辅参考图和用途。
- 锁定层、重建层、生成层。
- 允许变化与禁止变化。
- 视角能力、遮罩/边缘/深度等通用控制建议。
- 后期合成、精确文字与修图要求。

不得假定用户拥有未声明的具体工具或模型功能。

### G. 提示词编译智能体

读取：已裁决且为`RELEASED`的商品、参考图、范围、结构、方向与分镜槽位合同，绑定当前 FS 版本的不可变分镜草案产物、视觉/生产工作包，以及 `prompt-orchestration.md`。

职责：把每张图编译成单义、可执行、分层清晰的中文图生图提示词和动态负面提示词。

输出工作包：

- 本张最终提示词。
- 本张负面提示词。
- 后期说明。
- 删除的歧义、冲突或不可执行内容。
- 绑定的输入合同版本、`status: PENDING`与 FR/PR `release_pair`；不得自行把提示词或对应分镜合同标为`RELEASED`。

不得重新决定商品事实和图组策略。

### H. 提示词失败诊断智能体

读取：原提示词、生成结果或用户反馈、参考图策略、目标分镜。

职责：定位失败属于身份漂移、结构变形、角度越界、材质失真、文字错误、场景物理错误、构图偏差、人物交互、指令冲突或负面词过载。

输出工作包：

- 最早失败层。
- 保留不变项。
- 需要修改的最小提示词片段。
- 是否应改用合成、补图或降低视角。

不得在未定位根因时整段重写。

### I. 个人偏好学习智能体

读取：本轮用户原话、选择、确认、否定、返修、最终采用项和 `persistence-evolution.md`。

职责：捕获用户在选图、张数、结构、卖点顺序、场景、人物、构图、审美、信息密度、保真、提示词语法和工作节奏上的偏好。

输出工作包：

- `preference_events`：event_id、时间、原始反馈、动作、维度、极性、标准化规则、五级范围、证据、置信状态、覆盖对象、失效条件、提示词字段和持久化授权。
- 本轮输入与当前任务临时要求。
- 商品/SKU、品牌/系列、用户通用规则。
- 稳定禁区、撤销、覆盖、局部例外与陈旧候选。
- 只读`preference_profile`偏好配置和下轮首推调整。

不得保存隐藏思考链、未经确认事实或把一次选择自动升级为永久偏好。静默、自动模式采用和未评价结果不得强化；没有明确持久化授权时只能会话内捕获。

### J. 提示词对抗审查智能体

读取：待发布的单张提示词、对应分镜/参考图/生产合同和放行标准。不要读取G的创作过程、评分或主控结论。

职责：以独立上下文方式尝试证伪提示词，查找商品漂移、参考图职责混淆、槽位冲突、未知面、物理错误、正负冲突、套路化默认和不可执行指令。

输出工作包：

- 可复现发现项及`Q0-Q3`严重度。
- 对应合同条款和最早失败负责模块。
- 必须保留的正确片段。
- 最小修复条件；没有问题时明确`NO_FINDING`。

不得替G写新策略、生成第二套完整提示词或把偏好当事实。

### K. 生图结果审计智能体

读取：实际生成图片、对应参考图、分镜/提示词发布配对版本和生图候选追溯记录。

职责：逐轴比较身份、几何、材质、颜色、文字、包装、配件、尺度、人物物理、槽位、单图任务与组内连续性。

输出工作包：

- 通过项与失败证据的可观察描述。
- 最早失败层及是否跨多个候选重复。
- 应保留的背景、构图或正确商品区域。
- `ACCEPT`、`PATCH_REQUIRED`或`TOOL_LIMIT`结论。

不得因一个随机候选失败就判定提示词错误，不得自行重生或修改提示词。

### L. 进化仲裁智能体

读取：I提交的偏好事件、选中与未选结果的差异、历史同范围记忆记录和当前事实/安全边界。

职责：用对比归因检查“用户究竟选择了哪个差异”，裁决证据等级、适用范围、冲突、覆盖、衰减与是否允许注入`preference_profile`偏好配置。

输出工作包：

- 可归因的显式规则与不可归因属性。
- `promote / keep_candidate / suppress / revoke / exception`动作。
- 最窄范围、证据等级、冲突与下一次验证条件。
- 可注入的具体提示词字段；没有明确证据时保持E0。

不得把整个获选画面的全部属性归因给用户，也不得授权持久化、修改商品事实或配置生图。

## 分工编排

### 常规商品图分镜

`A商品图法证 → C图组策略 → E视觉导演 → F生产监制 → G提示词编译 → J对抗审查 → 主控终检`

### 高风险或复杂SKU

`A商品图法证 + B事实合规`并行，完成后`C图组策略 + D转化产品思维`并行，再顺序进入`E/F/G/J`。

### 强创意全套

`S1：A/B形成商品与事实草案 → 主控发布商品/参考图合同 → S2：C/D形成需求预判 → 主控发布范围合同 → S3：C形成最小图组与结构建议 → 主控发布结构合同 → S4：C/D/E基于同一已发布输入并行形成固定5个方向，B按风险复核 → 主控发布方向合同 → S5：E/F建立并发布分镜槽位并物化当前分镜草案 → S6：G编译、J独立审查，主控原子发布FR/PR`。强创意只增加并行发散深度，不得跨过 SC/ST/DC/FS 或阶段令牌。

### 返修生成结果

`K结果审计（有图片时） → H失败路由 → 对应A/C/E/F/G最小返修 → J复查 → B按风险复核 → 主控交付`。

### 提示词交付后的可选生图

主控先按 `render-gate.md` 获取用户明确范围与每张候选数量，再调用当前环境可用的图片生成工具。子智能体不直接调用工具、不替用户扩大范围；结果由`K`对照冻结合同审计，异常时由`H`返回最早失败层，随后对应负责模块创建新的原子 FR/PR 配对最小补丁，主控仅在用户要求时重生受影响目标。

### 偏好进化

任务开始时，主控读取经`L`裁决的同范围稳定偏好摘要；每次用户选择、否定、纠正或返修后由`I`生成偏好事件，再由`L`做对比归因、范围与证据仲裁。提示词编译器启动前，`L`按“商品事实/安全 > 当前明确要求 > 更窄范围 > 同范围E3 > 较新E2 > E1 > E0”输出只读`preference_profile`偏好配置，只注入对应分镜字段。提示词交付时先形成可增量合并的学习快照；用户暂不生图、结束生图或请求进入`ACCEPTED/CANCELLED`后，`I/L`合并有效候选反馈并刷新最终学习包。只有用户明确要求记住、保存、以后长期使用或已有明确授权时才持久化；记忆文件存在不等于写入授权。偏好只改变合法候选排序、表达颗粒度和首推，不替代本轮商品、范围、结构、方向或逐图合同，也不自动配置生图范围、候选数量、运营执行或独立报告。

## 主控合并检查

- 所有角色是否使用同一商品身份和参考图编号。
- 图组任务是否覆盖真实需求且没有同义重复。
- 视觉方案是否在参考图和生产能力内。
- 提示词是否明确主/辅参考图、锁定/允许变化和后期边界。
- J是否只审查产物+合同，G是否只修复可复现发现项，没有生成者自审替代独立审查。
- K是否把随机候选失败与可重复提示词/合同失败区分开。
- 合规红队删除的内容是否从文案、场景、组件、提示词和负面词中同步清除。
- I/L是否只把可归因差异写入最窄范围，没有把获选画面全部属性或生图数量误学为偏好。
- 最终输出是否仍是统一分镜提示词，而非多角色分析报告。
