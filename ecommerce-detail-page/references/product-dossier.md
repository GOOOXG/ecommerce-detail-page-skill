# 商品文档与商品卡系统

本文件是商品文档聚合、AI补全边界、动态字段需求映射、商品卡展示、用户字段决策和商品合同发布的唯一来源。不负责原始图像识别、逐张设计或最终分镜。

## 目录

`两层结构` / `内部文档模式` / `输入来源` / `字段状态` / `商品文档结构` / `AI丰富流程` / `动态字段需求映射` / `可选信息补充建议` / `商品准备度摘要` / `自动跳过与字段恢复` / `商品卡信息识别内容` / `确认与修订` / `确认提交与输出接口`

## 两层结构

- 商品文档草案：内部结构化记录，汇总用户输入、图片识别、上下文、卖点参数体检、图片质量和行业字段。
- 商品信息确认卡：商品文档的用户可读视图，只展示与当前商品真实相关的字段、依据、风险和可选补充项。

先建立商品文档，再生成商品卡。不得用一张简短身份卡代替商品文档，也不得在商品卡确认前询问做主图、SKU图、详情页、海报还是素材图。

## 输入来源

按以下优先级聚合，并为每个字段保留来源：

1. 用户明确提供且无冲突的信息。
2. 图片清晰可见事实与产品原文。
3. 当前对话已确认资料。
4. 文件名、包装文字或附件说明线索。
5. 行业知识产生的字段需求与推断候选。

行业知识可以判断“可能需要什么字段”，不能凭空生成字段值。

## 字段状态

每个字段维护：值、来源、可信度、事实状态、设计相关性、用户决策和禁用范围。

| 状态 | 含义 | 下游权限 |
|---|---|---|
| 已确认 | 用户明确提供或确认的事实 | 可直接用于匹配的设计任务 |
| 图片可见 | 可从图片直接描述的形态、颜色、表面或原文 | 只描述可见内容，不延伸性能 |
| 推断候选 | AI基于品类、结构或场景提出的可能结论 | 可用于讨论和方案候选，不作为商品事实或确定文案 |
| 自动跳过 | 字段没有准确值、来源不可靠或仍存在歧义 | 写入跳过字段清单；商品卡和设计均不展示、不占位、不主动追问 |
| 冲突 | 来源之间互相矛盾 | 解除冲突前不能确认相关事实 |
| 禁用 | 用户明确不要或存在合规风险 | 所有下游删除相关表达 |

确认整张商品卡不会把推断候选升级为事实。只有用户明确补充、确认具体字段，或图片能直接证明时，字段才可升级。

## 商品文档结构

商品文档至少包含以下分区；没有实际相关性的字段不为凑完整而加载：

1. 商品身份：名称、品牌、型号、品类、子类、主商品/配件/替换件/耗材/套装关系。
2. 用户输入：原始商品描述、卖点、参数、目标平台、设计意向、数量、用途和禁区。
3. 视觉资产：参考图稳定编号与角色、商品视觉DNA、P0-P4参考能力、形态、比例、轮廓、颜色、材质表面、纹理、LOGO/原文、包装、配件、可用角度、缺失视角和不可改变项。
4. 功能与结构：可确认用途、工作关系、安装/使用方式、维护方式及结构候选。
5. 属性参数：规格、尺寸、重量、容量、成分、型号、数量、适配、执行标准等动态字段。
6. 卖点地图：事实卖点、可观察优势、推断候选、消费者利益、视觉承载和证据需求。
7. 买家地图：目标人群候选、使用场景、买家任务、主要顾虑、错误选择风险和决策复杂度。
8. 证据资产：报告、证书、专利、评价、销量、案例、售后、品牌授权及其真实性状态。
9. 图片生产能力：素材清晰度、遮挡、可抠图性、可用视角、可做特写、缺失角度和保真模式。
10. 字段决策：已采用、自动跳过、重新打开、冲突和禁用表达。

## AI丰富流程

1. 归一化：统一同义名称、单位、型号原文和商品关系，不擅自改写品牌原文。
2. 分类：先按参数标品、体验非标、安全敏感、高客单耐用品、高频复购、礼赠、圈层或服务判断决策结构，再映射行业。
3. 补骨架：加载该商品真正相关的属性字段，不加载全行业字段全集。
4. 反推任务：从商品作用、使用环境和购买风险推断买家任务、人群、场景和顾虑候选。
5. 拆卖点：把用户普通描述拆成属性、利益、证据、画面和限制；没有证据的停留在候选。
6. 计算字段相关性：不预先选择输出对象，但统筹评估每个字段对主图、SKU图、详情页、海报和产品素材图的潜在作用；用户已表达某类输出意向时提高该对象权重。
7. 识别缺口：缺少准确值的字段不进入商品事实区；高价值且用户可提供的字段进入一次性“可选信息补充建议”，其余直接进入内部跳过字段清单。只有关键身份冲突才向用户询问一个最小问题。
8. 设定边界：对自动跳过、冲突和禁用字段建立下游使用规则。
9. 生成商品卡：先输出准确、可追溯且对当前商品有价值的事实字段，再输出3到5项按价值排序的可选补充建议，不展示完整思考链。

## 动态字段需求映射

字段是否进入商品卡，由“商品相关性 × 买家风险 × 潜在设计价值 × 证据可得性”决定。AI可以推断字段需求，不能推断未知数值。

| 字段类型 | 解决的购买问题与进入条件 | 可能影响的设计 | 自动跳过后的设计降级 |
|---|---|---|---|
| 尺寸/规格 | 避免安装、穿戴、收纳、空间占用和型号选择错误 | SKU图、详情页，必要时主图 | 删除尺寸和比例承诺，只保留可见结构与非数据场景 |
| 材质/成分 | 解释质感、安全、耐用、触感、食品/美妆成分或清洁维护 | 主图特写、详情页、海报 | 只描述图片可见表面，不写具体材质性能 |
| 型号/适配 | 避免配件、替换件、耗材、接口、车型或机型买错 | SKU图、详情页、防退货页 | 删除适配结论和型号对照，不生成兼容承诺 |
| 数量/套装 | 说明到手内容、单件/多件和组合关系 | 主图、SKU图、详情页 | 不展示数量徽章、套装清单或赠品关系 |
| 安装/使用 | 回答会不会装、会不会用、步骤是否复杂和操作是否安全 | 详情页、无字场景图 | 只做结果场景或产品展示，不编排具体步骤 |
| 性能参数 | 证明核心性能和利益是否可信 | 主图利益化、详情页证明 | 删除数据与效果承诺，改为结构可见表达 |
| 维护/周期 | 解释清洁、更换、保存、保质或复购任务 | 详情页、复购素材 | 不写周期、寿命和频次，只保留一般维护场景 |
| 认证/检测 | 建立安全、健康、食品、美妆、母婴或医疗信任 | 详情页信任模块 | 删除认证、专家和检测背书，不制造证据占位 |
| 人物使用信息 | 解释人体尺度、穿戴、操作、安装、情绪代入或目标人群 | 主图、海报、详情页、无字场景图 | 可使用不限定具体人群的安全动作，或改为无人产品场景 |

例如尺寸对替换件很重要但用户没有提供准确值时，不得生成尺寸商品字段或猜测数值；商品卡可以显示“可选补充建议：尺寸”，并说明它可支持SKU选型、详情页参数和防买错表达。用户确认时仍未补充，则尺寸进入跳过字段清单，不出现在设计、文案、分镜或提示词中。

## 可选信息补充建议

AI在商品卡确认前，必须从主图、SKU图、详情页、海报和产品素材图五类潜在输出统筹一次信息需求。该步骤只推荐值得用户补充的资料，不提前选择输出对象，也不把未知值写成商品事实。

建议生成规则：

1. 信息不完整时默认输出3到5项；资料已充分覆盖高价值设计需求时删除冗余建议，不为凑数制造低价值字段。只有深度模式或用户要求完整资料清单时最多10项。
2. 按“防买错与安全影响 > 核心卖点证明 > 转化提升 > 视觉可视化 > 跨素材复用”排序。
3. 用户已明确某类输出意向时优先推荐能直接支持该对象的字段，同时检查其他对象是否有高复用字段。
4. 每项必须包含：建议字段、建议输入格式、适用输出对象、可启用的卖点或设计组件、不补充时的跳过结果。
5. 不提供候选数值、不诱导用户确认AI猜测、不要求一次补齐全部资料。
6. 只有用户提供准确值后，建议字段才转入商品事实区并记录来源；部分补充只启用对应字段。
7. 用户选择确认但没有补充时，所有剩余建议自动跳过，对应卖点、参数、证据、选型、活动或售后组件同步删除，不再次追问。
8. 商品主体、安全或合法性无法成立的关键问题不属于可选建议，必须单独阻塞并询问。

## 商品准备度摘要

商品卡内部评估但不伪造精确分数：

- 身份准备度：商品名称、品类、商品关系和型号是否足以避免认错。
- 视觉准备度：产品轮廓、材质表面、品牌原文和关键角度是否足以保持一致。
- 参数准备度：高相关字段中有多少已确认或自动跳过。
- 卖点准备度：是否存在可验证利益、可视化结构和证据边界。
- 场景准备度：是否知道真实使用环境、交互动作和人物参与方式。
- 商用准备度：可直接设计 / 适合背景生成后合成 / 需补产品角度 / 仅适合概念预览。

准备度用于决定生成方式和信息密度，不以缺失字段阻塞可继续的设计，也不以虚假的百分比制造确定感。

## 自动跳过与字段恢复

- 商品文档建立时，没有准确值、来源不可靠或语义有歧义的非关键字段不得进入商品事实区；其中3到5项高价值字段可在商品卡中作为一次性可选补充建议，其余自动跳过。
- 自动跳过字段写入跳过字段清单：后续主图、SKU图、海报、详情页和提示词均不展示，不写“待确认”，不制造参数占位；商品卡确认后不再主动追问。
- 后续仅选择SKU图、详情页或其他通常会使用该字段的对象，不构成重新打开理由；AI必须用现有准确事实设计，不足的页面任务直接删减或改用不依赖该字段的表达。
- 用户可在任何阶段输入“新增/补充字段名 + 准确值”，系统记录来源、重新打开字段并重发更新后的商品卡信息识别内容。
- 字段恢复后计算依赖范围：尚未设计内容直接读取新值；待确认或已确认图片只对引用该字段的任务、文案、视觉组件和提示词执行定向重算。
- 用户只说“增加尺寸”等字段名但没有准确值时，只询问该字段的具体值，不把空字段加入商品卡或设计。
- 身份、型号关系或安全合规冲突不能靠自动跳过伪装成确定事实；主体无法成立时必须先解除冲突。

## 商品卡信息识别内容

商品卡正文全部采用单行字段格式：`字段：内容`。不使用表格、长段落、子卡片或重复解释。商品事实字段只显示具有准确值和可靠来源的内容；可选补充建议必须明确标为建议，不能混入商品事实。自动跳过字段完全隐藏。

字段按当前商品的购买重要度动态排序，不机械套固定顺序：

1. 身份与选型：商品名称、品类、商品关系、品牌、型号、SKU、适配、安全边界。
2. 核心决策：核心用途、关键规格、尺寸、材质、成分、性能、数量和最影响购买的属性。
3. 视觉保真：形态、比例、轮廓、结构、颜色、表面、纹理、LOGO/原文和不可改变项。
4. 使用交付：安装、使用、清洁、维护、包装、配件、储存、周期和售后事实。
5. 元信息：识别置信度、信息来源、用户设计意向和禁用要求。

同层字段再按“买错/安全风险、转化影响、下游复用价值、证据确定性”排序。没有准确值的字段自动跳过并隐藏；低相关字段不显示。

```text
【商品卡信息识别内容】
- 商品名称：[值｜状态/来源按需]
- 商品品类：[值｜状态/来源按需]
- 商品关系：[值｜状态/来源按需]
- 品牌/型号/适配：[仅在有准确值时按重要度拆成独立字段；未知时整行删除]
- 核心用途：[已确认事实或边界表达]
- 关键属性：[只用准确值，按重要度逐项生成尺寸、规格、材质、成分、性能、数量等字段]
- 视觉特征：[形态、结构、颜色、表面、LOGO/原文等拆成独立字段]
- 使用交付：[安装、清洁、维护、包装、配件等高相关字段]
- 识别置信度：[结论]
- 信息来源：[用户、图片、上下文或文件]
- 用户设计意向：[仅在用户已提供时显示；未指定时整行删除]
- 可选补充建议1：[字段名]｜建议输入：[格式]｜支持：[相关输出对象]｜可启用：[卖点或设计组件]｜不补充：[自动跳过的表达]
- 可选补充建议2：[按价值排序；只写高价值建议]
- 可选补充建议3：[按价值排序；没有更多高价值建议时删除本行]
- 可选补充建议4：[按价值排序；没有更多高价值建议时删除本行]
- 可选补充建议5：[按价值排序；没有更多高价值建议时删除本行]
```

## 确认与修订

- 用户回复`1`、“确认、正确、没问题、继续”时，只有关键身份冲突清零才可确认；未补充建议批量转入跳过字段清单，对应卖点和组件一并关闭。
- 用户选择`2`到`5`或自然语言纠正后，更新商品文档、重算受影响字段和边界，并完整重发修订卡；修订卡必须再次明确确认。
- 中置信Top3选择只确定身份候选，不等于确认整份商品文档。
- 用户新增事实后记录来源；无法验证的卖点仍保留为推断候选。
- 已确认商品发生事实变化时，先使商品合同和受影响下游失效，重新确认后再继续。

## 确认提交与输出接口

确认时原子发布一个商品合同，统一承载商品身份、已确认事实、字段决策、禁用项、跳过字段清单、确认来源和用户原始设计意向；参考图索引、视觉DNA和能力轴由参考图合同承载。向 `reasoning-engine.md` 交付商品文档摘要时必须带完整商品合同信封，且`contract_version: PC-nnn`、`status: RELEASED`；确认后先生成设计需求预判，不直接进入对象专属设计。
