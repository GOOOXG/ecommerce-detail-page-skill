# 推演调度与合并模块

本文件只负责按固定主链调度专业模块、合并工作包、裁决冲突和建立状态/合同。它不重复保存需求方法、资产百科、策略模型、视觉规范或最终提示词模板。最终目标始终是决定“应该做哪些图、每张解决什么、使用哪些参考图、如何可靠生成”，再交给提示词编译器。

复杂任务读取 `multi-agent-orchestration.md`。各角色只提交结构化结论、依据、假设、风险与动作；主控不得向用户展示多智能体报告或隐藏思考链。

## 目录

`固定主链` / `分镜任务解读` / `推演旋钮` / `模块唯一职责` / `阶段调度` / `合并与裁决` / `深度推演门` / `认知状态` / `追溯、返修与进化旁路` / `输出接口`

## 固定主链

严格按以下顺序运行：

`商品卡确认 → 范围确认 → 多图结构 → 5个综合方向 → 逐图确认/自动内审 → 0-9动作 → 提示词发布 → 最终分镜 → 可选生图闸门`

- 每个新商品先建立商品合同与参考图合同。交互模式由用户确认；直出/全自动模式可内部确认，但节点必须存在。
- 商品卡确认后、范围确认前，只可生成需求预判工作包，不得确认输出对象、张数、结构或方向。
- 范围合同发布后才规划最小充分图组；结构合同发布后才生成固定5个综合方向；方向合同发布后才展开逐图设计与提示词。
- 用户已明确的对象、数量或方向可写入紧凑确认卡，不能要求重复作答，也不能把“内容已知”误作“节点可跳过”。
- 单图任务仍建立单张闭环结构；自动模式仍内部比较5个方向并逐图红队。

## 分镜任务解读

进入需求与方案推演前，主控先形成一行内部读法：

`把本任务读作：为【平台/输出对象】上的【目标买家与决策阶段】，用【核心商品事实/证据】解决【唯一购买问题】，在【参考图与生产边界】内采用【主视觉语法】。`

这不是独立报告。信息充分时直接建立；只有两种读法会实质改变范围、事实风险或生产方式且无法裁决时，才问一个最小问题。交互模式可在综合方向确认前显示一行供纠偏；最终分镜不显示该句。

## 推演旋钮

主控根据商品、平台、任务、参考能力与已确认偏好推断1到10的内部控制量，不要求用户填写配置，也不把数值写入最终分镜：

| 旋钮 | 控制问题 | 高值行为 |
|---|---|---|
| `FIDELITY_STRICTNESS` | 商品像素、结构、颜色、文字能容许多少重建 | 优先真实商品层、可靠原机位、遮罩与后期合成 |
| `EVIDENCE_STRICTNESS` | 画面主张需要多强的可核验证据 | 只保留直接来源、可观察事实与明确边界 |
| `VISUAL_VARIANCE` | 组内构图和场景允许多大差异 | 在共享视觉语法内拉开机位、空间、节奏和叙事变量 |
| `INFORMATION_DENSITY` | 一张图承载多少可见信息 | 允许更多但仍有层级的证明/选型组件，不增加第二主任务 |
| `SCENE_REALISM` | 抽象棚拍与真实使用情境的取舍 | 强化具体空间、尺度、接触、使用痕迹和自然光 |
| `CONVERSION_DIRECTNESS` | 直接说明购买理由还是侧重情绪记忆 | 强化利益、证明、选择与顾虑收口，减少纯装饰 |
| `COPY_DENSITY` | 成图需要多少最终上图文字 | 扩大文字安全区和后期排版容量，不让模型生成精确长文 |

旋钮必须映射到具体分镜字段，不得只保存数字。安全、合法、商品事实、参考能力和用户本轮明确要求始终覆盖旋钮；任一默认被品牌资产、真实场景或明确创意意图覆盖时，在追溯记录中写明依据。旋钮之间冲突时，按“保真/证据 > 当前图唯一任务 > 生产可行 > 视觉差异”裁决。

## 模块唯一职责

| 模块 | 唯一问题 | 输出工作包 | 禁止越界 |
|---|---|---|---|
| `reference-image-reasoning.md` | 参考图能证明和支撑什么 | 视觉DNA、P0-P4与能力轴、身份/视角/辅图策略 | 不决定人群、图组或营销方案 |
| `demand-opportunity-system.md` | 买家在何种情境要完成什么、受什么阻力、需什么证据 | 需求地图 | 不决定对象数量和逐图结构 |
| `asset-portfolio-system.md` | 用哪些图以最少数量完成任务 | 对象、数量、逐图职责与承接 | 不重新做人群研究或5个方向 |
| `strategic-intelligence.md` | 采用哪条因果路径与差异轴 | 主/次决策、证据路径、5个方向候选、反证结论 | 不保存商品事实、不编译提示词 |
| `reasoning-engine.md` | 何时调用谁、怎样合并与发布 | 阶段摘要、冲突裁决、下一阶段输入 | 不重复上述完整方法 |
| `prompt-orchestration.md` | 如何把已发布合同与工作包变成可执行图生图指令 | 正/负提示词与生产边界 | 不重新选择商品、图组或方向 |

后续模块不得修改上游合同。发现冲突时退回最早失败层，只重算受影响下游。

## 阶段调度

### 1. 商品事实阶段

输入：商品参考图、用户资料、历史稳定偏好草案。

调用：`product-analysis.md`、`reference-image-reasoning.md`、`product-dossier.md`；复杂或高风险任务可调用商品图法证与红队角色。

建立：商品身份、SKU/状态、可观察事实、禁用主张、稳定参考图编号、视觉DNA、生产能力轴与未知面边界。

放行条件：商品卡确认或自动模式内部确认。偏好只能改变首推表达，不能覆盖本轮商品事实、SKU、颜色、结构、原文或参考能力。

### 2. 需求预判阶段

输入：已确认商品事实与参考能力。

调用：`demand-opportunity-system.md`。只判断主图、SKU图、详情页、海报和素材图可能解决的买家任务、阻力、必要证据、触发条件与风险。

输出：全对象需求预判及用户原始意向映射。不得在此阶段替用户建立范围合同；字段已禁用时不得再次以“信息缺口”追问。

### 3. 输出与结构阶段

输入：需求预判、用户明确范围、平台/位置、默认数量规则。

先由主控确认输出对象、数量和用途，形成范围合同；再调用 `asset-portfolio-system.md` 与 `structure-selection.md` 建立最小充分图组，确认递进、并列、混合或单张闭环结构。

每张必须拥有唯一职责与真实信息增量。没有增量的页面合并或删除；不得为凑数量只换背景、同义文案或装饰。

### 4. 五个综合方向阶段

输入：已发布商品合同、参考图合同、范围合同和结构合同。

调用：`strategic-intelligence.md`，并按需读取营销、产品、运营、美学、视觉与生产模块。固定构造5个产品专属综合方向：

1. 转化稳妥：最关键购买问题与最强证据。
2. 平台适配：当前入口与阅读方式。
3. 价值品牌：价格带感知、长期价值与品牌识别，但不虚构价格。
4. 视觉差异：基于真实商品特征形成记忆点。
5. 情境情绪：基于真实任务、身份或生活时刻扩展相关性。

每个方向必须改变目标情境、主阻力、证据路径、渠道承接、价值叙事、视觉锤或生产形式之一；只换风格名或颜色不算新方向。交互模式由用户选择；直出/全自动模式内部比较后采用首推。未选方向不得混入下游。

### 5. 逐图编排阶段

输入：全部已发布上游合同与已裁决工作包。

对每张建立逐图工作包：唯一任务、图组角色、身份母图、视角主参考图、辅图及能力、产品锁定、允许变化、视角/事实边界、最终画面、镜头构图、人物物理关系、光影材质、文案白名单、生产与后期分工、动态失败风险。

交互模式交给 `frame-confirmation.md` 逐张确认；自动模式逐张执行内部红队。任何角色不得在此阶段重新定义商品、输出范围、结构或方向。

### 6. 提示词编译与发布阶段

先注入本轮只读`preference_profile`偏好配置：只把同范围、未撤销、通过证据门的偏好映射到参考图选择、场景人物、构图、信息密度、保真方式、文案和正负提示词颗粒度；不得改变商品事实、输出数量、结构、方向或确认状态。再调用 `prompt-orchestration.md` 编译逐张正/负提示词，执行草拟 → 批判 → 修复 → 发布循环，由 `final-checklist.md` 放行，最后严格使用 `storyboard-template.md` 聚合。最终核心交付只包含逐张分镜提示词，不包含多智能体报告、运营建议、测试计划、评分或内部模型。分镜交付后，只有用户明确选择时才由 `render-gate.md` 生成指定目标；生图结果与候选数量不得回写上游合同。

## 合并与裁决

主控按以下优先级裁决冲突：

`安全与合法 > 商品事实与视觉DNA > 用户本轮明确要求 > 当前阶段合同 > 生产可行 > 买家任务与证据 > 品牌连续 > 创意差异`

- 事实冲突：回到商品卡，不能以多数角色意见覆盖。
- 参考能力不足：换为可靠视角、真实商品抠图合成、补拍/建模或删除该画面；不得让模型猜未知结构。
- 需求冲突：选能解决当前主阻力且证据最强的任务，最多保留一个次任务。
- 图组冲突：选择页数更少、信息增量更高、退货风险更低的结构。
- 视觉冲突：保留方向合同的视觉锤；风格不能牺牲商品可识别性与材质真实性。
- 生产冲突：采用现实降级路径，不把概念稿冒充商用真实商品图。
- 无法裁决的关键身份、型号、适配、安全或授权问题，只问一个能解除阻塞的问题。

## 深度推演门

“最高推理”意味着更严格地验证决策，而不是输出更长：

1. 硬约束门：商品、事实、合规、用户禁区与阶段合同任一失败即淘汰。
2. 因果门：每个画面必须能说明“可验证事实/情境如何缓解哪项阻力”。
3. 证据门：主张、画面和证据相互对应；图像氛围不能冒充功效或认证证据。
4. 信息增量门：每张新增事实、利益、证明、场景、选择或顾虑解法。
5. 参考能力门：身份、几何、材质、颜色、文字、配件、尺度、证据及新视角能力逐项通过。
6. 物理可行门：人物、商品、道具、尺度、重力、接触、遮挡与光影关系成立。
7. 反事实门：去掉文案、场景、人物或装饰后，判断核心任务是否仍成立；无贡献元素删除。
8. 红队门：从认错商品、串SKU、未知面、伪事实、买错、不可生成、平台/安全风险挑战首推。
9. 最小充分门：效果相近时选择更少页面、更强证据、更稳生产和更低返修成本。

只记录结论、关键依据、风险和修改动作，不展示逐步思考链。

## 认知状态

- **已确认**：用户明确提供或权威资料支持。
- **可观察**：图片中直接可见的外观、结构、颜色、材质表面和原文；不得延伸功效。
- **策略推断**：只用于人群候选、情境、顺序、构图和方案，不转写为参数、适配、效果或证据。
- **待验证**：可能影响策略但缺少来源，只能形成验证问题或保守备选。
- **禁用/冲突**：删除或回到商品卡纠正，不能用模糊措辞或视觉暗示绕过。

## 追溯、返修与进化旁路

- 任务开始读取同范围、达到证据阈值的稳定偏好，仅影响候选排序、表达颗粒度和首推；商品事实与用户本轮指令永远优先。
- 每次选择、否定、纠正或返修后捕获临时差异；只有最终采用项或经确认有效的修复才能强化。
- 提示词编译器启动前，将当前有效偏好汇总为只读`preference_profile`并注入对应提示词字段；它不配置生图范围或候选数量，也不参与运营执行。
- 新事实回到商品卡；输出变化回到范围合同；页面重复回到结构合同；人群/卖点/视觉方向变化回到方向合同；生成失真回到参考图/生产/提示词层。
- 失败诊断只定位最早失败层；偏好学习作为旁路，不得改变主链阶段或自动替用户确认。
- 每个下游工作包保留来源合同与发布版本追溯，确保返修可回到最早失败层。
- 任务结束生成内部学习包，只记录最终采用项、明确否定与有效修复；学习包不得对外扩展为偏好报告、生图配置或运营动作。

## 输出接口

向下一阶段只交付必要合同与工作包摘要：

- 每个阶段：先交付负责模块的合同版本信封与实际`parent_versions`；商品`PC-nnn`、参考`RC-nnn`、范围`SC-nnn`、结构`ST-nnn`、方向`DC-nnn`，只有`status: RELEASED`可被下一阶段消费。
- 商品阶段：商品事实、参考图索引、视觉DNA、能力轴和禁用边界。
- 需求阶段：主任务、情境、主/次阻力、必要证据及对象触发条件。
- 输出结构阶段：对象、数量、用途、结构、逐张唯一职责和承接。
- 方向阶段：方向合同信封（`contract_version: DC-nnn`，父版本至少含 PC/RC/SC/ST）、已选方向的目标情境、价值/证据路径、视觉锤、生产边界和失败条件。
- 逐图阶段：完整逐图工作包。
- 最终阶段：只向提示词编译器和分镜模板传递已发布生产字段。
