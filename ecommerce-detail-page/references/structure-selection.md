# 图组结构选择系统

本文件是主图、SKU图、海报和详情页在正式图组编排前进行结构推荐、用户选择、结构合同发布和重选影响处理的唯一来源。不负责逐张角色细则、文案生成、视觉设计或最终分镜格式。

## 目录

`结构闸门位置` / `三种结构` / `输出对象注解` / `AI推荐算法` / `结构选择卡` / `多输出对象` / `结构合同` / `重选与返修` / `输出接口`

## 结构闸门位置

执行顺序固定为：

`建立商品文档草案 -> LLM对话确认商品信息 -> AI预判全对象设计需求 -> 用户确认输出对象与数量 -> 初步推演买家任务 -> 推荐并确认图组结构 -> 推荐并确认综合方案 -> 编排卖点/文案/视觉与逐张角色 -> 逐图确认 -> 最终分镜`

主图、SKU图、海报和详情页只要输出数量大于1，必须先形成已发布结构合同，才能进入综合方向选择；方向合同发布后才能生成逐张角色、文案矩阵、卖点分配、视觉节奏和图生图提示词。用户已在原始要求中明确结构时直接写入结构合同，不重复询问。

单张输出没有图组关系，结构合同直接采用“单张闭环”。产品白底图、透明图和无字场景素材默认按资产角色并列，不强制展示三选一；用户要求素材组叙事或混合投放时才调用本文件。

## 三种结构

### 1. 递进式主次

第1张承担主入口，后续图片逐张新增信息和购买理由。适合需要连续理解、商品页轮播承接、复杂卖点教育或从注意到行动的完整路径。

核心约束：后一张必须新增命题，不能重复上一张；返修上游核心页时需要检查下游连续性。

### 2. 等量并列

每张都能独立成立，没有“次图”地位。适合独立投放、多个真实SKU、多平台适配、多人群/多场景覆盖或A/B测试。

核心约束：共享商品与品牌不变量，但每张必须拥有不同购买问题、场景或测试变量；局部返修默认不影响其他图。

### 3. 混合结构

先用部分图片形成递进主链，再用剩余图片做独立SKU、场景、人群、平台或A/B变体。适合既要商品页成套解释，又要保留独立投放资产的任务。

核心约束：明确主链与变体边界；主链按递进依赖，独立变体按并列依赖。没有双重目标时不为了复杂而启用。

## 输出对象注解

### 主图

| 结构 | 具体含义 | 适合情况 | 对后续设计的影响 |
|---|---|---|---|
| 递进式主次 | 第1张负责搜索截停和主体识别，后续依次承接利益、结构证明、场景和防错/信任 | 单商品成套主图、商品轮播、卖点需要逐步讲清 | 文案和卖点按“识别 -> 利益 -> 证明 -> 场景 -> 信任”拆分 |
| 等量并列 | 每张都是可独立投放的主图 | A/B测试、多平台、多场景、每张都要承担点击 | 每张都有独立钩子、主利益、视觉锤和行动理由 |
| 混合结构 | 前几张建立商品理解，后几张作为独立投放变体 | 既要商品页图组，又要测试素材 | 主链卖点递进，变体只改变明确人群/场景/测试变量 |

### SKU图

| 结构 | 具体含义 | 适合情况 | 对后续设计的影响 |
|---|---|---|---|
| 递进式主次 | 从SKU总览进入规格差异、型号识别、套装关系和适配防错 | SKU关系复杂、买家容易选错 | 信息按选择步骤递进，不重复规格字段 |
| 等量并列 | 每张独立展示一个真实SKU或同等权重选项 | 多颜色、多款式、多型号分别销售 | 统一机位和标签，每张突出自身差异与适配对象 |
| 混合结构 | 先做总览/对比，再为主推或易混SKU做独立图 | 同时需要选择教育和单SKU展示 | 主链解释怎么选，变体负责具体SKU识别和防错 |

### 海报

| 结构 | 具体含义 | 适合情况 | 对后续设计的影响 |
|---|---|---|---|
| 递进式主次 | 主题主视觉后依次进入场景种草、利益证明、情绪/信任和行动 | 系列传播、活动预热到转化、连续发布 | 每张只承接一个传播阶段，主题资产保持连续 |
| 等量并列 | 每张都是独立传播海报 | 多平台、多圈层、多主题测试 | 每张拥有独立主题、产品利益和行动方向 |
| 混合结构 | 保留主题传播主链，同时生成平台/人群独立变体 | 品牌活动兼顾统一主题与分渠道投放 | 主链统一叙事，变体沿用品牌资产但独立成立 |

### 详情页

| 结构 | 具体含义 | 适合情况 | 对后续设计的影响 |
|---|---|---|---|
| 递进式主次 | 从首屏承接、痛点、卖点证明、场景、信任、参数到顾虑收口形成连续阅读链 | 单商品、决策路径清楚、短中型详情页 | 页序严格服务购买阶段，前后钩子连续 |
| 等量并列 | 主体模块同级独立，可按场景、人群、卖点或证据自由组合 | 多场景、多受众、跨平台复用模块 | 每个模块独立解决一个问题；完整详情仍保留必要首屏和收口 |
| 混合结构 | 核心转化链保持递进，中段场景/人群/证据模块并列 | 长详情页、复杂产品、高客单、多证据 | 主链保证转化闭环，并列模块便于替换、增删和跨平台复用 |

## AI推荐算法

在选择卡中必须先给一个首推，但不能替用户静默确认。按以下因素判断：

1. 投放用途：商品轮播/连续阅读偏递进；独立投放/A/B测试偏并列；两者兼有偏混合。
2. 产品复杂度：单卖点、短决策偏递进或并列；多卖点、多证据、高客单偏混合。
3. SKU关系：选择路径复杂偏递进；真实SKU同等权重偏并列；总览加单SKU展示偏混合。
4. 平台：货架商品组偏递进；内容流多素材测试偏并列；跨平台资产矩阵偏混合。
5. 张数：2张通常选递进或并列；3张以上才在确有双重目标时考虑混合。
6. 复用目标：只服务一个商品页偏递进；需要拆分复用、投放测试偏并列或混合。

推荐输出包含：首推结构、两条产品化理由、对文案/卖点编排的直接影响、一个风险提醒。不要只写“更适合”。

## 结构选择卡

在正式图组设计前正常渲染：

```text
【图组结构选择｜[输出对象][数量]张】
- 系统首推：[结构名称]
- 推荐理由：[结合产品、平台、数量和投放目标的2条理由]
- 对后续影响：[卖点如何拆、文案如何分工、页面如何衔接]

1. 递进式主次：[当前输出对象的具体注解]
2. 等量并列：[当前输出对象的具体注解]
3. 混合结构：[当前输出对象的具体注解]
4. 采用系统首推：由AI写入推荐结构
5. 自定义：说明主链张数、独立变体、顺序或特殊用途
```

系统首推在1到3中对应项标记“【推荐】”。用户回复`1`、`2`、`3`或`4`后写入结构合同；回复自然语言结构名称等同于数字选择。没有选择时不得进入逐张卖点、文案和视觉编排。

## 多输出对象

主图、SKU图、海报和详情页分别拥有独立结构合同，不允许把主图结构自动套给其他素材组。

用户要求多个对象或全部设计时，优先一次输出紧凑的批量结构选择卡，每组都给首推和简短注解。支持回复：

```text
主图1，SKU2，海报3，详情页3
```

也支持“全部采用推荐”。未选择的素材组保持待确认，不开始该组设计。产品素材图按资产角色并列，不混入此批量选择，除非用户主动自定义。

## 结构合同

确认后记录：输出对象与数量、选择结构、选择来源、选择理由和风险、主链/并列范围、下游编排约束、返修依赖和状态。

下游只能消费状态为`RELEASED`的结构合同。全自动、直出和通版可由AI采用首推并自动确认，但仍必须建立结构合同。

## 重选与返修

- 尚未设计单图：重选后直接重建角色序列。
- 已有待确认单图卡：该卡失效，按新结构重新推演。
- 已有已确认卡：先说明全部受影响图序，用户确认后使当前素材组单图卡失效并重新编排；其他素材组不受影响。
- 只调整混合结构的主链/变体范围时，保留能映射到新角色且语义不冲突的卡，其余卡失效。

不得在用户确认结构后静默切换结构。AI发现结构不适配时，只能提出重选建议和影响范围。

## 输出接口

向执行引擎交付：结构合同版本信封（`contract_version: ST-nnn`、规范`status`、负责人、`parent_versions.scope: SC-nnn`与来源追溯记录）、结构选择卡、系统首推、已确认结构快照、主链/并列范围、下游编排约束、返修依赖和受影响图序。只有`status: RELEASED`可进入方向阶段。
