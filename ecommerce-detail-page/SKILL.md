# 商品图深度推演与图生图分镜

本技能的唯一最终交付是逐张、可直接执行的中文图生图分镜提示词。对话中的建议卡、商品卡和必要确认只用于把事实、目标、授权和生产路径收敛清楚，不另交运营或分析报告；生图结果反馈只用于后续返修和受控学习。

## 不可妥协

1. 先实际查看全部可访问参考视觉的像素或真实画面内容并识别核心对象、商品形态、SKU或权益版本和状态，再决定制作什么图片，最后才写提示词。用户口述的图片清单、文件名、附件数量、替代文字、聊天摘要或“已经提供图片”的声明都不等于实际看图，不能据此补造视觉事实。实体商品使用实拍、包装、结构图等资料；数字权益或服务可使用真实界面、权益页、流程截图、授权页或已授权服务场景。完全没有可直接查看的参考视觉时停止本图生图技能，只请求最小必要素材，不伪装成已完成图生图分镜。
2. 核心对象身份不得无依据改变：实体商品保护轮廓、结构、比例、颜色、可观察表面、包装、配件、标志和可见原文；数字权益或服务保护真实界面、权益版本、流程、交付状态、授权、品牌视觉和可见原文。先区分商品身份证据、结构细节、包装/界面文字、尺度使用、视觉灵感和反例；风格图与竞品图只影响视觉表达，不证明当前商品事实。
3. 隐藏视图规则只对实体商品中真实存在且与当前图片任务有关的目标启用。已有可确认的同SKU真实目标视图时直接作为证据；缺少直接资料时，适用的背面、底部、内部和拆解分别评分，只有超过80分的目标才进入“写实视图确认”候选，必须由用户用序列号确认后才可写入写实分镜。预构建时任务相关性已经明确就当场列入确认候选并推送确认卡；尚未明确就只在商品卡记录“待范围判断”，等商品卡与输出范围确认后立即筛选并推送确认卡，始终在图组编排前完成。未确认的推理目标不得进入写实分镜；数字权益、服务及不具备该物理面的商品直接记为“不适用”，不评分、不弹确认卡。
4. 每个独立画面单元只解决一个主要购买问题；连续详情页可以作为一个最终长画布承载多个顺序模块，但每个模块仍只解决一个主问题。多图或多模块必须有新的事实、证据、选择帮助、场景或顾虑解法，不能靠换背景凑数量。
5. 商业、运营、产品、营销、消费者心理和美学判断必须落到“做什么图、为什么、怎样画、什么不能画”。按注意力抓取、三秒信息效率、信任、情绪与身份、转化驱动、平台与无障碍适配六个维度模拟用户决策，不另行输出分析报告。
6. 用户给出的图型、案例、行业或参考项目默认是思维起点，不是能力上限。每次先匹配已有知识，再主动检查关键买家问题是否遗漏；新候选仍必须通过事实、生产、风险、平台和新增价值检查。
7. 事实与安全使用必要硬边界，创意与探索使用正向目标、可变空间和成功标准。在不改变商品事实、不误导购买且能够生产的范围内，优先告诉AI要实现什么、哪些内容可以自由发挥，不用通用禁令压缩合理想象。
8. 分析、确认、说明和提示词使用自然中文；商品原文、品牌、型号、文件名和必要工具字段可保留原样，画面最终文案可按用户确认的销售市场与展示语言处理。
9. 正式提示词先完整交付；生图是后续可选动作，默认不自动执行。
10. 平台尺寸、广告规则、促销条件、法规与资质有效性属于会变化的外部事实。只有用户资料或任务当时可核验的当前官方来源才能作为精确依据；无法核验时保留安全区和待适配说明，不把记忆中的旧规则写成“最新要求”。
11. 真实界面、订单、授权文件、用户案例或场景照片包含个人、账户或可用编码信息时，先做最小必要使用和发布权限判断；未经明确授权且非画面必需的内容先遮盖、裁掉或替换，不把私密证据像素发送给生成工具。
12. 在图组规划前确定一个首要买家目标、最多两个次要目标和不可牺牲的事实/安全/平台护栏；不要把六个决策维度当成同等优先级。
13. 对会进入商品卡、文案、画面或提示词的重要主张建立内部轻量证据账本，区分图片可见事实、用户声明、当前可核验资料、策略推断和未知内容；用户确认授权画面不等于补足证据。
14. 在确定结构和生产路径前完成工具能力画像；多参考、遮罩、透明通道、精确文字、分层合成、画布比例和候选数量不能等到提示词写完后才发现不成立。
15. 推演深度按不确定性、错误代价和新增信息价值自适应；综合方向最多比较5个，不强制每次生成5个。生图后按结果复核并只更新受影响字段，不把沉默或工具失败当成偏好。

## 唯一工作主线

`识别商品主体 → AI预构建 → 编号建议/手动纠正 → 商品卡（待确认） → 用户确认或明确直出授权 → 已确认商品卡 → 首要目标/风险/工具能力画像 → 设计需求预判与输出范围 → 自适应多图结构与综合方向 → 图组编排 → 逐图确认/内部自动复核 → 最终分镜 → 可选生图与结果反馈`

这条主线不可倒置。默认先让用户确认商品卡，再确定首要目标、风险和生产能力，最后问真正要做什么图；用户明确说“直接出”“只要提示词”“全部采用AI推荐并确认”等直出授权时，可以压缩建议菜单，但仍必须完成主体、SKU、事实、素材、安全和授权冲突检查。单一清晰目标且无关键冲突时可把明确直出授权视为确认；多SKU、相似款、主体/SKU/状态不确定或关键卖点、素材、授权未证实时，必须展示商品卡并等待用户确认或纠正，不能由模型自行静默确认。范围、结构和方向确定后才编排第1张；当前图确认或内部自动复核通过后才进入下一张。每次确认都要区分授权范围，不把商品卡、隐藏视图、分镜和生图数量混成一次确认。商品卡、需求卡和确认卡都只是对话中的确认依据，不是额外的运营交付。

## 深化推演控制

静态图型库不能代替主动推演。主线中每个会改变商品判断、图片需求、图组结构或逐张任务的节点，按不确定性、错误代价和新增信息价值执行一轮或多轮推演循环（loop）：

`证据观察 → 问题建模 → 发散候选 → 跨域组合 → 反证淘汰 → 收敛排序 → 阶段落位 → 缺口回看`

- **证据观察**：综合读取全部有效参考图和用户资料，先区分事实、可见内容、策略推断与禁用内容。
- **问题建模**：从商品决策特征、输出对象和用户决策六维中找出当前最重要的买家问题，不从固定风格或图型名称出发。
- **发散候选**：以图型库为起点，主动提出能够解决问题的不同画面、证据、场景和生产路径；用户示例不是默认上限。
- **跨域组合**：把商品、运营、商业、产品、营销、审美、场景和生产知识只组合成可画的图片职责；每张仍只保留一个主问题。
- **反证淘汰**：主动寻找串SKU、伪事实、缺证主张、物理错误、平台风险、重复任务、不可生产和文字重绘问题，先淘汰硬伤。
- **收敛排序**：只对通过硬门槛的候选做价值排序和新增价值去重，选最小充分图组，不以候选多证明思考深入；简单任务只保留首推，中等任务比较1–3个真正改变任务的候选，复杂任务才扩大比较范围，综合方向最多5个。
- **阶段落位**：只把采用结论写入当前阶段允许的结果：预构建落到编号建议，商品确认落到商品卡，范围阶段落到对象、数量、结构和方向，图组阶段落到逐张任务；只有正式分镜阶段才落到分镜字段和正负提示词。不得借循环提前越过商品卡或范围确认。
- **缺口回看**：从买家最终看到的图组反查是否仍有识别、选择、证明、使用、场景、交付或行动缺口；发现关键缺口就回到问题建模，无新增价值或无证据可支持时停止。

同一结论只推演一次。进入提示词阶段后，复用已经确认的商品卡、范围、结构、方向和逐张任务，不重新发散商品身份、输出数量或图组方案；只对当前画面的表达、物理关系、生产可行性和指令兼容做“编译 → 反证 → 最小修复”。只有反证发现上游事实或任务真的错误时才返回对应阶段，不能用重复循环制造流程感。

多SKU、高风险、跨行业、陌生商品或多个候选难分高下时，按 [enhancements.md](references/enhancements.md) 增加独立角色反证或第二轮推演；简单任务可以压缩对外展示，也可以只运行一轮，但不能跳过事实、反证和可执行性检查。不要用循环次数、子智能体数量或候选数量证明思考深度。

### 1. 识别商品主体

读取 [product-and-reference.md](references/product-and-reference.md) 和 [prebuild-and-product-card.md](references/prebuild-and-product-card.md)。实际查看每张可访问参考视觉；可在内部按上传顺序建立临时稳定编号用于纠错和证据追踪，但正式分镜不输出编号。先判断商品形态是实体、数字权益还是服务，再提取全部有效资料中的品类、核心对象、品牌、型号或版本、SKU或权益档位、状态、可见结构或界面、文字、包装或交付载体、配件或权益、尺度或使用范围、场景和冲突；同时区分商品身份、结构细节、包装/界面文字、尺度使用、视觉灵感和反例职责，形成按SKU/版本/状态分组的综合依据，再进入预构建。

把结论分为“用户已确认事实、参考视觉可见事实、策略推断、待验证/禁用”。核心对象或SKU/版本无法合理区分时只指出一个关键冲突，不提前写分镜。

### 2. AI预构建

在同一轮对话中基于全部有效参考视觉的综合结论，读取 [category-adaptation.md](references/category-adaptation.md) 的“预构建初筛”规则，只把商品决策特征作为待用户确认的需求假设；再读取轻量的 [image-type-index.md](references/image-type-index.md) 做候选初筛，不在商品卡前提前加载完整图型规划：候选卖点与文案方向、需要用户提供的事实与内容、可用素材、缺失素材、建议图片、视觉与生产条件。可轻量读取 [marketing-reasoning.md](references/marketing-reasoning.md) 的**营销模型加速层**，把“特征→可能利益→待补证据”用于卖点候选排序；这一层只提出问题和证据需求，**不改变主流程**，不锁定对象、数量或图组。实体商品再记录适用隐藏视图的直接证据状态或独立还原置信度；非实体或物理目标不适用时直接跳过。此时不使用“已确认商品卡”规则，不锁定输出对象、数量、图组结构或最终图型；“建议图片”只是帮助用户判断需求的非约束性假设，用户选中只表示愿意把该买家问题带入商品卡和后续范围判断，不等于确认正式对象、分镜数量、图型或顺序。卖点与文案可以深度拓展表达，但不能把参考视觉未证明的参数、功效、权益、认证或承诺写成事实。缺少同SKU直接目标视图时，先记录超过80分的适用候选；当前原始意向已足以判断候选与任务有关时，单独给出序列号等待确认，意向仍不清时标记“待范围判断”，不为了提前发卡而假定输出对象。展示密度服从决策复杂度：简单且资料充分时只给首推和真正会改变分镜的备选，复杂任务通常展示3–5项。

### 3. 编号确认与手动纠正

先展示AI首推和编号选项，再等待用户选择。主建议选择完成后，若缺少直接证据的适用隐藏视图中有超过80分的目标且当前任务相关性已经明确，单独显示一张“写实视图确认”卡，只给可确认目标分配序列号；意向不足以判断相关性时暂不弹卡，在商品卡中记录“待范围判断”，待输出范围明确后再筛选。低分和不适用目标不塞进操作卡，仅在商品卡中按相关性紧凑记录。若没有候选且本次任务不需要未知面，只显示“未启用未知写实视图”，不逐项展示无关分数。该卡不与其他数字菜单同时出现。用户选择后先生成“商品卡（待确认）”，不能把这一步当成最终确认。编号只用于当前可见卡；字段内选择必须写成`主体：1；卖点：1,3；图片：1,2`，裸单个数字只执行当前卡的操作项，无法判定含义的裸多个数字只问一句澄清，不猜测。看到新的卡后按新卡重新选择，自然语言纠正始终有效。用户可以回复当前卡中的序列号，也可以使用紧凑格式：

```text
主体：1；卖点：1,3；补充：容量=750ml；图片：1,2,4
```

紧凑格式只处理当前“AI预构建建议”卡；写实视图序列号必须等独立“写实视图确认”卡实际显示后再回复，不能预填或猜测。用户在主建议卡说“全部采用AI推荐并直接确认”“直接出”“只要提示词”“不要逐步问”或其他无歧义的直出表达时可压缩建议菜单，但直出不自动确认任何尚未编号的写实视图：默认排除这些候选；用户明确要纳入时，先显示独立确认卡，再由用户回复卡内序列号。独立确认卡已经是当前唯一可见卡时，`写实视图：1,3`或裸序列号才有效。系统仍先生成并记录商品卡（待确认），检查SKU、事实、素材、授权和视图选择冲突；单一清晰目标且无关键冲突时，才把用户的明确直出授权视为该待确认卡的确认，不是模型自行确认；多SKU、相似款、主体/SKU/状态不确定或关键卖点、素材、授权未证实时必须展示卡并等待确认，存在其他关键冲突时只问一个最小问题。用户指出识别错误时，以纠正为准，重发受影响的建议，不继续沿用旧结论。

### 4. 生成并确认商品卡

读取 [prebuild-and-product-card.md](references/prebuild-and-product-card.md) 和 [evidence-and-feedback.md](references/evidence-and-feedback.md) 的商品卡规则。用户选择或纠正后，先汇总一张标明“待确认”的商品卡：商品形态、核心对象与识别置信度、SKU/权益版本清单与状态、每个对象的综合有效参考内容、参考视觉和用户确认事实、采用卖点、待补证卖点、已有/缺失素材、用户原始输出意向（仅作待确认线索）、必须保持/允许变化/必要边界和纠正结论。对进入商品卡、文案或画面的重要主张，内部同时记录来源、具体证据、可用范围和不可推导内容；不能证明的主张不因写入商品卡而升级为事实。实体商品增加适用隐藏视图的直接证据、独立置信度，以及已确认、未选择或“待范围判断”的状态；只有实际显示过确认卡的目标才记录序列号。数字权益或服务则记录交付内容、发放/预约、激活/有效期、权限与地区、退款/取消/续费、授权和异常处理边界，并把物理隐藏视图标为不适用。

向用户明确询问“确认商品卡”或“需要修改什么”。商品卡汇总此前已确认、未选择和因任务范围未明而暂记“待范围判断”的写实视图；当前任务相关性已明确但显式选择尚未完成时，才补发一次独立“写实视图确认”序列号清单。用户回复序列号（例如“1、3”）只确认对应视图，不等同于确认商品卡。待确认卡阶段仍不提供商品卡裸数字确认；用户只回复“1”等数字时，除非当前上下文明确是写实视图确认清单，否则不视为商品卡确认。当前唯一可见确认对象就是商品卡且没有歧义时，“确认”“没问题”“按这个”“就这样”与“确认商品卡”等价；“继续”和裸数字仍不确认。只有用户明确确认商品卡，或单一清晰目标在完成内部冲突检查后收到明确直出授权，才把卡标为“已确认商品卡”；多SKU、相似款、主体/SKU/状态不确定或关键事实未证实时必须展示卡并等待确认。直出或全部采用推荐都不能自动纳入视图候选：未被序列号确认的目标一律排除；交互任务中因范围未明而延期的候选，在范围明确且确实相关时必须再发确认卡。已确认的写实视图写入后续写实分镜范围；正式分镜不显示分数、置信度或任何推定性质标签。

非关键资料可以由用户选择跳过并在后续删除相关主张；主体、SKU、安全或合法性仍不成立时只问一个最小问题。商品卡确认前不编写正式分镜。

### 5. 首要目标、风险与工具能力画像

商品卡确认后、正式确定图组前，读取 [evidence-and-feedback.md](references/evidence-and-feedback.md)。先确定一个首要买家目标、最多两个次要目标和不可牺牲的事实/安全/平台护栏；没有明确目标时依据输出位置和买家任务给出首推。再把当前任务划为低、中或高风险：健康、安全、性能、认证、价格促销、兼容承诺和个人信息属于高风险，不能只靠视觉推断或80分门槛放行。

同一阶段前置记录执行环境能力：多参考图、图生图/编辑、遮罩、真实透明通道、精确画布、独立负面提示词、分层合成、批量候选、真实文字/界面层保留和结果回溯。工具能力未知时，优先采用真实商品/界面层加背景生成的保守生产路径；能力不足若会改变任务语义，先让用户确认降级，不把工具限制留到提示词完成后才发现。

在商品卡确认且首要目标已明确后，按当前阻力按需读取 [marketing-reasoning.md](references/marketing-reasoning.md) 的“模型调用卡：从触发到分镜”，进行一次正式**营销模型加速层**调用：默认选择一个主模型，最多两个辅助检查，把结论统一编译为“商品事实→买家任务→阻力/动机→卖点/利益→证据需求→图片任务→文案命题→生产边界→成功标准”。模型只帮助排序和构设画面，**不改变主流程**、不新增确认步骤，也不替代证据账本；无法证明的主张自动降级为可观察特征、待补证或删除。

每次确认都说明授权范围：商品卡只锁定商品与事实摘要，写实视图序列号只允许该视图成为本次画面目标，范围确认只锁定对象与数量，单张确认只锁定当前分镜，生图选择只授权指定分镜和候选数量。用户确认不自动补足证据。

### 6. 需求预判与输出范围

读取 [confirmation-workflow.md](references/confirmation-workflow.md)。仅在“已确认商品卡”成立后确认对象、平台、用途、可执行的画布方向与比例，以及多SKU/版本映射；销售市场、展示语言、单位或阅读方向会改变文案、版式或合规时才一并确认。数量必须分清三层：最终交付的成品数量、需要编写的分镜或详情页内部模块数量、提示词交付后的每分镜生图候选数量。用户没有给比例但位置明确时由AI首推可执行比例，用户可纠正；不能只因像素未知而留下无方向、无比例的最终分镜。用户已经明确这些内容且无冲突时，原意向本身即完成范围确认；把一行范围摘要与结构首推放在同一轮，摘要只作透明记录，不等待用户再次回复。只有摘要暴露冲突或会改变分镜的缺口时才停下确认。只缺少一两项时仅补齐会改变分镜的选项；意向不清或用户要求完整探索时才展示覆盖主图、SKU图、详情页、海报、适用产品素材图、全部设计和自定义组合的“设计需求预判卡”。“产品素材图”不是正式输出对象；用户选择后必须继续确定白底图、透明图或无字场景图及各自分镜数量。用户只说“整张详情页”“详情页1张”或“详情页1组”时，先确认其中的“1”指最终长画布、单个模块还是一组页面；若指最终长画布，记录为“成品1张 + 内部若干个模块/分镜”。实际模块数必须等于已确认商品卡中有具体依据、能够命名且互不重复的买家任务数，由AI按最小充分决策链首推并允许用户纠正；不按通用详情页习惯默认8、10或12个模块，不用“结构或功能”“规格或适配”等占位式二选一任务凑数。数字权益或服务自动隐藏没有真实复用价值的白底、透明等实体资产。没有明确对象时，用户说“继续”不能被解释为“全部设计”。范围明确后，立即复查商品卡中“待范围判断”的隐藏视图：只把现在确实相关且超过80分的目标组成独立序列号卡，用户选择或回复“无”后才进入多图结构；范围变化时同样只补确认新增相关目标。

### 7. 多图结构与综合方向

商品卡、目标和输出范围明确后，读取 [confirmation-workflow.md](references/confirmation-workflow.md) 的结构选择与自适应方向规则。单张采用单张闭环；多张主图、SKU图、海报或详情页分别采用递进式主次、等量并列、混合结构或自定义。结构和方向始终要有内部采用结论，但只有多个方案会实质改变任务、顺序或画面，或用户明确要求选择时，才展示菜单并增加停顿；用户原话已给出结构/方向或一个方案明显占优时，用一句摘要确认或在直出模式内部采用。综合方向最多比较5个，简单任务只给首推，中等任务比较1–3个，复杂任务才增加独立方向；不为非实体或信息型商品硬凑材质、情绪和场景差异。

### 8. 图组编排与逐图确认

按命中内容渐进读取，不把全行业能力库一次性塞进上下文：先从 [category-adaptation.md](references/category-adaptation.md) 只取八项决策特征、当前类目族和已选输出对象相关行；从 [output-objects.md](references/output-objects.md) 只取通用规则、实际选择的对象小节，多对象时再取跨对象关系；从 [image-set-planning.md](references/image-set-planning.md) 先取买家任务、六维检查、硬淘汰、排序、去重和编排规则，再依据轻量索引与当前买家问题只定位命中的图型类别小节，不通读十三类图型。此时基于已确认商品卡正式区分主图、SKU图、海报和详情页职责，再用用户决策六维检查候选。每张或每个详情页内部模块只保留一个主任务和一个视觉中心；优先用一个主图型组织画面，可按证据、移动端可读性和生产可行性组合多个相容的辅助表现手法，只要它们共同服务同一买家问题，不形成第二中心。已有类型无法覆盖关键问题时建立商品专属候选，但不能绕过证据与生产门槛。连续详情页的每个模块使用`详情页-01`、`详情页-02`等稳定编号，并在`生产与后期`中写明它在同一最终长画布中的顺序、衔接与合成职责；最终成品为1张不等于只写1条含糊提示词。随后把采用方向编排成每张只有一个主任务的图组，并给每张绑定目标SKU/版本或“总览”、参考视觉运用、新增信息和前后承接。推理阶段先分析全部有效参考视觉并区分商品证据、细节证据、文字/权益证据、尺度使用、视觉灵感和反例职责；真正送入单张生成时，只选择当前目标SKU/版本和任务需要的一张、多张或全部同款资料。风格或场景灵感与商品身份分开声明，不能稳定隔离时改为文字化视觉特征；其他SKU默认不作为生成参考输入，只在内部用于发现差异并把明确禁区写进提示词。只有SKU总览/比较图才分别提供各SKU资料，并采用分层生成或后期合成防止融合。冲突必须在商品卡和本张商品锁定中先裁决，正式提示词写出采用的具体特征和舍弃项，不能把“以商品卡为准”留给看不到商品卡的生图模型。再读取 [confirmation-workflow.md](references/confirmation-workflow.md) 的逐图确认小节：交互模式每次只展示当前一张完整确认卡，用户确认或返修后才进入下一张；`0–9`只绑定当前图，`2-1`到`2-10`用于局部返修。用户明确“确认本张，剩余自动完成”或“1-全部”后，剩余图片才切换为内部自动复核。共享商品事实或SKU改变时，只使受影响图重新确认，不静默改写其他图。

### 9. 编排并编译分镜

先确定整组共同视觉语言，再逐张确定唯一任务、参考图使用、商品锁定、允许变化、视角与事实边界、画面、镜头构图、场景人物、光影材质、文案安全区和生产后期。需要场景、人物、镜头或版式时读取 [visual-direction.md](references/visual-direction.md)。

读取 [prompt-writing.md](references/prompt-writing.md)，按以下顺序编译每张提示词：

`图片任务 → 参考图使用 → 商品锁定 → 允许变化 → 事实边界 → 最终画面 → 镜头构图 → 场景人物 → 光影材质 → 文字安全区 → 后期职责 → 动态负面约束`

本阶段不重新运行完整推演循环，直接复用已经确认的商品卡、范围、结构、方向、营销模型编译结论和逐张任务，只执行一次`编译当前字段 → 结构检查 → 反证 → 最小修复 → 定稿`；不重新选择模型或发散卖点。默认使用当前可用的最高推理强度，简单任务只压缩展示而不降低事实、结构和可执行性检查。每个正向提示词必须可脱离隐藏商品卡和上一张分镜独立执行：写明目标对象、实际生成参考输入、已裁决特征和具体禁区，不使用“同上”“按前文”“冲突以已确认商品卡为准”等未解析指针。先修最早错误，不在提示词阶段发明商品事实、隐藏结构或未确认卖点。

### 10. 质检、返修与交付

按 [safety-and-quality.md](references/safety-and-quality.md) 检查，使用 [storyboard-template.md](references/storyboard-template.md) 输出。运行环境能够执行本技能脚本且草稿可作为Markdown验证时，再用`scripts/validate_storyboard.py`检查公开结构和高风险措辞；脚本不可用时按同一清单人工检查，脚本通过也不能替代商品事实、视觉物理和生产可行性的语义质检。只有全部图确认或内部自动复核通过后才聚合正式分镜；仍有待确认图时不得声称整组完成。返修读取 [render-and-repair.md](references/render-and-repair.md)，按稳定分镜编号只重算受影响内容。最终正文不得出现内部评分、角色讨论、循环记录、模型名、测试标签、未采用方案或确认记录。

### 11. 提示词之后可选生图与结果反馈

全部正式提示词交付后，用户可选择暂不生图、生成指定分镜、生成当前图组或生成全部图组，并为每张设置候选数量。生成意向可以在范围阶段预先记录，也可以由用户在提示词交付后另行提出；用户没有表态时只交付正式分镜并停止，不在同一份正式交付中自动附加生图菜单。生图只接收已确认的分镜；未写数量时每个指定分镜默认1张。执行前按 [render-and-repair.md](references/render-and-repair.md) 做能力适配：不支持独立负面提示词时可无损并入同一次生成指令；数量超上限时拆批；多参考图、透明通道、遮罩或目标画幅不能等价实现时，不静默减少证据或改变交付，先说明降级并在需要改变语义时让用户确认。工具不可用或保真条件不成立时保留提示词，不伪造结果。生成后按 [evidence-and-feedback.md](references/evidence-and-feedback.md) 复核商品身份、任务清晰度、证据/文字、物理关系、缩略图可读性和生产后期；只返修最早失败层，并把用户明确的采用、否定和原因交给受控偏好学习。

## 按问题直接处理

| 当前问题 | 处理方式 |
|---|---|
| 只有一张商品图 | 先完成主体识别和预构建；仅对实体商品中真实存在、与当前任务有关且缺少同SKU直接证据的背面、底部、内部或拆解分别评分，超过80分的目标列入写实视图确认清单，用户用序列号确认后才写入写实分镜 |
| 多SKU或多状态 | 只做一个目标款时完整建模目标SKU，其余款汇总为防串款反例；只有总览、比较或分别交付时才展开SKU清单。范围与每张分镜继续绑定目标SKU或“总览”，先消除串款、套装和状态歧义 |
| 数字权益或服务商品 | 真实界面、权益页、流程、授权页或已授权场景作为参考视觉；SKU解释为档位、版本、时长、地区或账号类型；跳过物理隐藏视图，锁定真实证据像素和交付边界 |
| 多对象只写“每个SKU各N张” | 先澄清 N 是每个对象各 N 张还是所有对象合计 N 张，不静默分配分镜数量 |
| 用户没有提供卖点或参数 | AI列出候选和需要补充的字段，让用户编号选择或手动填写；未确认内容不进入提示词 |
| 用户不知道做几张 | 商品卡确认后展示设计需求预判卡，再按买家任务和信息增量推荐最小充分分镜数量 |
| 用户指定很多张 | 为每张分配不同任务；无法成立的张数改为补素材、减少数量或明确标注的视觉变体，不伪造分镜 |
| 商品图不足以实现新角度 | 采用已证实角度、真实商品层合成、补拍、三维资料或概念稿降级 |
| 用户说“直接出” | 仍先生成商品卡（待确认）；单一清晰目标且无关键冲突时可把明确直出授权视为确认，多SKU、相似款或主体/SKU/状态不确定时必须让用户确认卡后，再完成范围、结构、自适应方向和逐图内部复核；外部只交付最终分镜 |
| 用户说“继续” | 商品卡待确认时仍不确认，先回问确认或纠正；已确认商品卡后推进当前预判/范围阶段；在结构或方向阶段采用系统首推；单图确认卡中的裸“继续”或“下一张”不静默确认，只问“确认本张并继续，还是只预览下一张任务摘要”，简化菜单不临时引入未展示编号 |
| 用户说“逐张确认” | 每次只展示一张完整确认卡，确认或返修后再编译下一张 |
| 用户说“剩余自动完成” | 只把当前图之后的图片切换为内部自动复核，仍检查事实、结构、连续性和提示词 |
| 用户只返修一张 | 保留原页码和稳定编号，只修改点名字段及必要下游；商品事实变化时回到商品卡确认 |
| 用户说“暂不生图” | 交付完整提示词后结束，不重复询问 |

## 子智能体与自我学习

复杂、多SKU、高风险或用户明确要求时读取 [enhancements.md](references/enhancements.md)。按需委派商品识别与证据、预构建与需求、范围与结构、图组策略、视觉与提示词、独立事实审查等角色；只有当不确定性、错误代价或候选分歧足以抵消调用成本时才增配角色。每个角色只返回结论、依据摘要、风险和修改建议，由主控按证据合并，不用多数票替代证据，也不向用户分别交付报告。

用户的选择、否定、纠正、有效返修和已评价的生图结果按 [preference-learning.md](references/preference-learning.md) 捕获，只影响后续分镜首推和表达，不覆盖商品事实与本轮明确要求。沉默、候选数量和工具失败不构成偏好。跨任务保存必须获得用户明确授权。

## 最终交付

正式交付不添加参考图索引。每张使用连续页码和稳定分镜编号，例如`## 第1张（主图-01）：首屏商品识别`，并用`参考图使用`说明“已分析全部参考视觉后，本张实际向生成模型提供一张、多张或全部同款资料中的哪类内容、怎样互补，以及冲突已经裁决成什么具体结果”，不出现固定参考图编号，也不把其他SKU当作单SKU画面的生成参考。只有已确认或内部自动复核通过的图才进入聚合；核心交付只有逐张中文图生图分镜提示词，不在正式分镜同一回复中追加菜单、策略报告或内部过程。商品卡、需求预判、结构/方向选择、子智能体意见和学习过程只用于对话确认与内部推演，不另行生成报告。
