# 商品图深度推演与图生图分镜

把商品参考图转化为两项结果：先判断真正应该做哪些图片，再为每张图片写出可执行的中文图生图分镜提示词。

## 核心原则

1. 先看懂商品，再决定做什么图，最后写提示词；不要先套电商模板。
2. 商品身份、SKU、结构、比例、颜色、材质表面、包装、配件、标志和可见原文不得无依据改变。
3. 只画参考图和可靠资料能够证明的内容；未知背面、内部、配件、适配、参数、功效和认证不得补成事实。
4. 每张图只解决一个主要购买问题；多图必须形成互补的信息路径，不能靠换背景或同义文案凑数量。
5. 商业、运营、产品、营销、心理与美学判断必须落到“做什么图、为什么做、怎样画、什么不能画”，不能单独交付。
6. 使用自然中文。商品原文、通用缩写、文件名和工具固定字段可保留原样。
7. 正式提示词永远先完整交付；生图是之后的可选动作，默认不自动执行。

## 工作主线

### 1. 理解任务

识别商品、输出对象、数量、平台位置、用途、画布、必须保持、允许变化、禁止内容、推进要求和是否生图。用户已经说清楚的内容直接采用，不重复提问。

只有下列问题会阻塞：无法识别商品；不同资料在SKU、型号、规格、适配、套装或数量上互相冲突并可能误导购买；多个硬性要求无法同时成立；用户要求无依据高风险主张；现有素材无法维持商用真实性且不接受降级；合法、授权、平台或人身安全不成立。每次只问一个最能解除阻塞的问题。

### 2. 看懂商品与参考图

读取 [product-and-reference.md](references/product-and-reference.md)。按上传顺序建立`参考图1、参考图2……`稳定编号，区分商品身份、SKU或状态、视角、细节、材质、文字、包装、配件和场景职责。新图只追加编号，不复用旧编号。

建立商品保真边界：哪些必须保持，哪些允许生成，哪些必须删除或交给后期。多SKU分别绑定身份参考图，禁止跨款借结构、颜色、包装或配件。

### 3. 判断真正需要哪些图

用户只要一张明确图片时，直接设计该图，不加载完整图组方法。输出对象或图组尚不清楚时，读取 [image-set-planning.md](references/image-set-planning.md)，从买家任务、购买阻力、证据、选型、防退货、平台位置、素材能力和生产成本反推必要图片清单。产品、运营、商业、营销、心理、品牌和美学判断只保留能够改变图片任务、顺序、证据、构图或提示词的部分。

先执行事实、合规和可实现性否决，再用内部定量评分比较候选；分数只帮助排序，不冒充转化预测。正式的唯一任务图每增加一张都必须带来新的决策价值或信息增量；只有用户明确接受时，才可另做清楚标注的视觉变体。

根据具体对象读取 [output-objects.md](references/output-objects.md)，只采用当前对象的小节，不把其他对象规则混入当前分镜。

### 4. 推演方向并收敛

根据真实歧义决定方向数量：

- 方向已经明确：只深审1个方向。
- 人群、场景、证据或视觉路径存在实质歧义：比较3个方向。
- 用户明确要求深度全案、比较或脑暴：搜索5个方向。

方向数量不等于推理强度。一个方向也要使用最高可用推理强度检查事实、反证和生产可行性。不同方向必须改变购买问题、证据路径、使用情境、价值叙事、视觉记忆点或生产方式，不能只换色彩和风格名称。

### 5. 编排每张图

先确定整组共同视觉语言，再逐张确定唯一任务、参考图、商品锁定、允许变化、画布布局、最终画面、镜头构图、场景人物、光影材质、文案安全区和生产方式。

需要人物、空间、视角、版式或美学判断时读取 [visual-direction.md](references/visual-direction.md)。无人无手的画面不要加载人物规则。精确标志、包装原文、长文案和参数表优先保留真实商品层或由后期排版，不要求图像模型重新绘制。

### 6. 写中文图生图提示词

读取 [prompt-writing.md](references/prompt-writing.md)，按以下顺序编译每张提示词：

`图片任务 → 参考图职责 → 商品锁定 → 允许变化 → 事实边界 → 最终画面 → 镜头构图 → 场景人物 → 光影材质 → 文字安全区 → 后期职责 → 动态负面约束`

每张至少执行一轮推演循环（loop）：`观察 → 草拟 → 结构化检查 → 反证 → 最小修复 → 定稿`。发现问题后最多再执行一轮复检；两轮仍不能成立时，停止扩写并说明唯一阻塞。先修最早错误，不在提示词阶段重新发明商品事实、图组任务或卖点。

最后按 [safety-and-quality.md](references/safety-and-quality.md) 检查，并严格使用 [storyboard-template.md](references/storyboard-template.md) 输出。最终正文不得出现内部评分、角色讨论、循环记录、模型名、测试标签、未采用方案或确认记录。

### 7. 返修或选择生图

返修时读取 [render-and-repair.md](references/render-and-repair.md)。根据稳定分镜编号定位问题，明确保留项、修改项和禁止联动项，只重算受影响内容；共享商品事实或组级视觉语言改变时，才检查相邻分镜。

全部提示词交付后，用户尚未决定时提供：暂不生图、生成指定分镜、生成当前图组、生成全部图组，并可分别设置每张生成数量。只有用户明确选择且当前环境具备所需能力时才调用生图工具；用户已要求生图但未写数量时，每个指定分镜默认生成1张。能力不足时保留提示词并说明原因，不伪造结果，不静默改变参考图、尺寸、透明目标或数量。

## 按具体问题直接判断

| 当前问题 | 直接处理 |
|---|---|
| 只有一张商品图 | 只使用该图能证明的角度和结构；不补未知面 |
| 多SKU或多状态 | 分别绑定身份参考图，先消除串款与套装歧义 |
| 用户只要一张明确图片 | 直接建立单张任务，不运行完整图组规划 |
| 用户不知道该做几张 | 用买家任务和信息增量判断真正需要的数量 |
| 用户指定很多张 | 先说明当前能真实制作几张；其余让用户在减少数量、补充素材或明确制作视觉变体之间选择。用户已给出取舍时直接执行，必要时在索引前增加一行`> 数量说明：……`，不把缺素材任务伪装成可生图分镜 |
| 商品图不足以实现新角度 | 改用原角度、真实商品层合成、补拍、三维资料或明确概念稿 |
| 需要人物或手部 | 先检查动作、接触、尺度、遮挡、身份适配和商品可见性 |
| 需要精确文字 | 图像模型保留安全区，真实文字交给商品层或后期 |
| 用户说“直接出” | 内部完成必要检查，外部只给最终中文分镜 |
| 用户只返修一张 | 保留原页码和稳定编号，只修改点名字段及必要下游 |
| 用户已说“暂不生图” | 交付提示词后直接结束，不重复询问 |

## 后台增强能力

复杂、多SKU、高风险或深度任务才读取 [enhancements.md](references/enhancements.md)。按需要选择最小子智能体团队：商品与参考图、图组策略、视觉与提示词、独立审查。子智能体只返回结论、依据摘要、风险和修改建议，不向用户分别交付报告，也不展示隐藏思考链。

当用户对参考图选择、图片任务、顺序、场景、构图、审美、文案、保真或提示词写法出现明确选择、否定、纠正、有效返修，或说“记住这个偏好”时，读取 [preference-learning.md](references/preference-learning.md)。候选数量、工具故障和未评价结果不触发偏好学习。本轮偏好可立即用于后续分镜；跨任务保存必须获得明确授权并使用当前环境已有的私有记忆能力。没有可用记忆能力时只在本轮生效，不自行创建未知位置的文件。偏好不能覆盖商品事实、合规边界和本轮明确要求，也不能自动修改技能文件。

## 协作节奏

直接服从用户的自然语言，不要求记忆模式或数字菜单。未指定时只展示会实质改变结果的选择；用户说“逐张确认”时一张一张推进；说“直接完成”或“只要结果”时内部完成必要检查后一次性交付；说“深度推演”或“脑暴”时扩大搜索与反证，但未采用方向不进入正式分镜。

## 最终交付

每组先列参考图索引。只有用户指定数量无法真实成立时，才可在索引前增加一行`> 数量说明：实际交付数量与原因`。每张标题同时保留阅读页码和稳定编号，例如`## 第1张（主图-01）：首屏商品识别`。页码表示顺序，稳定编号用于确认、返修和选择生图。

核心交付只有逐张中文图生图分镜提示词。商业判断、运营逻辑、营销思维、产品分析、美学选择、定量评分、子智能体意见和自我学习过程都应转化到分镜字段，不另行生成报告。
