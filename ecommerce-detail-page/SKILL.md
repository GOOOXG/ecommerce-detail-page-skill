# 商品图深度推演与图生图分镜

本技能的唯一结果是逐张、可直接执行的中文图生图分镜提示词。商品识别、AI预构建、子智能体、推演循环、定量比较和偏好学习都只为这项结果服务，不另交报告。

## 不可妥协

1. 先实际查看参考图并识别商品主体、SKU和状态，再决定制作什么图片，最后才写提示词。
2. 商品身份、轮廓、结构、比例、颜色、可观察表面、包装、配件、标志和可见原文不得无依据改变。
3. 隐藏视图按目标独立判断。背面、底部、内部和拆解只有在各自还原置信度高于90分（91–100分）时，才可写成“高置信推定/示意”；没有同款直接证据时不得冒充已证实事实。
4. 每张图只解决一个主要购买问题；多图必须有新的事实、证据、选择帮助、场景或顾虑解法，不能靠换背景凑数量。
5. 商业、运营、产品、营销、消费者心理和美学判断必须落到“做什么图、为什么、怎样画、什么不能画”。
6. 分析、确认、说明和提示词使用自然中文；商品原文、品牌、型号、文件名和必要工具字段可保留原样。
7. 正式提示词先完整交付；生图是后续可选动作，默认不自动执行。

## 唯一工作主线

`识别商品主体 → AI预构建 → 编号建议 → 用户数字选择/手动纠正 → 已确认商品卡 → 图片规划 → 逐张分镜提示词 → 可选生图`

这条主线不可倒置。商品卡是图片规划与提示词编写的中间确认依据，不是额外的运营交付。

### 1. 识别商品主体

读取 [product-and-reference.md](references/product-and-reference.md) 和 [prebuild-and-product-card.md](references/prebuild-and-product-card.md)。按上传顺序建立稳定的`参考图1、参考图2……`编号，实际查看每张可访问图片，识别品类、商品主体、品牌、型号、SKU、颜色、容量、状态、可见结构、文字、包装、配件和参考图职责。

把结论分为“用户已确认事实、图片可见事实、策略推断、待验证/禁用”。主体或SKU无法合理区分时只指出一个关键冲突，不提前写分镜。

### 2. AI预构建

在同一轮对话中预构建本商品可能需要的：候选卖点、需要用户提供的事实与内容、可用素材、缺失素材、建议图片、视觉与生产条件，以及背面/底部/内部/拆解的独立还原置信度。建议按买错风险和分镜价值排序，通常展示3–5项，不把AI猜测写成商品事实。

### 3. 编号确认与手动纠正

先展示AI首推和编号选项，再等待用户选择。编号只用于当前建议卡；看到新的建议卡后按新卡重新选择，自然语言纠正始终有效。用户可以回复“1”，也可以使用紧凑格式：

```text
主体：1；卖点：1,3；补充：容量=750ml；图片：1,2,4；背面：采用92分推定；底部：不做
```

用户说“全部采用AI推荐并直接确认”时可压缩交互，但仍须检查SKU、事实和素材冲突。用户指出识别错误时，以纠正为准，重发受影响的建议，不继续沿用旧结论。

### 4. 生成已确认商品卡

读取 [prebuild-and-product-card.md](references/prebuild-and-product-card.md) 的商品卡规则。商品卡至少汇总：主体与识别置信度、SKU/状态、图片和用户确认事实、采用卖点、待补证卖点、已有/缺失素材、输出对象与数量、必须保持/允许变化/禁止内容、隐藏视图独立置信度、用户最终选择和纠正结论。置信度数字只在商品卡确认阶段使用；正式分镜只保留“高置信推定/示意”或“已证实视图”的事实边界。

非关键资料可以由用户选择跳过并在后续删除相关主张；主体、SKU、安全或合法性仍不成立时只问一个最小问题。商品卡确认前不编写正式分镜。

### 5. 规划真正需要的图片

商品卡确认后，若用户只要一张明确图片，直接建立单张任务；否则读取 [image-set-planning.md](references/image-set-planning.md)，从买家识别、理解、选择、证明、使用和防错任务中选择最小充分图组。根据具体对象再读取 [output-objects.md](references/output-objects.md)。定量评分只用于内部排序，不写入最终分镜。

### 6. 编排并编译分镜

先确定整组共同视觉语言，再逐张确定唯一任务、参考图职责、商品锁定、允许变化、视角与事实边界、画面、镜头构图、场景人物、光影材质、文案安全区和生产后期。需要场景、人物、镜头或版式时读取 [visual-direction.md](references/visual-direction.md)。

读取 [prompt-writing.md](references/prompt-writing.md)，按以下顺序编译每张提示词：

`图片任务 → 参考图职责 → 商品锁定 → 允许变化 → 事实边界 → 最终画面 → 镜头构图 → 场景人物 → 光影材质 → 文字安全区 → 后期职责 → 动态负面约束`

每张至少执行一轮推演循环（loop）：`观察 → 草拟 → 结构检查 → 反证 → 最小修复 → 定稿`；复杂或高风险任务使用当前可用的最高推理强度。先修最早错误，不在提示词阶段发明商品事实、隐藏结构或未确认卖点。

### 7. 质检、返修与交付

按 [safety-and-quality.md](references/safety-and-quality.md) 检查，使用 [storyboard-template.md](references/storyboard-template.md) 输出。返修读取 [render-and-repair.md](references/render-and-repair.md)，按稳定分镜编号只重算受影响内容。最终正文不得出现内部评分、角色讨论、循环记录、模型名、测试标签、未采用方案或确认记录。

### 8. 提示词之后可选生图

全部正式提示词交付后，用户可选择暂不生图、生成指定分镜、生成当前图组或生成全部图组，并为每张设置数量。只有用户明确选择且当前环境具备生图能力时才调用；未写数量时每个指定分镜默认1张。工具不可用、参考图不足或透明能力不成立时保留提示词并说明原因，不伪造结果。

## 按问题直接处理

| 当前问题 | 处理方式 |
|---|---|
| 只有一张商品图 | 先完成主体识别和预构建；背面、底部、内部、拆解分别评分，只有91–100分的目标可做高置信推定 |
| 多SKU或多状态 | 分别绑定身份参考图，在商品卡中先消除串款、套装和状态歧义 |
| 用户没有提供卖点或参数 | AI列出候选和需要补充的字段，让用户编号选择或手动填写；未确认内容不进入提示词 |
| 用户不知道做几张 | 商品卡确认后按买家任务和信息增量推荐最小充分数量 |
| 用户指定很多张 | 为每张分配不同任务；无法成立的张数改为补素材、减少数量或明确标注的视觉变体，不伪造分镜 |
| 商品图不足以实现新角度 | 采用已证实角度、真实商品层合成、补拍、三维资料或概念稿降级 |
| 用户说“直接出” | 仍完成识别、预构建和商品卡确认；可把AI推荐作为默认选择，外部只交付最终分镜 |
| 用户只返修一张 | 保留原页码和稳定编号，只修改点名字段及必要下游 |
| 用户说“暂不生图” | 交付完整提示词后结束，不重复询问 |

## 子智能体与自我学习

复杂、多SKU、高风险或用户明确要求时读取 [enhancements.md](references/enhancements.md)。按需委派商品识别与证据、预构建与需求、图组策略、视觉与提示词、独立事实审查等角色；每个角色只返回结论、依据摘要、风险和修改建议，由主控合并，不向用户分别交付报告。

用户的选择、否定、纠正和有效返修按 [preference-learning.md](references/preference-learning.md) 捕获，只影响后续分镜首推和表达，不覆盖商品事实与本轮明确要求。跨任务保存必须获得用户明确授权。

## 最终交付

每组先列实际使用的参考图索引，每张使用连续页码和稳定编号，例如`## 第1张（主图-01）：首屏商品识别`。核心交付只有逐张中文图生图分镜提示词；商品卡、图片建议、子智能体意见和学习过程只用于对话确认与内部推演，不另行生成报告。
