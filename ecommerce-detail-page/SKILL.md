# 商品图深度推演与图生图分镜

本技能的唯一结果是逐张、可直接执行的中文图生图分镜提示词。商品识别、AI预构建、子智能体、推演循环、定量比较和偏好学习都只为这项结果服务，不另交报告。

## 不可妥协

1. 先实际查看参考图并识别商品主体、SKU和状态，再决定制作什么图片，最后才写提示词。
2. 商品身份、轮廓、结构、比例、颜色、可观察表面、包装、配件、标志和可见原文不得无依据改变。
3. 隐藏视图按目标独立判断。背面、底部、内部和拆解只有在各自还原置信度高于90分（91–100分）时，才可写成“高置信推定/示意”；没有同款直接证据时不得冒充已证实事实。
4. 每张图只解决一个主要购买问题；多图必须有新的事实、证据、选择帮助、场景或顾虑解法，不能靠换背景凑数量。
5. 商业、运营、产品、营销、消费者心理和美学判断必须落到“做什么图、为什么、怎样画、什么不能画”。
6. 分析、确认、说明和提示词使用自然中文；商品原文、品牌、型号、文件名和必要工具字段可保留原样。
7. 正式提示词先完整交付；生图是后续可选动作，默认不自动执行。

## 唯一工作主线

`识别商品主体 → AI预构建 → 编号建议/手动纠正 → 商品卡（待确认） → 用户确认 → 已确认商品卡 → 设计需求预判与输出范围 → 多图结构 → 固定5个综合方向 → 图组编排 → 逐图确认/内部自动复核 → 最终分镜 → 可选生图`

这条主线不可倒置。先让用户确认商品卡，再问真正要做什么图；范围、结构和方向确定后才编排第1张；当前图确认或内部自动复核通过后才进入下一张。商品卡、需求卡和确认卡都只是对话中的确认依据，不是额外的运营交付。

### 1. 识别商品主体

读取 [product-and-reference.md](references/product-and-reference.md) 和 [prebuild-and-product-card.md](references/prebuild-and-product-card.md)。按上传顺序建立稳定的`参考图1、参考图2……`编号，实际查看每张可访问图片，识别品类、商品主体、品牌、型号、SKU、颜色、容量、状态、可见结构、文字、包装、配件和参考图职责。

把结论分为“用户已确认事实、图片可见事实、策略推断、待验证/禁用”。主体或SKU无法合理区分时只指出一个关键冲突，不提前写分镜。

### 2. AI预构建

在同一轮对话中预构建本商品可能需要的：候选卖点、需要用户提供的事实与内容、可用素材、缺失素材、建议图片、视觉与生产条件，以及背面/底部/内部/拆解的独立还原置信度。建议按买错风险和分镜价值排序，通常展示3–5项，不把AI猜测写成商品事实。

### 3. 编号确认与手动纠正

先展示AI首推和编号选项，再等待用户选择。用户选择后先生成“商品卡（待确认）”，不能把这一步当成最终确认。编号只用于当前建议卡；看到新的建议卡后按新卡重新选择，自然语言纠正始终有效。用户可以回复“1”，也可以使用紧凑格式：

```text
主体：1；卖点：1,3；补充：容量=750ml；图片：1,2,4；背面：采用92分推定；底部：不做
```

用户说“全部采用AI推荐并直接确认”时可压缩可见交互，但仍先生成并记录商品卡（待确认），检查SKU、事实和素材冲突后把该句话视为明确确认，再标记为已确认。用户指出识别错误时，以纠正为准，重发受影响的建议，不继续沿用旧结论。

### 4. 生成并确认商品卡

读取 [prebuild-and-product-card.md](references/prebuild-and-product-card.md) 的商品卡规则。用户选择或纠正后，先汇总一张标明“待确认”的商品卡：主体与识别置信度、SKU清单与状态、每个SKU的身份参考图、图片和用户确认事实、采用卖点、待补证卖点、已有/缺失素材、用户原始输出意向（仅作待确认线索）、必须保持/允许变化/禁止内容、每个隐藏视图的独立置信度和纠正结论。

向用户明确询问“确认商品卡”或“需要修改什么”。待确认卡阶段不再提供裸数字确认菜单；用户只回复“1”等数字时，不视为确认，应回问确认或字段纠正。只有用户明确确认（或用户明确要求全部采用AI推荐并直接确认，且系统已先生成待确认卡并通过内部冲突检查）后，才把卡标为“已确认商品卡”，并进入需求预判；进入下一张确认卡后，数字才按新卡重新绑定。商品卡阶段可以显示置信度数字；正式分镜只保留“高置信推定/示意”或“已证实视图”的事实边界。

非关键资料可以由用户选择跳过并在后续删除相关主张；主体、SKU、安全或合法性仍不成立时只问一个最小问题。商品卡确认前不编写正式分镜。

### 5. 需求预判与输出范围

读取 [confirmation-workflow.md](references/confirmation-workflow.md)。仅在“已确认商品卡”成立后，先展示覆盖主图、SKU图、详情页、海报、产品素材图、全部设计和自定义组合的“设计需求预判卡”，再确认对象、分镜数量、平台、用途和多SKU映射。用户原话已明确的内容标记为“已捕捉意向”并紧凑确认；没有明确对象时，用户说“继续”不能被解释为“全部设计”。这里记录的是分镜数量，不是提示词完成后的生图候选数量。

### 6. 多图结构与综合方向

商品卡和输出范围明确后，读取 [confirmation-workflow.md](references/confirmation-workflow.md) 的结构选择与五方向规则。单张采用单张闭环，但仍在内部比较5个方向；多张主图、SKU图、海报或详情页分别选择递进式主次、等量并列、混合结构、系统首推或自定义。结构确认后固定推演5个产品专属综合方向：前3个偏转化/平台适配/价值品牌，后2个偏视觉差异/情绪场景。交互模式等待用户选择、组合或自定义；直出/全自动在内部比较后采用首推，但不跳过这些判断。

### 7. 图组编排与逐图确认

读取 [image-set-planning.md](references/image-set-planning.md) 和 [output-objects.md](references/output-objects.md)，将采用方向编排成每张只有一个主任务的图组，并给每张绑定目标SKU或“总览”、参考图职责、新增信息和前后承接。再读取 [confirmation-workflow.md](references/confirmation-workflow.md)：交互模式每次只展示当前一张完整确认卡，用户确认或返修后才进入下一张；`0–9`只绑定当前图，`2-1`到`2-10`用于局部返修。用户明确“确认本张，剩余自动完成”或“1-全部”后，剩余图片才切换为内部自动复核。共享商品事实或SKU改变时，只使受影响图重新确认，不静默改写其他图。

### 8. 编排并编译分镜

先确定整组共同视觉语言，再逐张确定唯一任务、参考图职责、商品锁定、允许变化、视角与事实边界、画面、镜头构图、场景人物、光影材质、文案安全区和生产后期。需要场景、人物、镜头或版式时读取 [visual-direction.md](references/visual-direction.md)。

读取 [prompt-writing.md](references/prompt-writing.md)，按以下顺序编译每张提示词：

`图片任务 → 参考图职责 → 商品锁定 → 允许变化 → 事实边界 → 最终画面 → 镜头构图 → 场景人物 → 光影材质 → 文字安全区 → 后期职责 → 动态负面约束`

每张至少执行一轮推演循环（loop）：`观察 → 草拟 → 结构检查 → 反证 → 最小修复 → 定稿`；默认使用当前可用的最高推理强度，简单任务只压缩展示而不降低事实、结构和可执行性检查。先修最早错误，不在提示词阶段发明商品事实、隐藏结构或未确认卖点。

### 9. 质检、返修与交付

按 [safety-and-quality.md](references/safety-and-quality.md) 检查，使用 [storyboard-template.md](references/storyboard-template.md) 输出。只有全部图确认或内部自动复核通过后才聚合正式分镜；仍有待确认图时不得声称整组完成。返修读取 [render-and-repair.md](references/render-and-repair.md)，按稳定分镜编号只重算受影响内容。最终正文不得出现内部评分、角色讨论、循环记录、模型名、测试标签、未采用方案或确认记录。

### 10. 提示词之后可选生图

全部正式提示词交付后，用户可选择暂不生图、生成指定分镜、生成当前图组或生成全部图组，并为每张设置候选数量。生图只接收已确认的分镜；未写数量时每个指定分镜默认1张。工具不可用、参考图不足或透明能力不成立时保留提示词并说明原因，不伪造结果。

## 按问题直接处理

| 当前问题 | 处理方式 |
|---|---|
| 只有一张商品图 | 先完成主体识别和预构建；背面、底部、内部、拆解分别评分，只有91–100分的目标可做高置信推定 |
| 多SKU或多状态 | 商品卡建立SKU清单、身份参考图、差异和状态；范围与每张分镜继续绑定目标SKU或“总览”，先消除串款、套装和状态歧义 |
| 多对象只写“每个SKU各N张” | 先澄清 N 是每个对象各 N 张还是所有对象合计 N 张，不静默分配分镜数量 |
| 用户没有提供卖点或参数 | AI列出候选和需要补充的字段，让用户编号选择或手动填写；未确认内容不进入提示词 |
| 用户不知道做几张 | 商品卡确认后展示设计需求预判卡，再按买家任务和信息增量推荐最小充分分镜数量 |
| 用户指定很多张 | 为每张分配不同任务；无法成立的张数改为补素材、减少数量或明确标注的视觉变体，不伪造分镜 |
| 商品图不足以实现新角度 | 采用已证实角度、真实商品层合成、补拍、三维资料或概念稿降级 |
| 用户说“直接出” | 仍先生成并记录商品卡（待确认），把用户明示直出视为确认后，再完成范围、结构、五方向和逐图内部复核；外部只交付最终分镜 |
| 用户说“继续” | 商品卡待确认时仍不确认，先回问确认或纠正；已确认商品卡后推进当前预判/范围阶段；在结构或方向阶段采用系统首推；在单图阶段只确认当前图，不跳过后续确认 |
| 用户说“逐张确认” | 每次只展示一张完整确认卡，确认或返修后再编译下一张 |
| 用户说“剩余自动完成” | 只把当前图之后的图片切换为内部自动复核，仍检查事实、结构、连续性和提示词 |
| 用户只返修一张 | 保留原页码和稳定编号，只修改点名字段及必要下游；商品事实变化时回到商品卡确认 |
| 用户说“暂不生图” | 交付完整提示词后结束，不重复询问 |

## 子智能体与自我学习

复杂、多SKU、高风险或用户明确要求时读取 [enhancements.md](references/enhancements.md)。按需委派商品识别与证据、预构建与需求、范围与结构、图组策略、视觉与提示词、独立事实审查等角色；每个角色只返回结论、依据摘要、风险和修改建议，由主控合并，不向用户分别交付报告。

用户的选择、否定、纠正和有效返修按 [preference-learning.md](references/preference-learning.md) 捕获，只影响后续分镜首推和表达，不覆盖商品事实与本轮明确要求。跨任务保存必须获得用户明确授权。

## 最终交付

每组先列实际使用的参考图索引，每张使用连续页码和稳定编号，例如`## 第1张（主图-01）：首屏商品识别`。只有已确认或内部自动复核通过的图才进入聚合；核心交付只有逐张中文图生图分镜提示词。商品卡、需求预判、结构/方向选择、子智能体意见和学习过程只用于对话确认与内部推演，不另行生成报告。
